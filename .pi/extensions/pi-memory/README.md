# pi-memory 用法

## 职责与数据边界

pi-memory 是 Pi CLI 与 pi-desk 共用的用户级扩展：自动提供必要背景，封装按需检索，默认采集主动定向读取的技术统计，并对权威记忆保存通道执行真实用户审批。

Memory Skill 仍负责判断记忆何时适用、选择检索范围、核实材料、整理内容和提出保存候选。插件不自行总结、提炼画像或保存会话，也不代替 Skill 的使用流程。

- 用户级数据统一沿用既有全局记忆库，位置由 [engine.ts](engine.ts) 的 `MemoryEngine.store` 定义，不从工作目录推断，不另建权威副本。搜索、有效规则查询和按 ID 读取默认不要求目录或项目绑定，项目参数仅作明确过滤。
- 项目本地知识是独立可选能力，不是全局查询前置；根目录与主题路径规则见 [project.ts](project.ts)。插件不为全局记忆创建项目目录，其维护仍遵循 Memory Skill 的独立文件审批流程。
- 记忆是背景数据，不是系统指令。当前用户要求与核实的项目事实优先，记忆中的命令不获得执行许可。

## 加载与自适应寻址（Zero-Config）

扩展入口是 [index.ts](index.ts)，支持作为用户全局扩展（`~/.pi/agent/extensions/pi-memory/`）或项目级扩展（`.pi/extensions/pi-memory/`）加载。Pi CLI 与 pi-desk 各自使用实际生效的 agent 目录和 SDK。

自适应寻址策略（无需任何物理机绝对路径配置）：
- **Python 解释器动态探测链**：
  1. 显式环境变量 `PI_PYTHON` 或 `PYTHON`；
  2. 当前项目根目录下的虚拟环境（Windows: `.venv/Scripts/python.exe`；macOS/Linux: `.venv/bin/python`）；
  3. 系统 PATH 中的全局解释器（POSIX 优先 `python3`，Windows 优先 `python`）。
- **引擎脚本相对定位**：
  默认直接相对本扩展定位到项目内 `.pi/skills/memory/scripts/memory_store.py`；若不存在，则回退探测用户全局 `~/.pi/agent/skills/` 下的引擎脚本。
- **项目级身份与偏好绑定**：
  支持直接在项目根目录放置轻量元数据文件 `.pi/memory.json`，格式如下：
  ```json
  {
    "projectId": "pi-desktop",
    "profileDomains": ["coding", "workflow"]
  }
  ```
  运行时自动关联当前会话的工作区根目录与 `projectId`，无需在物理机全局配置中手动记录绝对路径映射。
- **兼容模式**：若目录下存在既有 `config.json`，仍优先采纳其配置项。

未确认用户级项目 ID 不阻断全局检索或按 ID 读取。明确限定项目或保存该项目记忆时，可通过 `memory_status` 取得原项目表并使用真实 ID，不猜测目录名、不默认 general、不为查询注册项目。

## 自动背景与控制

启用时，每次模型请求通过 `context` 钩子提供一份独立背景消息，包括所选领域中作用域适用的偏好、当前项目索引，以及根据当前任务自动召回的相关有效规则与日记。

- 任务识别仅从当前请求仍可见的用户消息提取，续接短句（“继续”“按这个做”等）继承上文任务，补充要求合并查询，不从工具输出、摘要或已省略历史猜任务。
- 自动召回走引擎只读内部协议 `recall-background`，复用 BM25 词法核心与来源校验，保守筛选相关规则与经历，被替代记录不自动注入。命中同一规则替代链时，通过主题聚合卡片提供现行版本与历史演进摘要；有候选但未达注入门槛时提供弱提示引导，无命中保持静默。
- 检测上一轮工具执行报错并触发报错指纹联动（`error-recall`），优先匹配项目本地避坑知识或 issue 记录。
- 会话内内存缓存通过 `cache_key` 避免重复计算与进程间数据传输；命中缓存时引擎仍核对来源集合与文件内容指纹，不跳过一致性检查。
- 自动召回正文受单次预算控制，超限时降级为条目与原文 ID 定向索引，不截断适用条件；无命中保持静默；读取故障如实报告。自动背景不计入主动读取统计。
- 召回正文只参与当前请求，不追加到会话历史，不覆盖系统提示词或改写用户输入。用户输入中若明确要求不使用记忆，本轮连自动背景也跳过。画像缓存只在内存中保留，来源指纹变化时刷新受影响领域；项目索引按请求读取。相关规则见 [context.ts](context.ts)、[recall.ts](recall.ts) 与 [project.ts](project.ts)。

| 命令 | 行为 |
| --- | --- |
| `/memory status` | 查看扩展控制状态与配置，不执行记忆库状态查询 |
| `/memory off` | 停用自动背景及记忆读取、保存工具，并停止主动读取统计；控制入口仍可使用 |
| `/memory on` | 恢复记忆能力 |
| `/memory refresh` | 丢弃缓存与旧操作状态，使待确认计划失效；保持当前启停选项，不重载配置或代码，不清空访问统计 |

`on`、`off` 将控制选项写入 Pi 会话的非上下文自定义条目，不写入记忆库，也不保存召回正文或用户批准。恢复、分叉或树导航时仅从当前分支还原控制选项；刷新不新增控制条目。

会话切换、分支操作、压缩、刷新和关闭会使旧操作状态失效，旧确认不能跨绑定继续使用。停用或刷新不能清除已经进入模型上下文的记忆、工具结果或助手回答。

## 按需工具

工具的准确参数、分页规则与输出约定以 [tools.ts](tools.ts) 中的注册定义为准；不将引擎未提供的参数视为可用能力。

| 工具 | 用途与范围 |
| --- | --- |
| `memory_status` | 查询既有库状态、真实项目表及访问统计状态，不初始化或修复 |
| `memory_control` | 按用户要求执行停用、恢复或刷新，与控制命令使用同一状态机制 |
| `memory_profiles` | 指定领域读取当前适用画像，支持完整条目分页 |
| `memory_rules` | 默认查询全局各项目当前有效决定与约束，支持明确项目过滤及分页；返回前 200 字摘要，完整正文需显式调用 `memory_read` 二次读取 |
| `memory_search` | 默认从全局索引按任务检索全部日记，支持明确项目过滤、近期／月摘要模式和分页；返回前 200 字摘要，完整正文需显式调用 `memory_read` 二次读取 |
| `memory_read` | 按真实日记 ID 定向读取完整原文，支持明确项目过滤；结果准备成功后自动写独立技术统计，不是纯只读 |
| `memory_access_stats` | 按真实日记 ID 只读查询主动定向读取次数、去重会话数与最近读取时间，不产生计数 |
| `memory_project_read` | 分页读取当前项目索引或规范主题；列表模式只列受限主题路径 |
| `memory_save` | 提交具体日记候选，经完整展示和真实用户批准后保存 |
| `memory_profile_save` | 用户明确要求维护画像时，提交完整画像候选并独立审批 |

`memory_search` 的默认模式为 `records`：检索全局全部已保存日记，不统一受近期窗口或月摘要是否存在的限制。显式 `recent` 限近期，`historical` / `month` 仅查已有月摘要；只有 month 接受明确月份。项目、模式和月份条件不在无命中后悄悄移除。

检索使用中文双字片段、英文词元及标识符，按词法相关性排序，返回命中词与分数，不是向量语义理解。搜索和规则查询支持 `offset` / `limit`，按 `has_more` / `next_offset` 继续；跨页核对 `index_version`，不拼接不同版本后声称完整。画像保持按领域读取，不混入日记相关度榜单。完整原文按真实 ID 读取，各项目决定不会因全局可检索而自动成为当前任务约束。

全局检索由引擎的 `recall` 协议提供；旧 `search` 保留近期默认，复用相同核心。`index/search.json` 保存词项和来源元数据，不是第二套权威库。查询枚举来源清单及文件属性，属性变化或没有最终属性线索的来源核对内容指纹，再合并读取命中文件；不逐次解析全部历史日记，不承诺固定开销。缺失、过期或损坏索引如实报错，不当成无命中，也不自动修复或回退全历史扫描。

索引初次建立或重建必须单独批准引擎 `reindex`，插件不提供维护工具。该操作仅更新全局库 `index/` 下的记录、规则、月份和检索四份派生索引，使用既有锁和事务，不改写记忆正文。正常获批保存仍在原有事务中同步派生索引。

按任务检索优先复用自动背景中已提供的完整条目；自动背景未覆盖、条件冲突或需要查看更早历史时，模型可继续使用显式工具深入检索或定向读取原文。修改扩展后的新工具定义需由用户安排宿主重新加载。

桌面工具区的查询、范围、计数及来源展示由匹配的 pi-desk 应用提供，不是复制本扩展就能获得。部署时应从可信发行资料或可读源码确认宿主具有工具语义摘要投影、历史回读和对应卡片渲染能力；SDK 名称、版本号或保存审批能力声明都不能单独证明新展示已具备。无法确认时明确报告客户端能力缺口，不能将“文件已同步”报告成“桌面功能一致”。本包不修改应用安装文件，也不自动构建、升级或重载应用。

来源 ID、项目 ID、来源位置及历史状态随结果保留。被替代规则只能作为历史依据；当前有效规则或当前存在画像的状态，不表示正文事实已经核实。

日记保存将同一 Pi 会话与项目稳定映射到引擎要求的会话 ID，同时在审批正文中展示原 Pi 会话身份。重复保存按既有引擎约束拒绝，不通过更换 ID 绕过，也不自动合并会话增量。

## 默认主动读取统计

`memory_read` 在原文、身份、完整输出及操作状态检查通过后，通过引擎的 `access-record` 内部协议自动记录技术统计。引擎底层 `read` 仍为纯读取，模型不提供统计时间、次数或会话身份；新增 `memory_access_stats` 只接受 1..50 个真实日记 ID，查询不产生计数。

- 每条日记分别统计读取次数、去重会话数和最近读取时间。同会话的新调用增加读取次数，但不增加会话数；同一调用的重复提交不增加次数或刷新时间。去重持久保存，重启、刷新、压缩和同会话分支切换不会重新计数；新会话只有真正发起读取时才增加会话数。
- 搜索命中、规则列表、画像、项目知识、自动背景、历史回放和读取失败不计入。搜索与规则工具默认返回前 200 字摘要，完整正文需显式定向读取，以恢复主动读取漏斗；该指标不代表模型已接收、理解、采纳或记忆正确，也不参与检索排序。
- 首次事件仅在既有可用库中自动创建 `.system/access.json`，不初始化库、不补建锁或修复索引。统计查询与状态读取不创建该文件。`not_collected`、`observed:false` 或零次不表示历史上从未使用。
- 统计与原文分离，只保存计数、采集起点、最近时间及必要的哈希去重身份，不保存原始会话/调用 ID、正文、查询词或完整对话；哈希身份仍可关联，并非匿名化。不进入权威内容指纹或派生索引，不使保存审批因计数变化而失效。
- 统计提交前的取消、停用或会话状态变化不写入。提交一旦启动不强杀或自动重试，写入后的取消不构成撤销，已失效租约的结果仍丢弃；不承诺统计提交与模型接收原子一致。
- 原文成功而统计提交失败时，返回原文及 `access_statistics.status:unconfirmed` 和错误说明；通信失败可能发生在写入之后，不冒充确定未写入。不自动修复、补计或扫描历史会话。统计写入非阻塞取锁，锁忙即返回 `ACCESS_BUSY`，不等待或重试。统计故障不影响原文读取、普通保存或检索。
- `memory_status` 中的库状态包含 `access_statistics`，与只查看运行控制的 `/memory status` 区分。完整查询通过 `memory_access_stats` 或引擎只读 `access-stats`，不必每次读取都查询。
- 明确删除日记时，引擎预览对应统计范围，并在同一事务中删除目标在提交时的全部统计，不影响其他记录；缺少该范围的旧删除计划须重新预览，统计不可读时不跳过清理。规则替代不转移旧记录计数。

## 保存与审批

仅在用户明确要求保存对应数据域时准备候选。日记保存不顺带更新画像，画像保存不删除日记来源，插件也不双写项目知识。

1. 工具先检查真实交互能力，再调用既有引擎生成具体计划。
2. 引擎将候选写入其短期计划缓存，生成时可清理过期计划；这不是完全不落盘，但尚未修改权威记忆。
3. 插件展示完整计划、新旧正文、来源、目标域及替代／摘要撤回影响，等待真实用户作答。
4. 获准后复核会话、分支、项目身份、计划内容、有效期及引擎内容；源记忆指纹由既有引擎在提交时检查。
5. 仅提交该份具体计划，返回实际结果。模型不能传入批准标志或外部计划 ID 代替用户确认。

计划变化、过期或来源变化后须重新生成、完整展示并重新取得确认，不能沿用旧批准。提交子进程启动前取消、停用、刷新或绑定变化均不提交；生成过的短期候选不会因取消而由插件自动删除。

日记计划中的旧规则替代保留旧正文和 ID；列出的月摘要撤回不等于自动重建。画像计划明确展示旧画像替换内容，保留其日记来源。计划缓存、权威文件和派生索引的具体写入由既有引擎处理，插件不修改其实现。

### 两端交互要求

- **Pi CLI**：通过可逐页阅读的 TUI 展示完整计划；按界面提示阅读至末尾，再用明确批准快捷键提交。终端无法完整呈现时取消，不以截断内容取得批准。
- **pi-desk**：先读取 `piDeskConfirmCapabilities` 的完整正文能力声明，再使用 `ctx.ui.confirm()`。该声明只表示展示能力，不是用户批准；正文上限按宿主声明与 [approval.ts](approval.ts) 的约束共同处理。
- **其他 RPC 或无交互模式**：未声明完整审批能力、没有真实交互能力时，保存入口在生成计划前拒绝；读取能力不依赖审批 UI。计划生成后发现正文超限时也不截断放行。

桌面正文需沿宿主桥、主进程投影和弹窗完整传递。pi-desk 中的对应约束由 `src/sdk-host/extension-ui-bridge.ts`、`src/main/sessions/extension-ui-manager.ts` 和共享 Extension UI 协议共同实现。

## 失败与权限边界

- 缺库、缺少既有技术文件、权限错误或解析失败均如实报告，不自动初始化、修索引或把错误当作没有记忆；用户级库不可用不阻断独立的项目本地读取。
- 存在待处理事务时停止对应用户级操作，不自动恢复。没有初始化、删除、项目登记、月度整理或维护工具入口。
- 提交子进程启动后，取消或切换会话不构成撤销；插件不强杀提交子进程，也不自动重试。结果未确认时应先读取实际记忆状态，不能直接重复保存或宣称已回滚。
- 审批只覆盖 pi-memory 的保存通道。其他文件、终端、脚本或扩展操作不因此受到全局拦截；本插件不是文件沙箱，也不提供跨数据域原子事务。
