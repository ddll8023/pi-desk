# 项目知识文件格式

仅在首建、增加主题或调整结构时读取。模板不是项目事实，不原样保存占位符，也不预建空目录；文件创建须在具体草案确认之后。

## 项目索引

位置：`<PROJECT_ROOT>/.agents/memory/INDEX.md`。

```markdown
# 项目记忆

## 项目范围
<简短说明已确认的项目范围；没有可靠内容时省略。>

## 项目通用约束
- <本项目范围内少量跨模块必要约束及其条件。>

## 主题导航
- 约定：`topics/conventions/<topic>.md`——在<环境/配置/选型条件>时读取。
- 坑：`topics/gotchas/<topic>.md`——在排查<关键现象>时读取。
```

“项目通用”仅指本项目跨模块，不是所有项目的全局规范。索引是小入口，不是工作日记或全部历史摘要；模块细节与解释留在主题，不复制两份完整结论。

第一次只保存一条必要通用约束时可以只有索引。用户级偏好、跨项目工作日记不搬进本地；项目特定环境例外可以保留条件和原因，不复制全局偏好全文。

## 主题路径

配置/选型：`<PROJECT_ROOT>/.agents/memory/topics/conventions/<topic>.md`。

棘手问题：`<PROJECT_ROOT>/.agents/memory/topics/gotchas/<topic>.md`。

主题名稳定，使用小写英文、数字和连字符；标题与正文跟随用户语言，默认中文。不按日期/会话命名，不为不同内容形态另建一套数据根。所有索引路径须遵守 `project.md` 的越界及链接检查。

## 配置与选型模板

```markdown
# <主题>

### <一个特殊配置或选型取舍>
适用：<项目环境、依赖组合、模块或阶段。>
约定：<必要设置、采用方案或明确排除的做法。>
原因：<已确认的项目限制，以及默认配置/其他方案不适用的理由。>
重评条件：<什么变化需要重新考虑；没有则省略。>
关联：<已存在的日记 ID 或项目文档指向；有价值时才写。>
```

当前事实已经由代码完整承载时，不抄数值与字段清单；条目只保留难重推的取舍背景和必要指向。不编造理由，不把无背景的配置清单包装为经验。

## 棘手问题与项目经验模板

```markdown
# <主题>

### <一个棘手问题：关键现象>
适用：<复现环境和触发条件。>
现象：<对定位有价值的表现，不贴完整日志。>
根因：<已确认原因；用户要求保留未决问题时才标“待核实”。>
处置：<有效处理与条件；问题已解决时注明解决方式。>
排除：<实际排除过的方向；没有则省略。>
经验：<仍依赖该项目条件的方法；没有则省略。>
关联：<真实日记 ID 或项目文档；有必要才写。>
```

有价值的经历可保留，不因当前实现已有文档就一律删除；但不能把代码能直接推导的普通现状重复写成另一份说明。经验即使较抽象，也不因此自动提升到全局。根因未知时不得用通用方法冒充原因。

## 表达与更新

- 字段有内容才写，不为填模板造依据；日期和来源不强制每条都加。确需时间信息只能使用可确认日期，未知时省略或注明未知，不把整理日期伪装成决定发生日期。
- 一个小节表达一个独立约定或问题，保留结论、条件和关键理由。单主题约三千字符作为维护参考，不能靠删条件压缩；拆分仍须预览确认。
- 现行约定只维护一份，不并存互斥结论。明确改变决定时更新当前条目，失败案例或旧做法只有仍解释现状、具备重踩价值时才单独保留或指向来源，不逐日追加反转补丁。
- 项目文件路径尽量相对项目根，不写死机器目录；关联用户级日记用真实项目/日期/ID，不复制其全文，不伪造提交号、来源或运行结果。

## 原有结构

索引缺失但正文存在时按文件名、标题定向读取，不自动补索引。已有平铺 `topics/*.md` 或“现行结论/必要历史”结构可继续读取，经用户明确维护该主题并确认后才调整，不趁局部改动全量迁移。

索引损坏或链接越界不跟随，报告具体位置并提出唯一明确的修正建议；修正仍须进入文件清单并确认。
