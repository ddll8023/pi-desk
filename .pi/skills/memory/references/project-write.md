# 项目知识维护

仅在用户明确要求保存、提取、整理、更新或删除项目经验时加载；继续遵守 [项目知识](project.md) 的项目定位与路径边界。普通日记保存、技术方案确认或任务完成都不授权本地写入。

## 来源与准入

以用户指定的对话、结论或材料为范围。只读取当前项目、当前会话实际使用的分支，不拼接已放弃分支或扫描其他 Agent 会话。仅有压缩摘要或片段时明确覆盖范围，不补猜缺失结论，也不伪造提交、来源和运行结果。

候选可为棘手问题、特殊配置、选型取舍及仍依赖本项目条件的方法。必须同时满足：

1. **项目条件明确**：结论与本项目环境、目标、依赖或限制有关；即使表达为方法，也不自动升为跨项目规则。
2. **有不能直接重推的信息**：代码能显示“做了什么”不等于能解释“为什么”。只保留难以重推的条件、理由、失败经历或必要来源；若代码/文档已经完整表达结论与理由，不重复维护。
3. **有重踩成本**：不记会重复试错、误用配置、推翻已确认取舍或重新询问；没有这类价值就不新增。

棘手错误写关键现象、条件、已确认根因、有效处置和排除方向；未知根因仅在用户要求保留未决问题时标注未知。配置保留必要设置和默认方案不适用的理由，不抄配置文件。选型保留项目约束、采用/否决理由和重评条件，不写通用规范清单。

不保存普通实现清单、字段/接口枚举、样式数值、整段日志/代码、未采纳建议、库的通用 API 教材或单次工作进度。阶段性配置/选型只有满足准入条件才保存，注明阶段，不借短期状态堆积流水。进度属于日记，但本流程不自动转存日记。

不保存认证材料或无关个人信息。发现旧敏感内容时不复述原值，提出可理解的脱敏删除范围。

## 查重与合并

先读索引，再读相关原条目；必要时定向查目标模块的 README、docs 与代码注释，不做全仓库扫描。实现事实缺文档时，优先建议补正式说明，不把知识库变成另一份实现文档。真正有价值的决策背景不因当前事实已有说明就整体抹去。

对拟修改文件保留可核对的完整原文或唯一匹配片段。整文件重写必须完整读过该文件；不凭摘要、日期或修改时间覆盖原文。

- 相同结论：不新增，也不为更新时间而重写。
- 补充条件或依据：合并原事项，不建同义条目。
- 明确新决定：更新现行约定；旧值不继续当作当前约束。有重踩价值的失败经历或理由可按案例保留，或指向已存在的日记来源，不自动新建日记副本。
- 新旧冲突未决：展示已核实差异，不擅自按日期裁决；只处理已明确的部分。
- 问题已解决：保留有价值的根因与处置，标明已解决，不积累每日状态。
- 用户要求忘记：定位正文、索引和当前记忆目录中已知重复位置，预览删除范围，不自行建立副本。

沿用现有主题，不按日期或会话分文件。索引只做通用约束和导航，不重复正文；局部维护不扩大为全库迁移。通用性提炼另走用户明确指定的流程，不顺带双写。

## 展示具体草案

草案保留在对话，不创建临时文件。必须展示：项目根、材料覆盖范围、每个准确文件路径、操作类型及完整新增/删除内容，修改前后差异、适用条件与理由。新增、移动、拆分和删除文件都要逐项列明，不能只说“整理相关文件”。

如有关联来源，使用真实日记 ID 或项目内文档指向；没有来源不编造。与用户级日记同时维护时，分别列出数据域与目标；未明确展示的另一域不在确认范围内。

没有有效新增时按 NOOP 结束，不建空文件、不变更日期。取消不改变文件。只在用户明确确认当前具体草案后保存；调整草案、项目切换、草案不可见或源文件变化时，重新展示并确认。

## 按批准范围编辑

写入前再次核对项目真实路径及原文基线；准备新建的路径已经存在也算并发变化。发现不一致就停止，以最新内容重新合并，不覆盖其他人的修改；单看修改时间不算足够依据。

优先精确局部编辑，文件用 UTF-8。新增主题先写正文再加索引；删除主题先调整索引再删文件。只操作批准内容，不自动 Git 提交、改忽略规则、备份、迁移或修改目录外文件。

用文件工具的实际结果区分完成、部分完成和失败，不把多文件动作称为原子事务，也不宣称有并发锁。后续修复先核对最新内容，不盲目回滚覆盖外部修改。

普通文件读取与静态分析可服务于编辑；不得自动运行脚本、测试、检查器、构建或重载来确认效果。保存后简短报告实际路径与新增/更新/删除结果，不把未执行操作写成通过。
