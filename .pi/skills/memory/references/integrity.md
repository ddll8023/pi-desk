# 数据一致性与操作边界

## 两个数据域

用户级日记、画像、项目表与月度摘要位于当前用户的 `~/.agents/memory-store/`，这些权威内容的写入必须通过 `scripts/memory_store.py` 的 `plan` / `commit`，不能用文本替换修补权威数据。

项目本地知识是独立可选域，位于 `<PROJECT_ROOT>/.agents/memory/`，按 `project-write.md` 的文件流程维护，不通过全局引擎写入。全局检索不以项目目录或该域存在为前提；两域没有跨文件系统原子事务，不自动迁移、双写或建立第二套权威副本。

## 独立技术统计

`.system/access.json` 不是第三套权威记忆，也不是可从正文重建的检索索引。Pi 扩展的主动定向读取默认自动采集，无需用户配置；首次成功准备结果时可在已有库中创建该文件，不初始化记忆库、不补建锁文件。

统计保存主动定向读取次数、去重会话数、最近读取时间、采集起点及必要的哈希去重身份。不保存正文、查询词、完整对话或原始会话/调用 ID；哈希仍具有可关联性。会话与工具调用身份来自宿主，不由模型填写计数或时间。

统计提交非阻塞取得既有独占锁，锁忙即报告而不拖住已成功的原文读取；取得锁后使用单文件原子替换，同一记录的同一调用不重复计数；统计查询使用共享锁，不创建文件。统计不进入权威内容指纹或检索来源，不使保存计划因计数变化而失效，也不参与排名。被替代记录保留自己的统计，新规则不继承旧记录计数。

未采集不等于从未使用，损坏不当作零次。扩展在统计故障时保留成功原文并报告结果未确认，不自动重试、补计或修复。写入开始后的取消不等于撤销，不承诺统计与模型接收是同一个原子操作。原文读取、普通保存与检索不依赖统计可用性；涉及对应统计清理的明确删除必须完整处理，不能跳过故障后宣称已忘记。

## 历史与有效版本

- 现有日记格式继续可读，未带 `status` 的旧记录按有效处理，不因升级自动重写用户文件。
- 决定/约束可带 `status:active` 或 `status:superseded`；同项目同 `rule_key` 只允许一个有效版本。`supersedes` 与 `superseded_by` 关联同项目规则，不能指向未知记录或形成循环。
- 普通日记可用 `source_record_ids` 关联已有真实来源。状态只表示生命周期，不证明正文事实已核实。
- 新决定替代旧决定只标记有效性，保留旧 ID、日期与正文。当前 `rules` 排除旧版本，历史和月度来源查询包含历史版本。
- 画像替换不删除任何日记依据。后来的新决定不自动撤回旧月份的历史摘要；向已整理月份新增日记需撤回该月摘要，之后由用户另行要求整理。

## 明确删除

只有用户明确要求删除、忘记或纠正指定记录时才拟定 `plan delete`：展示完整目标正文、ID、项目/日期，以及受影响日记关联、画像来源、对应访问统计和月摘要。

提交时在同一事务中物理删除指定日记、移除目标当前的对应访问统计，并清理剩余记录的悬空来源/替代引用；删除后继不会使过时旧决定复活。画像的已确认正文不因来源删除自动消失。相关正式月摘要撤回，不能宣称自动完成语义重建。

删除计划的统计范围绑定目标记录 ID，审批期间新增的目标计数也一并清理，其他记录不受影响。不含完整统计范围的旧删除计划拒绝提交，须重新预览；统计损坏时不跳过清理或自动修复。

删除范围不包括外部 Git 历史、备份、云同步副本或其他机器，不能宣称全设备忘记。项目本地删除按其独立文件预览，不从全局删除计划扩展出去。

## 计划与并发

- `plan` 缓存短期候选；`commit` 才修改权威文件。`--approved` 只是执行参数，不鉴别确认者身份，Agent 必须获得真实确认。
- 当前计划协议版本为2。旧协议可能含物理替换语义，必须拒绝提交并重新预览；不批量修改或自动提交旧缓存。
- 计划24小时失效，提交时核对全局源内容指纹。任何源变更、候选变化或项目切换都不能沿用旧确认。
- 多项目/多用途计划依次处理；前一次提交改变指纹，不能提前生成多份计划后盲目顺序提交。
- 所有协作脚本操作使用锁；事务日志仅位于 `.system/transactions/`，计划仅位于 `.system/plans/`，索引仅位于 `index/`。明确删除可将唯一统计文件 `.system/access.json` 纳入同一事务，不因此开放其他技术文件的事务写入。外部程序绕过约定不受保护。

## 查询与恢复

查询使用既有锁，不自动创建缺失的技术文件，不在启动阶段执行恢复。发现未处理事务返回 `RECOVERY_REQUIRED`，停止相关操作；恢复须单独说明范围与副作用、取得授权后才执行 `recover --approved`。

恢复在独占锁内按事务日志清理已完成事务或回滚未完成提交；若权威文件被外部改写且不能安全判断则报错，不能覆盖用户修改。恢复、初始化、`validate` 和 `reindex` 都不是普通读取或写完后的默认收尾。

`index/search.json` 是日记与月摘要的全局词法派生索引，保存来源元数据和词项，不是权威正文副本。它与记录定位、规则、月份索引一起由既有事务发布；索引算法或结构不适用、来源集合变化、内容指纹不符时，查询停止，不回退全历史扫描。项目参数仅作明确过滤，不把不同项目的有效规则合并为同一通用要求。

来源文件属性仅用作判脏线索；属性变化以及事务写入尚无最终属性的来源须核对内容指纹，命中原文还须核对 SHA-256 与真实 ID、项目和状态。源清单检查需要枚举路径与属性，不宣称常数开销，也不将外部程序绕过协议的修改说成受事务保护。

`validate` 检查记录、有效版本、来源引用和派生索引；检索索引比较来源内容与检索表示，不把属性缓存差异误判为语义错误。`reindex` 重建四份派生索引，不修改记忆正文。两者仅在用户明确要求并允许运行时执行，不因索引陈旧自动修复。

## 当前能力边界

本实现不包含向量语义搜索、后台捕获、自动定时总结、完整会话增量合并或所有画像语义冲突的程序识别。语义判断由 Agent 依据材料提出，脚本只做确定性操作；不把提示词约束或文件锁等同于完整权限隔离。
