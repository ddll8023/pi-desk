# 2026-11-13

## 移除 genui（生成式界面）模块

**范围**：删除 40 个文件（`src/sdk-host/genui/`、`src/shared/genui/`、`src/main/genui/`、`src/renderer/src/genui/`、`src/preload/genui.ts`、`shared/genui-api.ts`、`shared/genui-params-api.ts`、`assets/genui.css`、`docs/modules/genui.md`），并清理 20 余处接入点。

**关键判断**

- 项目内唯一的「生成式」业务是 `genui`「生成式界面」，没有图片／视频等独立生成式能力。用户所说的"生成式 AI 模块"按此理解。
- **`src/preload/genui.ts` 不是纯 genui 文件**：它同时实现 `ExtensionUiApi` 的 `getExtensionUiState`／`respondExtensionDialog`／`onExtensionUiChanged`。整文件删除会让扩展交互全部落到 `BRIDGE_UNAVAILABLE`。处理方式：新增 `src/preload/extension-ui.ts` 承载这三方法，`preload/index.ts` 展开 `extensionUiApi`，交集类型保留 `ExtensionUiApi`、删 `GenuiParamsApi`。
- **`ui` 载荷链比表面更深**：`ToolExecution.ui`／`latestRevision` → renderer 的 `chat-view.ts`（`UiRef`／`supersededBy`／`uiCount` 整套缓存失效机制）→ `runtime-core.ts`／`runtime-history.ts` 的 `uiRevisions` 映射 → `AppTitleBar`／`chat-navigation` 的跳转列表计数。这些不在最初清单里，分两轮补齐后才动手。
- **`activity-projection.ts` 的 `BUILTIN_TOOLS`** 含 4 个 `ui_*` 工具名，需随工具注册移除，否则插件统计口径会留下永不出现的名字。
- 配置解析是逐字段归一，`desktop-config.json` 残留的 `genuiEnabled` 键不会导致解析失败，下次保存自然消失。
- `userData/genui-params.json` 是「可再生产的参数旁路缓存」，唯一消费者是 `GenuiParamStore`；本机检索未发现该文件，无实际删除动作。
- 旧会话 JSONL 中的界面工具结果保留，只从渲染改为普通工具卡片，不删历史记录。

**文档同步**：`项目结构文档.md`、`modules/{genui 删除, shared, sessions-chat, preferences, app-shell, sub-agent, lan-remote}.md`、`project-map.html`（模块条目、3 条关系、`contains`、流程 `genui-deliver`、`constraints`）一并收敛。`docs/开源项目参考/` 下的 genui 提及是外部调研，保留。

**方法教训**：macOS 自带的 BSD grep 不支持 `\|` 交替与 `\b`，带这些的模式会静默返回空结果；本仓检索一律用 `grep -F` 或 `grep -E`，否则会误判「已清理干净」。本次正因此漏掉 `use-app-startup.ts` 的 `onPageHide` 与 `ChatTurnItem.vue` 第三处 `@jump-latest`，另漏 `activityTool()` 里的 `ui: null` 字面量（未在检索模式内）；三处均由子代理审查发现，属工具方法缺陷而非判断错误。

**审查方式**：改动完成后派两个只读子代理（代码面 / 文档面）交叉审查，明确禁止其改文件与跑构建。代码面查出 3 处会阻断编译的漏改，文档面查出总览域清单缺 `agent-home`／`experts` 与 `main/` 目录枚举缺 `agent-home/`。结论：逐步 grep 自查不能替代一次完整的编译级审查。
