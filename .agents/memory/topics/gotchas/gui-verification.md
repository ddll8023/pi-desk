# 真机 GUI 验证

### 驱动窗口被辅助访问间歇拒绝；停 dev 后 Electron 主进程残留

现象：真机验证 Electron 界面时，用宿主系统脚本驱动窗口（点击、读窗口位置）会间歇被辅助访问权限拒绝，同一会话内首次可能成功、之后被拒；全屏截图截到的是前台其他应用窗口；停掉 dev 脚本后 Electron 主进程仍存活，再次 `npm run dev` 会因 5173 被占用而启动失败（应用自身的单实例锁会让第二个应用实例以退出码 0 直接结束，因此不会再出现两个窗口）。

根因：辅助访问授权对系统脚本工具不稳定（待核实）；dev 生命周期脚本退出不级联终止它启动的 Electron 主进程。

处置：窗口驱动与截图统一走 Orca computer-use CLI（`orca computer list-windows/click`，以 pid 定位应用，元素索引易过期、从返回 treeText 现取）；截图按窗口坐标区域取，不截全屏。停 dev 分两步：先停 dev 脚本，再按 Electron 可执行文件的进程路径找出并终止残留主进程，以查不到该进程为确认。驱动流程固定为：先 `get-app-state`（首次常只返回窗口标题的空树，需再调一次或加 `--restore-window`），从返回的 treeText 现取 element-index，每次动作后重新取状态——动作会使索引失效，复用会得到 `element_not_found`。需要在既有 dev server 之外另起一个应用实例（例如双实例验证）时，让 Electron 主进程以指向现有 dev server 的渲染端地址直接启动，不要第二次 `npm run dev`。

排除：依赖宿主系统的窗口自动化工具（授权不稳定）；未安装专用的坐标点击工具时不要假设其存在。

### 目录选择面板的「前往文件夹」

现象：用合成热键 Cmd+Shift+G 打不开 macOS 目录选择面板的「前往文件夹」。

根因：合成键盘事件对该原生面板不生效（待核实）。

处置：按 `/` 打开它，用 `set-value` 写入绝对路径后 Return，再点「选择此目录」。
