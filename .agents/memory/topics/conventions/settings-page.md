# 设置页

### 设置页是独立全屏页，左栏是分节导航

约定：设置页占据整个工作区，打开时不显示项目侧栏、右侧面板与工作区标签组；左栏按分组列出分节，右栏只渲染当前分节的内容，两栏各自滚动，页面本身不滚动。分节与分组的唯一数据源是 `src/renderer/src/settings-navigation.ts`：新增设置项在那里加一条数据，再到 `SettingsView` 补一个内容分支。设置页自身的界面状态（是否打开、当前分节）在 `src/renderer/src/stores/settings.ts`，其他入口跳转设置页时按分节 id 定位；离开设置页的入口固定在顶部栏，设置页内不另设返回按钮。

适用：新增或调整设置页的分节、导航与入口时。

原因：设置项会持续增加，平铺的入口卡片无法承载分组与扩展；左栏导航让分节名始终可见，新增分节也不必改动页面骨架。

### 模型相关能力合并为以供应商为主线的一页

约定：凭据、models.json 自定义条目与对话页模型可见性合并进同一个「模型」页：清单以 Pi 报告的供应商为主干，默认只列已配置凭据、有已知模型或在 models.json 里有条目的供应商，其余内置未配置的靠搜索找到；点清单某一行，凭据、端点摘要与对话页可见性三块就地展开在该行下方，再点一次收起，同一时刻只展开一行；models.json 条目的新建与编辑一律在弹窗（`ProviderEditorDialog`）里进行，清单行只给摘要与入口；弹窗关闭前若表单有未保存改动，在弹窗内切换确认视图，不叠加第二层弹窗；登录流程进行中或刚结束时固定为粘性顶部条，滚动与展开其他行都不会让它消失。

适用：新增任何与供应商、凭据或模型展示有关的界面时。

原因：这三份数据都按 provider id 对齐，合并的是界面组织而不是存储；分节内容区宽度有限（上限见 `.settings-page-content`），在分节内再分栏会让编辑区过窄，而弹窗可以按编辑/新建取更宽的宽度；编辑器（表单 + 请求头 + 模型列表 + 原始 JSON）内联展开会把清单撑长，逐行阅读时难以比对；模态嵌套以两层为上限，确认类交互改成同层切换可以避免第二层焦点陷阱与 Escape 归属问题；详情若放在页面底部，展开内容会落在视口之外，用户会以为点击没生效；登录流程若随选中项卸载或只渲染在页首，用户会卡在一个看不见的流程里。

### 对话页模型可见性开关是乐观更新

约定：可见性开关只走 `runtime` store 的 `setModelsVisibility`/`showAllModels`；界面先按本地选择变化，落盘在后台串行进行，在途期间的新选择合并成一次写入，失败时回滚到最近一次服务端确认值并报错；写入期间不禁用勾选，再点一次即为重试；「隐藏 N 个模型」与「恢复全部显示」用全量偏好计数，不随清单搜索过滤变化。

适用：改动可见性开关、批量显示/隐藏或相关计数时。

原因：一次勾选一次 IPC 往返会让连续操作手感卡顿，而「保存中禁用」会让第二次点击静默丢失；计数若从过滤后的清单求和，输入搜索词就会让数字缩水、按钮误变灰。
