# 设置页

### 设置首页的次级能力统一放同一张卡片的入口列表

约定：设置首页保留「外观」这类直接控件卡片；其余能力（打开一个全宽子页）合并进同一张卡片，按「标题 + 一句说明 + 右侧按钮」排成入口行，按钮文字统一为「管理」并各自带 `aria-label`；按钮列固定对齐，说明再长也不把按钮挤到下一行；共性前提（如「需要重启 Runtime」）只在卡片末尾写一次，不在每个入口重复。

适用：新增或调整设置首页的入口时。

原因：这些入口行为同构，按主题拆成多张卡片只会造成「哪些卡片归哪一类」的随意切分；按钮若随说明换行，多个入口的按钮列会互相错位。

### 模型相关能力合并为以供应商为主线的一页

约定：凭据、models.json 自定义条目与对话页模型可见性合并进同一个「模型」页：清单以 Pi 报告的供应商为主干，默认只列已配置凭据、有已知模型或在 models.json 里有条目的供应商，其余内置未配置的靠搜索找到；点清单某一行，凭据、端点与模型、对话页可见性三块就地展开在该行下方，再点一次收起，同一时刻只展开一行；新建自定义条目用弹窗，不渲染在页面流里；登录流程进行中或刚结束时固定在清单上方，展开另一行不隐藏它。

适用：新增任何与供应商、凭据或模型展示有关的界面时。

原因：这三份数据都按 provider id 对齐，合并的是界面组织而不是存储；设置页内容区上限约 896px，左右分栏会让完整编辑器过窄；详情若放在页面底部，展开内容会落在视口之外，用户会以为点击没生效；登录流程若随选中项卸载，用户会卡在一个看不见的流程里。
