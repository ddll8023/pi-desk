# 投影展示上限与过程块折叠

### 展示上限只收缩 AI 侧，用户输入不丢

约定：消息投影的展示上限（条数与文本总量）只收缩 AI 侧内容——先丢旧 AI 消息的 Thinking 与工具调用参数文本，再把旧 AI 正文压成开头片段，最后才丢整条 AI 消息；用户消息不参与这两项收缩，界面必须始终能看到全部用户输入。上限取值、收缩顺序与截断标记以 `src/sdk-host/projection/message-projection.ts` 的注释为准。任何收缩都要让渲染端整表重同步，并在界面顶部如实说明省略了什么。

适用：调整消息投影的上限、截断与丢弃逻辑，或修改对话区的截断提示文案时。

原因：早期实现按消息条数从最旧整条丢弃，长会话里用户输入会连同 AI 回复一起消失；把收缩对象限定在 AI 侧后，长会话保留的是用户真正写下的内容，代价只是旧轮次的思考与工具细节。

### 响应过程逐项展示，只有相邻工具调用归组

约定：对话区把一条 AI 消息里的 Thinking 与工具调用**逐项展示、各自开合**，回答正文按原位置展示、始终可见；不存在把 Thinking 与工具合并成的「过程」区块。唯一的归组是工具之间：连续出现且都没有生成式界面的工具调用合成一个「执行记录」面板，面板只提供归组与状态统计，组内每条仍是独立折叠的工具卡；单条工具不套面板，Thinking、正文与生成式界面都是分组分界。开合优先级为手动选择 > 生成状态；失败首次出现时自动展开一次，之后不覆盖手动选择。实现与开合细则以 `src/renderer/src/sessions/components/ChatMessageItem.vue`、`ToolCard.vue` 与 `src/renderer/src/sessions/stores/session-view.ts` 的注释为准。

适用：调整对话区消息渲染、工具卡归组或折叠交互时。

原因：过程细节是长会话里最占体积、阅读时最不需要常驻的部分，逐项折叠能只收起用户不想看的那一段；而相邻工具调用通常是同一次任务里的连续动作，归到一个面板里才能在收起状态下看到「几个工具、几个失败」，且不影响任何 Thinking 或正文的可见性。

### 工具卡的改动量可以是推断值，必须标出来

约定：文件类工具（`edit` / `write`）摘要行的 `+n −m` 只在来自工具结果 `details.diff` 时才算真实 Diff 统计；`write` 没有 Diff 时只能按写入内容行数估算新增（拿不到旧文件，删除恒为 0），此时界面必须在**两处**都标出推断口径：摘要行带可见的「推断」标签（不能只靠悬停提示），展开区标题写明「写入内容预览（根据工具参数推断，非实际文件 Diff）」，不得把推断值或写入内容预览当真实 Diff 展示。展开区、摘要改动量与展开区标题从同一个 computed 出口取数（`ToolCard.vue` 的 `fileFacts`），不得用「已展示行数 + 剩余行数」反推总行数。

适用：调整工具卡的文件变更展示、改动量统计、展开区标题或写入预览行数上限时。

原因：推断值在覆盖写、追加写、含末尾空行等情况下会与文件的实际变化不一致，而写入内容预览只说明文件将被写成什么、不含旧内容，两者都不能叫「变更」；把口径写死在单一出口上，调预览上限时改动量数字和标题才不会跟着错。

### 工具卡折叠态不承担全文级计算

约定：`ToolCard.vue` 里凡需要遍历完整结果文本的计算（行数与字节数统计、预览裁剪、JSON 结构摘要）都必须受 `expanded` 门控，折叠时返回 null 或空占位；模板读到的值不能是 `null`，用 `EMPTY_RESULT_PREVIEW` 这类固定空对象顶替。JSON 分支只有一个判据：`expanded && resultJsonLabel !== null`——形状检查、长度区间、解析都在 `summarizeResultText` 内部完成，界面不得自己再拿 `looksLikeJsonText` 之类的廉价判定去分支，否则会出现「摘要分支」与「纯文本分支」两套提示互相竞争。纯文本分支的所有说明（结果过大、按行裁、按字符裁）合并到同一个 computed（`resultPlainNote`）里按分号拼成一句，同一屏不并列两条口径。

适用：给工具卡增加展示字段、调整结果规模统计与预览、或修改 JSON 摘要展示时。

原因：长会话里绝大多数工具卡是折叠的，折叠态仍对每条大输出做全文扫描会把“收起省成本”这件事变成空话；而界面一旦自己判定 JSON 形状，就会出现“判定说像 JSON、解析却失败”的分叉，用户会在同一屏看到两条互相矛盾的说明。
