# 门禁与记忆系统项目级绑定与去宿主耦合开发设计文档

## 1. 文档定位与背景

本设计面向 Pi Agent 及桌面端（pi-desk）中的两大核心基础设施——**Skill 门禁系统（skill-guard）**与**记忆系统（pi-memory / Memory Skill）**。

当前体系强依赖宿主全局目录（`~/.pi/agent`）下的扩展代码部署，且底层配置（`config.json`）硬编码了具体物理机的绝对路径（包括 Python 解释器绝对路径、`memory_store.py` 脚本位置以及特定盘符的项目路径映射）。在多电脑漫游开发场景下，用户更换电脑或克隆仓库后，系统无法直接生效，必须通过专门的 `pi-skill-setup` 技能进行人工干预与成套部署，运维负担沉重且存在设计与数据一致性隐患。

本设计旨在重构两者的加载、绑定与寻址机制，将项目治理规则及执行扩展同项目本身绑定，记忆底层转为动态自适应探测，实现**跨机克隆即用、用户零额外配置**。

---

## 2. 核心痛点与问题陈述

1. **环境与机器强耦合**：
   - 记忆扩展配置文件直接记录物理磁盘路径（如 `C:\Users\...\python.exe` 与 `H:\code\...`），一旦更换运行环境或不同操作系统，配置全部失效。
   - `pi-memory` 对项目 `projectId` 的识别依赖全局静态注册表中的固定映射，无法自动关联当前已打开的工作区目录。
2. **规则漂移与维护分裂**：
   - 全局 `AGENTS.md` 独立于仓库代码之外，导致多端开发时项目规则无法跟随 Git 版本化流转。
3. **运维工具越位（技能代偿架构缺陷）**：
   - `pi-skill-setup` 作为辅助技能，实质承担了环境初始化、跨机文件复制与配置模板渲染的运维工作。应通过系统自包含与自适应架构消除此类冗余技能。

---

## 3. 目标、范围与明确不做项

### 3.1 目标
- **克隆即用（Zero-Config）**：新电脑直接 `git clone` 代码仓库即可自动拥有项目级门禁约束与记忆能力，无需在全局环境做任何代码或扩展部署。
- **项目级规则自包含**：项目专属的 Agent 规范与执行门禁收敛于项目根及 `.pi/` 目录中，随版本控制自然流动。
- **记忆引擎自适应寻址**：解除对特定解释器和脚本绝对路径的依赖，通过动态探测策略与当前工作区自动对齐。
- **废弃跨机部署技能**：彻底淘汰 `pi-skill-setup` 的依赖，消除人工迁移配置环节。

### 3.2 明确不做项
- **不做跨机记忆正文远程同步**：用户本地日记与画像仍然保存在当前电脑的用户目录，不通过 Git 上传到公开或团队代码库，避免隐私泄漏与多人数据冲突。
- **不做中心化配置服务**：不引入远程配置中心或第三方云端依赖，保持轻量级单机文件与项目级无状态架构。
- **不改动官方 SDK 核心契约**：仅利用 Pi 既有的 Project-local 扩展（`.pi/extensions/`）与 Project Skills（`.pi/skills/`）机制，不魔改不可升级的 SDK 内核。

---

## 4. 总体架构与职责划分

系统分为三层协同架构：**项目规则与门禁层**、**自适应记忆扩展层**、**分层存储层**。

```text
+-------------------------------------------------------------------------+
|                              项目仓库目录                                |
|                                                                         |
|  AGENTS.md  <-------------------+ (项目级规则，随 Git 跟踪)             |
|                                 |                                       |
|  .pi/                           |                                       |
|   ├── memory.json               | (纯业务元数据：projectId、领域列表)   |
|   ├── extensions/               |                                       |
|   │    ├── skill-guard/ --------+ (项目级门禁扩展，校验本仓库规范执行)  |
|   │    └── pi-memory/ --------+                                         |
|   │                           |                                         |
|   └── skills/                 |                                         |
|        └── memory/ <----------+ (自包含 Python 引擎与引用文档)           |
+-------------------------------------------------------------------------+
                                |
                                v
               [ 动态环境自适应探测 (Zero-Config) ]
          1. Python: PYTHON 环境变量 -> .venv/ -> 系统 PATH
          2. Engine: 相对寻址 .pi/skills/memory/scripts/memory_store.py
          3. ProjectId: 当前 cwd 与 .pi/memory.json 自动匹配
                                |
                                v
+-------------------------------------------------------------------------+
|                        用户级存储 (本地无感持久化)                       |
|                                                                         |
|  ~/.agents/memory-store/                                                |
|   ├── profile/      (个人画像：跨项目复用)                              |
|   ├── daily/        (工作日记：按日积累)                                |
|   └── .system/      (派生 BM25 索引与事务锁)                            |
+-------------------------------------------------------------------------+
```

### 4.1 项目级规则与门禁系统
- **规则下沉**：原先位于全局 `~/.pi/agent/AGENTS.md` 的研发规范下沉至当前项目根目录 `AGENTS.md`，由项目 Git 直接维护。
- **门禁本地化**：`skill-guard` 扩展放置于 `.pi/extensions/skill-guard/`。当项目被信任并打开时，Pi 会自动加载该项目级扩展，针对本项目的工具调用拦截并强制核对上下文证据。

### 4.2 自适应记忆扩展（pi-memory 零配置改造）
- **废弃 config.json 绝对路径**：
  扩展启动时不再强制要求同目录存在写死路径的 `config.json`。
- **Python 解释器动态探测链**：
  引擎通过以下顺序自动发现可用解释器：
  1. 显式环境变量 `PYTHON` 或 `PI_PYTHON`；
  2. 当前项目根目录下的虚拟环境（Windows: `.venv/Scripts/python.exe`；macOS/Linux: `.venv/bin/python`）；
  3. 系统 PATH 中的全局解释器（`python` / `python3`）。
- **引擎脚本相对定位**：
  默认直接相对本扩展定位到项目内的 `.pi/skills/memory/scripts/memory_store.py`，无需绝对路径声明。
- **项目身份自动绑定**：
  项目根目录放置轻量元数据文件 `.pi/memory.json`，格式如下：
  ```json
  {
    "projectId": "pi-desktop",
    "profileDomains": ["coding", "workflow"]
  }
  ```
  扩展运行时读取当前会话 `cwd` 所在的项目元数据，自动绑定 `projectId`，无需预先向全局列表手动登记根路径。

### 4.3 数据分层存储策略
- **项目级知识与规则**：保存在当前项目代码库中（如 `docs/`、`AGENTS.md` 及 `.pi/skills/`），多人共享，克隆即得。
- **用户级记忆（画像、日记、检索索引）**：统一存放在标准用户存储路径 `~/.agents/memory-store/`。
  - 冷启动策略：若本地尚无记忆数据，系统静默保持空状态运行，不产生报错阻断；
  - 存在即可用：若本地已存在画像与日记，扩展自动激活全局画像注入与检索能力。

## 5. 关键取舍与架构约束

| 方案分支 | 核心做法 | 优势 | 代价 / 风险 | 结论 |
|---|---|---|---|---|
| **方案 A：自适应零配置（推荐）** | 规则/门禁进项目，记忆扩展自适应寻址，数据合理分层 | 换机 0 操作，克隆即跑，不污染团队仓库 | 需重构扩展寻址模块以支持回退探测 | **采纳** |
| **方案 B：纯项目全包** | 门禁、扩展、Python 引擎及个人数据全塞入项目 | 极致自包含 | 个人日记与画像无法跨项目共享；协作时隐私外泄 | 否决 |
| **方案 C：便携包同步** | 维持全局架构，通过脚本一键把 `~/.pi/agent` 打包同步 | 无需改动代码 | 换机仍需运行外部安装脚本；依然依赖机器绝对路径 | 否决 |

### 架构约束
1. **跨平台路径归一**：解释器探测逻辑与路径解析必须自动兼容 Windows（反斜杠、`.exe`）与 POSIX 环境，不假定特定 OS。
2. **信任机制约束**：Pi 对 `.pi/extensions/` 的加载依赖项目信任（`projectTrusted: true`）。系统应保证首次打开项目时触发标准信任确认，随后无缝加载。
3. **版本控制忽略**：用户运行产生的临时缓存与本地虚拟环境（`.venv/`、`__pycache__/` 等）严格通过 `.gitignore` 排除，不提交到代码库。

## 6. 开发阶段规划与依赖关系

任务按依赖关系拆分为三个独立阶段，后续在独立对话中推进具体实施：

```text
[阶段 1: 规则与门禁项目化] 
            │
            ▼
[阶段 2: 记忆扩展自适应改造] 
            │
            ▼
[阶段 3: 项目记忆元数据与封装]
```

### 阶段 1：规则与门禁项目化
- **目标**：实现规则与门禁在项目内的自包含。
- **职责范围**：
  - 在当前项目根创建 `AGENTS.md`，固化通用规范与工作规则；
  - 将 `skill-guard` 门禁扩展（入口、路由、上下文指纹、引用校验）迁入 `.pi/extensions/skill-guard/`。
- **关注点**：确保项目信任后扩展能够被正确加载，门禁拦截与审计事件正常生效。

### 阶段 2：记忆扩展自适应改造（Zero-Config）
- **目标**：彻底消除记忆扩展对绝对路径的依赖。
- **职责范围**：
  - 改造 `engine.ts` 中的配置加载模块，移除强校验绝对路径的限制；
  - 实现 Python 解释器三级自适应探测（环境变量 -> `.venv` -> PATH）；
  - 将 `pi-memory` 部署至 `.pi/extensions/pi-memory/`。
- **关注点**：多平台路径兼容性、找不到 Python 时的优雅降级提示。

### 阶段 3：项目记忆元数据与规范封装
- **目标**：完成项目级身份对齐与能力闭环。
- **职责范围**：
  - 建立项目元数据 `.pi/memory.json` 并接入 `context.ts` 动态识别；
  - 在 `.pi/skills/memory/` 放置自包含引擎脚本 `memory_store.py` 及相关引用文档；
  - 整理与归档废弃的全局部署工具（如声明 `pi-skill-setup` 过期）。
- **关注点**：工作区根目录与 `projectId` 的精准匹配。

---

## 7. 待定问题与非阻塞假设

1. **非阻塞假设：Python 运行环境**：
   假设目标机器上至少已存在标准 Python 3.10+ 环境（无论在全局 PATH 还是项目 `.venv`）。若目标机完全未安装 Python，记忆功能将降级为只读或静默跳过，但不阻断 Agent 正常会话。
2. **开发待定项：桌面应用内置集成时机**：
   未来可考虑将通用扩展（如 `skill-guard`）直接编译内置进 `src/sdk-host/session-runtime.ts` 的 `builtinExtensions` 中，作为全局默认开箱能力；但当前阶段优先采用项目级 `.pi/extensions/`，以保证最大灵活性和跨客户端通用性。
