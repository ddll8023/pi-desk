# 语气风格库开发设计

状态：已实施（2026-11-16）。方案与范围由产品负责人确认，代码与随包文档已按本文档落地，并以仓库代码为准；§5 的同名合并与 §3.2 的背景注入口径已按实施阶段的要求修订。

## 1. 问题与目标

用户希望「让产出像自己说话」。现有记忆系统能记住结论与偏好，但存不下「我通常怎么表达」：`records` 保存的是模型重写后的结论，`profiles` 每域只保留一份现行画像，两者都留不住原句。

本功能要做的是：从本产品会话记录里取出**用户本人发的消息**，蒸馏成可复用、可浏览、可覆盖的风格资产，写作或表达类任务按需取用。

## 2. 已确认范围

- 语料来源单一：本产品会话 JSONL 中 `role=user` 的文本，不支持导入外部写作样本
- 触发方式：用户显式触发、一次性、可重跑；不做后台周期蒸馏
- 产出形态：每条风格 = 名称 + 适用场景 + 要点 + 1..12 条原句样本 + 来源会话与日期
- 存放位置：记忆库 `memory.db`，与记录、画像并列但独立成表
- 使用方式：不常驻背景，按需读取；原句样本用于 few-shot 模仿

### 能力定位（必须写进规范，避免实现时扩大承诺）

| 能可靠支持 | 不能可靠支持 |
| --- | --- |
| 像用户一样提要求、写需求说明 | 像用户一样写对外邮件、营销文案 |
| 像用户一样写评审意见、表达取舍与理由 | 像用户一样写私人消息、社交内容 |
| 像用户一样写决策记录、收尾与确认 | 需要特定体裁模板的成文材料 |

原因：本产品会话是「人指挥 AI」的语料，短句、祈使、夹杂代码与日志；其中没有对外文案体裁。实现时不得把功能描述成「代写邮件」这类语料不支持的用途。

## 3. 方案依据

### 3.1 外部对照（核实于 2026-11-16）

| 参考 | 与本决策相关的做法 |
| --- | --- |
| WeClone Speaking Style（`docs.weclone.love/docs/profile/style`，AGPL-3.0，只借设计不借代码） | 只读本人发出的消息；179 项特征分十类；**本地统计 + 模型抽样判断**分离，页面标明哪些是本地算、哪些是模型判；显式 CLI 触发（`build-profile --purpose clone`、单跑 `distill-style`），带时间窗、模型样本上限、`--no-llm`、`--limit` 试跑 |
| Claude Styles（`support.claude.com`） | 风格是用户显式创建的独立资产，与 instructions／skills 分属不同能力，可多份并存在会话内切换 |
| ChatGPT 个性化（`learn.chatgpt.com/docs/personalize`） | 自定义指令为静态文本；风格主要靠预设 personality，不从历史对话蒸馏风格画像 |
| Catch Me If You Can?（Findings EMNLP 2025，`aclanthology.org/2025.findings-emnlp.532/`） | 少样本模仿：结构化体裁（新闻、邮件）可接近，口语化体裁（博客、论坛）明显失败 |
| RAGs to Style（PERSONALIZE 2024，`aclanthology.org/2024.personalize-1.11.pdf`） | 生成时检索风格样例优于仅注入描述 |

由此确定的三个取舍：显式可重跑而非后台；本地统计与模型判断分离且模型侧有上限；描述用于理解、原句用于生成。

### 3.2 为什么放在记忆库内

复用既有的受管运行环境、`plan→commit` 写入闸门、并发互斥与库完整性校验，避免为风格另建一套引擎、备份与状态展示。但必须保持四条独立边界：

1. 不复用 `records`／`profiles` 表：字段语义（`rule_key`、生命周期、预算）与风格资产不符
2. 进常驻背景但独立预算（2026-11-16 变更）：全量注入要点与全部原句，独立 20,000 字符预算，超出整条跳过；不进词法检索与月摘要
3. 不复用 `memory_*` 工具名：风格读取与蒸馏是另一套时机
4. 规范单独成段：记忆 Skill 管结论保存，风格库需要自己的引用文档

## 5. 数据模型

新增两张表，`STORE_VERSION` 升到 3：

- `styles`：`id`（`t_` + ULID）、`date`、`session_id`、`agent`、`saved_at`、`name`、`scene`、`points`
- `style_samples`：`style_id`（外键，级联删除）、`position`、`quote`、`source_session`、`source_date`
- 索引：`styles.date`

约束口径：

- 风格 ID 用独立前缀 `t_`，不并入既有 `ID_RE`（该正则同时校验记录、画像与计划，扩展会放宽它们的校验）
- 名称是用户视角的稳定标识：同名保存自动合并（保留 ID 与首次创建日期，场景与要点覆盖，样本按「来源会话 + 原句」去重追加，合计不超 12 条）；改名换条目才用 `replace_style_ids`（删除重建）
- 单次提交 1..10 条风格；每条 1..12 条样本；单条原句不超过 1000 字符
- 升级路径：v1→v2 保持现状（删访问统计、建标注事件表），v2→v3 只建这两张表，不改写既有记录、画像与摘要；事务内完成，失败回滚保持原版本

风格资产不参与词项检索、不进月度摘要、不进 `export` 快照。`status` 视图增加风格计数。

## 6. 引擎契约

新增子命令与计划操作：

- `styles`：列出全部风格（名称、场景、要点、样本），返回 `memory_scope: "global"` 与总数
- `style-read <id>...`：按 1..10 个真实风格 ID 读取
- `plan style`：输入 `{agent, session_id, styles: [{name, scene, points, samples: [{quote, source_session, source_date}], replace_style_ids?}]}`
- 预览键：`date`、`styles`、`replaced_styles`；`commit` 返回 `new_style_ids`、`replaced_style_ids`

校验与既有操作同风格：字段白名单、文本非空、保留标记拒绝、替换目标必须存在且不能在本次计划中重复替换、来源日期必须是合法日期。

## 7. 扩展契约

### 7.1 取样模块（新增，只读）

输入只有宿主注入的会话根，模型不能指定路径；逐行解析会话 JSONL，只取 `type:"message"` 且 `role:"user"` 的文本块；按会话头 `cwd` 判定项目归属，不按目录名猜。

硬过滤（先于统计，覆盖可判定形态）：

- 整条只是应答的确认句（继续／好的／嗯／可以／确认／收到等）
- 含代码围栏、diff 标记、技能触发块
- 以图片标记为主
- 多行且 60% 以上是路径、或 40% 以上是日志／栈行
- 符号密度过高（代码或表达式为主）
- 长度低于下限

输出每条样本带 `session_id`、`date`、`kind`（长／短，阈值取 200 字符）；超出会话数、字符预算或收集上限时返回 `has_more` 与 `next_offset`；单条超过整份预算时跳过而不是截断。

### 7.2 工具

| 工具 | 性质 | 参数要点 |
| --- | --- | --- |
| `style_sample` | 只读 | `scope`（current-project／all，默认当前项目）、`days`、`session_limit`、`max_chars`、`min_chars`、`offset` |
| `style_list` | 只读 | 无参数 |
| `style_read` | 只读 | `ids`：1..10 个 `t_` ID，返回顺序与请求一致，身份不一致即拒 |
| `style_save` | 写入 | `styles`：1..10 条，字段同上；走 `assertWritableHost` + `plan→commit`，回执含风格 ID、名称、场景与样本数 |

三个只读工具经 `runtime.lease` 沿用停用与换代边界；`style_sample` 在宿主未提供会话目录时明确报错，不回退其他路径。

## 8. 宿主装配

- 记忆配置契约升 `version: 2`，新增必填 `sessions`（绝对路径）；主进程 `isMemoryHostConfiguration` 与扩展 `parseHostConfiguration` 两处校验同时改
- `managedMemoryConfiguration` 增加 `sessions` 参数；`MemoryManager` 的两处调用传入会话根
- 会话根必须复用 `session-store.ts` 的既有推导：把 `getSessionRoot` 导出，不在记忆模块再写一份 `join(agentDir, 'sessions')`

## 9. 提示与门禁

- `src/sdk-host/product-tools-hint.ts`：在记忆段内补风格库时机——写作或表达类任务需要模仿用户表达时先 `style_list`／`style_read`；用户要求提炼风格时 `style_sample` → 蒸馏 → `style_save`。快速模式随记忆组一并下线
- `resources/agent/extensions/skill-guard/index.ts`：`RECOVERY_TOOLS` 增 `style_sample`、`style_list`、`style_read`；`style_save` 不放行

## 12. 待定与风险

待定（实现阶段按当次事实确定）：取样的默认时间窗、会话数上限、字符预算与最小长度；编辑口径与分页粒度。这组默认值由实现专家在实施阶段按当次事实取定，产品侧不再前置拍板。

风险：

| 项 | 说明 |
| --- | --- |
| 语料偏薄 | 用户多数消息是短指令，长消息属长尾；有效样本不足时风格条目会退化为几条口头禅。实现需保留样本数与过滤计数，让蒸馏阶段能看到语料规模 |
| 语料污染 | 不做硬过滤时，代码与日志会被当作表达样本，特征直接失真；过滤口径只覆盖可判定形态，不做主观筛选 |
| 规范冲突 | `resources/agent/skills/memory/SKILL.md` 第 6 条禁止扫描其他 Agent 会话补造工作史；风格取样读的是用户本人发言，必须在 `references/style.md` 写明这一例外，否则模型会自我阻断 |
| 隐私面 | 首次出现批量读取会话正文的通路：只读、按范围、不留副本、目录由宿主注入，模型不可指定路径 |
| 定位误用 | 若实现把功能描述为「代写邮件」，用户会得到语料不支持的结果；第 2 节的能力表是硬约束 |

## 13. 交接说明

实现方在开列执行清单前需自行复核：`STORE_VERSION` 升级路径对**已存在 v2 库**的实际影响、`PLAN_VERSION` 是否需要同步、会话 JSONL 用户消息的实际形态（以本机会话文件为准）、`bundle.json` 构建期核对的覆盖范围。本文档给出的是方案与改动需求，不是逐行代码；各文件的实现细节由实施阶段按当次事实确定。
