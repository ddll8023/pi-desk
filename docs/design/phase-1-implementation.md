# 阶段 1：SDK 宿主与完整会话主链

## 1. 定位

本阶段优先替换会话执行主链，不以完整设置页、资源页或认证执行迁移为前提。架构选择见[设计基线](./runtime-sdk-migration.md)，阶段关系见[开发总览](./runtime-development.md)，事实依据见[架构调研](./runtime-architecture-analysis.md)。

本文规划开发责任、数据流和失败边界，不是已实现状态，也不是可直接复制的 SDK 代码。实际接口、文件拆分及构建参数在本阶段详细讨论后确定，不沿用未经核实的示例。

## 2. 目标与范围

- 常驻独立 SDK 宿主，正常新建、打开和切换不以进程重启实现。
- 完整接入提交文本及图片、中止、模型选择、消息与工具展示、既有回退语义和必要资源重载入口。
- 使用官方会话生命周期，独立管理宿主与活动会话代际；不自行重写会话树、压缩、模型行为或 Agent 队列。
- 保持信任前置、渲染隔离、凭据保护、主进程校验、工具审批和扩展交互。
- 全局展示不随切换清空；基础认证同步、宿主退出、会话替换失败和结果未知在本阶段收敛。
- 宿主入口、构建产物与应用启动路径随主链接入，而不是留到最终清理阶段。

不建设多活动会话、并发宿主池或后台会话缓存；完整查询体系在阶段 2 完善，旧发行资源在阶段 3 退役。过渡期可保留职责明确的旧查询，但活动会话只由 SDK 后端负责。

## 3. 模块责任

### 桌面主进程

管理窗口、preload IPC、项目与信任；将渲染端意图转换为范围明确的业务请求。会话文件、项目归属和信任决定由主进程确认，不允许页面提交任意可执行路径、宿主参数或未校验的 SDK 对象。

监督宿主启停、就绪与退出，收敛未完成请求，保留安全的展示副本。Agent 和扩展执行不放入主进程。

### 会话操作所有者

一个所有者集中编排新建、打开、切换、回退、重载与关闭，统一用户确认、互斥、失效和结果表达。主进程的用户意图编排与宿主的 SDK 执行需明确分工，不建立两套竞争的会话状态机。

展示目标与实际活动会话分开：用户选中了目标不等于目标已经接管。旧会话可以作为只读视图保留，但失效后不得继续接收写操作。

### SDK 宿主

持有官方 SDK 和一个活动会话，执行官方生命周期、绑定必要内建扩展及桌面 UI，提供可序列化的结果与权威状态。SDK 内部对象不直接暴露给页面。

复用宿主不强制复用会话对象或 services。项目模型注册、扩展上下文与 MCP 属于有范围的会话责任，不能为了速度继承旧项目的可变状态。

### 投影与交互桥

投影负责消息、工具和统计的展示，不持久化第二套消息真相。交互桥负责审批、弹窗和登录请求的归属、取消及响应；会话失效后旧交互不可作用于新会话。

## 4. 生命周期与状态方向

分别表达：

- **宿主**：未建立、建立中、可通信、退出或故障恢复、不可用。
- **会话**：无活动会话、目标准备中、活动会话可用、已失效或恢复失败。
- **执行**：空闲、预提交、运行、压缩、排队、等待用户、中止收敛或结果未知。
- **展示**：有效基准、读取中、增量同步、范围失效或读取失败。

这些是责任方向，不是提前固定的枚举定义。不能让宿主 ready 自动代表会话可提交，不能让页面未 streaming 自动代表 SDK 已空闲，也不能让快照刷新代表宿主重启。

宿主按需建立，正常会话切换复用。跨项目变化重新判定信任与资源范围，优先替换会话服务；无法收敛的进程级副作用另行表达为宿主重建原因。

## 5. 会话主链数据流

### 新建、打开与切换

1. 主进程确认目标项目、会话归属和信任决定，解析真实 Pi 会话文件。不能根据会话 ID 拼造文件名或项目内路径。
2. 确认宿主可通信，确认当前官方执行状态。存在需中止的操作时先取得用户确认，再让旧执行收敛。
3. 在破坏旧会话之前做可行的目标预检；预检不以创建第二个活动 Agent 为代价。预检成功也不代表后续创建不会失败。
4. 通过官方入口替换会话，明确何时旧会话失效。失效时解绑旧订阅、关闭交互、收敛旧请求，并更新会话代际。
5. 绑定新会话的必要内建能力与桌面交互，取得实际会话身份、历史基准和执行状态。
6. 将新会话基准与对应事件交接到展示层，再发布实际可操作状态。历史未取得时不能把空内容标作完整恢复成功。

页面可以先展示正确归属的历史或基本信息，但可读与可提交必须分开。已提交切换不能被后续点击偷偷改写归属，旧切换的迟到结果不得覆盖新的用户目标。

### 历史与实时事件交接

从官方会话数据或官方 SessionManager 获取权威历史，不假定 `subscribe` 会自动重放历史事件。建立基准和开始消费增量之间必须有明确交接，防止消息遗漏、重复或新消息被基准覆盖。

宿主代际、会话代际和投影序列承担不同职责。快照或增量属于旧代际时丢弃；增量失序时重新读取当前会话基准，不靠重发用户操作补齐展示。

历史读取与投影职责可以放到合适的非界面执行位置，但传输与页面更新仍需有界。长历史的增量展示可在详细设计中选择，不将它预先承诺为官方 SDK 已有行为。

### 提交、中止与冲突操作

prompt 由官方实现处理 Agent 队列与模型行为；桌面只表达用户提交是否已被接受、是否正在准备、以及结果是否未知。不能把整个回答结束当作提交接受响应。

会话替换、回退、资源重载与其他冲突写操作互斥。中止、审批、扩展 UI 和登录回应必须能解除当前等待，不能排在等待它们的替换或 prompt 后面。

模型切换不一律按中断处理，回退不一律按只读处理。操作类别以它对官方会话的实际影响决定，不能照抄参考项目的命令集合。

回退保持现有“仅回退对话，不撤销项目文件”的边界，分支与历史写入由官方实现负责。

## 6. 全局展示与认证过渡

会话切换只失效会话动态能力与对应投影，不清空范围仍有效的基础模型、认证状态和静态目录。全局查询可以尚未全部迁入新服务，但它的视图生命周期必须先从活动会话解除。

认证 helper 继续沿用；登录、退出与凭据修改后通知查询和活动会话同步相关状态。凭据、令牌和认证原始记录不得进入普通快照或日志。

静态预览不执行扩展或连接 MCP。执行中的工具、项目扩展 provider 和 MCP 能力以实际会话为准，不把目录预览等同于运行可用性。

## 7. 失败边界与基础恢复

| 失败位置 | 处理方向 |
|---|---|
| 目标预检失败，旧会话仍有效 | 返回目标错误，保留真实旧状态，不改称目标已打开 |
| 旧会话已失效，新会话创建失败 | 明确无可用活动会话；保留可读历史不等于保留可执行旧对象 |
| 创建成功但必要交互或历史基准失败 | 不发布完整 ready；回收或限制会话，按实际责任报告错误 |
| 非必要扩展加载失败 | 可单独降级并展示诊断；信任、审批或必要能力失效不能以警告绕过 |
| 请求超时 | 结果未知，不自动重发；若操作可能改变状态，限制冲突写入并读取权威状态 |
| 宿主退出 | 失效会话与交互、收敛 pending，窗口及有效展示副本保留 |
| 宿主重建 | 有上限恢复基础设施；不重放 prompt、回退或工具，不宣称 JSONL 丢失 |
| 应用主动关闭 | 取消恢复安排，让执行、交互及宿主关闭收敛，只处理应用拥有的对象 |

恢复会话需要重新读取 Pi 文件与状态，不能重用崩溃前的对象。持久化历史、未持久化输出、结果未知的模型请求与已经发生的工具副作用分别表达，不承诺撤销或恢复全部副作用。

## 8. 开发拆分方向

下面是依赖方向与拆分依据；实际实现状态只以代码及其注释为准，本文不记录进度与流水。

- **官方生命周期适配与宿主入口**：确认当前 SDK 的替换与关闭语义，建立独立构建入口和应用通信边界。
- **会话编排与请求归属**：接入主进程校验、信任、互斥、中止确认和失效处理。
- **历史基准与事件投影**：明确快照获取、订阅重绑和增量交接，替换 Runtime 代际耦合。
- **完整操作与交互**：接入提交、模型选择、中止、回退、必要内建能力、审批和扩展 UI。
- **全局展示与基础恢复**：保留有效快照，接入认证变化、宿主退出和切换失败的收敛。

这些是依赖方向，不是执行命令或已完成清单。跨模块改动应围绕会话主链一起设计，不能先留下绕过信任、历史或交互的可提交入口。

## 9. 本阶段待定事项与风险

需要结合实际依赖确认官方生命周期钩子、services 重建、静态查询路径、历史基准与事件交接、扩展 UI 契约、宿主模块格式与发行资源解析。具体请求字段、文件组织、重启预算和超时只在实现处维护。

原生扩展 ABI、动态导入、资源初始化与长历史仍可能影响流畅性。常驻进程去除正常切换的进程启停，不保证零等待或具体耗时，也不能证明既有 Runtime 报错都已消除。

本阶段向[阶段 2](./phase-2-implementation.md)交接稳定的宿主、会话与交互归属，以及必要快照的独立生命周期；不将基础故障处理或安全责任留给后续补丁。
