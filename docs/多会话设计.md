# 多会话开发设计

## 1. 文档定位

本文描述 Pi Desktop 同一窗口内多会话并行的需求、架构方向与开发边界，不表示功能已经实现，也不替代逐阶段的实施清单审批。

产品方向已经确认：**会话保留，宿主在空闲后自动回收，再次发送时自动恢复。** 用户不需要手动点击关闭宿主。每个运行中的会话独占 SDK 宿主是推荐架构，具体实现仍需结合各阶段调用链收窄。

## 2. 已确认需求与范围

### 2.1 多会话交互

- 同一窗口支持多个会话同时执行，允许跨项目并行。
- 使用侧栏会话列表管理和切换，不新增标签栏。
- 同一时刻只有一个前台会话；切换会话或项目不应中断后台操作。
- 前台会话所属项目决定当前项目上下文，项目资源展示与文件索引随前台会话切换。
- 后台等待审批或扩展输入时需要显示来源和等待状态，不抢占前台，也不能将回应发送给其他会话。
- 消息、草稿、图片附件和滚动位置不能串会话。

### 2.2 自动回收与恢复

- 回答完成不等于关闭会话，也不立即结束宿主。
- 前台和后台宿主均采用空闲延迟回收，不要求用户显式关闭。
- 回收只释放执行资源，不删除历史、不归档会话、不移除侧栏条目、不自动切换前台。
- 再次发送时自动恢复对应会话，再提交本次输入；不自动重发以前已提交或结果未知的操作。
- 仅查看历史不应强制建立完整的 Agent 执行环境。
- 用户停止当前操作与宿主资源回收是不同动作；停止不删除会话。

### 2.3 不做项

- 多窗口、分屏、额外标签栏。
- 将“侧栏多选”扩展为复选框或批量操作。
- worktree 隔离、自动文件冲突解决。
- 进程池、固定会话数量上限、资源监控面板。
- 自动恢复应用上次退出前的全部运行任务。
- 新增草稿与图片的跨应用重启持久化能力。
- 将设计落盘视为业务代码修改授权。

## 3. 当前项目事实与约束

项目采用 Electron、Vue、TypeScript、Pinia，Agent 执行由 Pi SDK 宿主承担。

当前实现已支持多个运行实例：运行身份、归属登记、定向请求、事件来源与项目范围收敛均已按实例贯通，
页面按二维身份（`runId` + `runtimeId`）寻址；渲染端仍只保存一份展示状态。

- `src/main/index.ts` 组合一个会话运行注册表、一个 `SdkRuntimeBridge` 和一个 `SessionManager`；宿主按运行实例按需建立，同一实例可跨会话复用。
- `src/main/session-run-registry.ts` 分配应用级运行身份与绑定代际，登记「归属项目 + 会话 id」的占用（含打开前占位、关闭中与退出未确认），并提供按项目或全应用范围的查询。
- `src/main/sdk-host-manager.ts` 监督单个 `utilityProcess`（每个运行实例一个），持有该实例的会话状态、投影和 Extension UI 镜像；授权只以注册表登记的归属项目为准。
- `src/sdk-host/session-runtime.ts` 管理该宿主内的单个活动 SDK 会话；新建、切换、分叉及重载会替换绑定，绑定代际由主进程分配。
- `src/main/sdk-runtime-bridge.ts` 按二维目标寻址：已由某实例承载的命名会话只转前台复用，其余优先复用空绑定实例、否则新建宿主；动作在目标与当前绑定一致时才发给宿主；只有前台实例的状态事件、投影批次与 Extension UI 快照进入页面（全部实例的粗粒度运行状态另经侧栏的运行状态通道下发）。
- `src/main/session-manager.ts` 的目标授权按调用方给定的归属项目执行；打开其他会话不再要求中断确认，重载按被重载会话的归属项目做信任复核。
- `src/main/project-manager.ts` 的前台项目切换只保存选择，不再收敛任何后台会话；项目移除按注册表登记逐个释放该项目范围内的实例。
- 渲染端 Runtime 与资源 Store 已按二维目标发请求并只消费前台实例的事件；侧栏经「会话运行状态」通道展示每个会话的运行、等待与未确认状态（阶段 1c-1）。消息投影、错误与模型的按会话分片，以及输入、阅读与扩展交互的分片留待 1c-2/1c-3。

必须延续的项目约定：

- Desktop 配置保持主进程单写者；多个会话宿主不得各自写入 Desktop 项目列表、偏好或窗口配置。
- 渲染端跨桥接载荷由 services 层显式重建为普通对象，不直接传递 Vue 响应式对象。
- 桥接失败保留原始异常信息，但不向页面暴露凭据或不应公开的宿主诊断内容。
- 运行身份与绑定代际都由主进程注册表统一分配；SDK 内部编号不得当作跨运行实例的全局身份。
- 配置和凭据是共享资源；独立进程不等于独立配置、独立文件目录或安全沙箱。

## 4. 推荐架构与职责

### 4.1 分离三个生命周期

| 对象 | 职责与生命周期 |
| --- | --- |
| 会话记录 | 表达会话身份、项目归属及历史；不随宿主退出而消失 |
| 运行实例 | 表达当前宿主、SDK 绑定和活动操作；按需建立，空闲后释放 |
| 前台视图 | 表达当前选择、消息展示、草稿与阅读位置；切换不决定后台执行是否继续 |

不能再以“当前项目”定位任意运行操作，也不能以“页面是否显示这个会话”判断是否销毁 SDK。

### 4.2 主进程会话运行注册表

推荐在主进程集中管理：

- 打开的会话及其规范项目归属。
- 会话对应的宿主、运行代际、生命周期操作与回收计时。
- 持久化会话占用关系，包括正在打开、正在关闭和退出未确认的实例。
- 前台选择及其对应的项目上下文。
- 运行状态、投影和交互事件的来源路由。
- 项目移除、应用退出时的范围化收敛。

查询和选择会话不应隐式重放业务操作。一个会话启动、恢复或回收时，其他会话仍可以独立运行；同一会话内部的冲突生命周期操作必须串行协调。

### 4.3 独立宿主

推荐每个实际运行的会话独占一个 SDK 宿主，复用已有单宿主监督能力，并将回收后的会话保留为无宿主状态。

选择该方向的原因是既有实现已经围绕单活动 SDK 会话建立了状态、投影、扩展交互和退出链，独立宿主有利于限制单个进程故障的影响。该选择不代表 Pi SDK 强制一会话一进程，也不代表它一定比同进程多 Runtime 更节省资源。

主进程必须引入独立于 SDK 持久化会话身份的运行身份。宿主重启、SDK 绑定变化及历史分叉都不能让旧请求命中新对象。

### 4.4 前端状态归属

运行状态、消息投影、错误、模型、审批、输入草稿和附件按会话保存；渲染层只选择其中一个会话显示。

- 后台事件继续更新来源会话的状态，不覆盖前台。
- 草稿提交和附件读取固定来源会话，迟到结果只能更新该来源。
- 滚动位置和跟随底部状态按会话保存。
- 项目文件候选按项目及请求归属处理，旧查询结果不进入新项目输入框。
- 应用内保留草稿和图片不等于将它们持久化到磁盘。

## 5. 自动回收与恢复

### 5.1 可回收的空闲

回收条件应同时覆盖主进程在途操作和宿主真实状态：

- SDK 不在执行模型或工具工作。
- 没有排队消息、独立 Bash 工作、等待中的审批或扩展输入。
- 没有尚未完成的 Prompt 提交、MCP 操作、会话切换、分叉、重载或其他生命周期操作。
- 不处于结果未知、恢复受阻或关闭失败状态。

普通等待用户发送下一条消息属于空闲；扩展已经提出输入请求并等待回应则不属于空闲。不能将低层的消息结束事件或单次模型调用结束事件直接视为全部工作结束。

满足条件后开始空闲宽限期。新的执行活动或需要宿主的显式操作取消计时。自动读取状态和页面渲染不应不断延长宿主寿命。

宽限期时长在实现阶段确定，不在初步设计中将未经资源测量的时间常数写成性能结论。

### 5.2 回收与新提交互斥

计时器到期只是发起回收判断，不是直接终止进程的依据：

1. 主进程固定目标运行身份，协调新提交与回收请求。
2. 宿主复核当前绑定和真实空闲状态；状态已变化时放弃本次回收，继续原工作。
3. 真正开始释放后，不再把新请求发送给正在退出的宿主。
4. 新发送若遇到已经开始的释放，等待旧宿主确认退出后，再恢复会话并提交。
5. 未确认旧宿主退出时保留占用，不建立第二个实例接管同一历史。

当前 `shutdown()` 会取消交互并中止工作，不能直接复用为计时器的无条件退出入口。自动回收需要宿主侧的空闲复核及明确的状态交接。

### 5.3 资源释放与展示保留

正常释放应经过 SDK 生命周期，处理扩展关闭与 MCP 连接释放，再等待宿主真实退出。超时不能伪装成成功；需要定向结束宿主时，也只能作用于应用拥有的目标。

回收前后保留最后可用的消息展示、会话身份、模型信息和用户输入状态。运行资源已释放后：

- 不清空聊天区，也不显示成会话被删除或异常丢失。
- 不将缓存的 MCP 状态描述为仍然在线。
- 资源缓存只能表达该会话上次加载的内容，不能冒充重新读取的最新配置。
- 历史基准与流式投影必须区分；恢复后以新实例的权威快照重新同步。

宿主退出并不能证明任意工具派生的所有后代进程均已结束。必须区分受管资源关闭与用户命令自行启动的脱离进程，不按进程名称扫描并终止无关程序。

### 5.4 自动恢复与提交

再次发送时，主进程按会话记录定位项目及历史，重新检查目标归属、信任和占用，再建立运行实例。并发触发的恢复应合并到同一会话的单次建立过程。

恢复成功后，仅提交这次用户明确发送的输入。提交目标和输入内容在发起时固定，不能在等待结束后改取前台草稿。

- 恢复失败时保留草稿和附件，并将错误归属到该会话。
- 恢复时若出现新的真实信任要求，仍需用户决定，不能为自动恢复绕过授权。
- 结果未知的旧请求不自动重试。
- 没有落盘历史的空会话保留输入意图，下次发送按新建处理；不能伪造可恢复的历史身份。
- 存在有效历史却无法读取时明确失败，不静默创建同名空会话替代。

正常空闲回收后的自动恢复，与宿主崩溃后的结果未知恢复不是同一流程。

### 5.5 执行停止、项目移除与应用退出

| 场景 | 处理方向 |
| --- | --- |
| 一轮全部工作完成 | 进入空闲计时，会话继续可见 |
| 切换前台会话或项目 | 不停止后台工作，不因为隐藏而关闭宿主 |
| 用户停止当前操作 | 中止指定会话的工作；收敛为空闲后再按通常规则回收 |
| SDK 扩展明确要求结束会话 | 进入统一生命周期管理，不能留下注册表不知道的空宿主 |
| 移除项目 | 固定该项目范围，处理其中所有运行实例；有未完成工作时明确确认中断；不删除项目目录或历史 |
| 退出应用 | 先阻止所有新建与恢复，再对全部宿主启动关闭；不能因一个关闭失败而跳过其余宿主 |

对于宿主关闭失败，应保留受阻状态和占用关系，不将仍可能存活的宿主从管理中遗忘。

## 6. 授权、共享资源与持久化边界

### 6.1 项目授权

会话在注册时绑定其所属项目，宿主不能借助前台项目变化获得另一个项目的授权。打开、恢复、重载及扩展发起的目标变化均通过主进程授权。

项目级文件索引和资源展示随前台选择变化，后台会话的执行目录与授权归属保持不变。没有前台会话时，项目选择只为浏览或新建提供上下文，不为其他后台会话重新指定目录。

### 6.2 防止重复接管

应用内同一个持久化会话只能由一个运行实例接管。占用应覆盖打开中的异步间隙和关闭未确认的状态，而不只是已就绪状态。

侧栏打开之外，SDK 扩展切换、新建、分叉及对话回退引起的身份变化，也必须纳入管理。不能假定持久化会话身份在运行实例生命周期中永远不变。

应用内登记不等于跨应用文件锁，不能据此保证外部 CLI 或其他程序不会同时改写同一会话文件。

### 6.3 配置、模型与凭据

- Desktop 项目配置、窗口和偏好继续由主进程唯一写入。
- 会话模型选择与全局默认模型是不同状态。推荐将两种用户意图分开表达，避免一次会话选择隐式改变全局默认；该交互调整属于推荐设计。
- 共享 Pi 配置写入需协调，不能仅因 Desktop 配置是单写者就推导所有 SDK 配置都安全。
- 官方凭据和动态模型目录存储已有文件锁，MCP OAuth 还有刷新互斥，应优先复用，不能无依据另建重复认证系统。
- 配置文件写入完成不代表所有驻留会话已经更新；不为传播配置而自动中断后台任务。
- 自动恢复会重新读取资源；新增或变化的受保护资源仍需遵守项目授权。

### 6.4 同项目并行与资源成本

多个会话使用同一项目目录时可能修改相同文件。进程隔离不能解决代码覆盖、Git 状态竞争或配置文件冲突，本任务不引入 worktree 或自动冲突解决。

当前 SDK 为会话创建独立 services，内置 MCP 扩展在会话启动时建立连接。多个活动宿主可能增加连接和 stdio 服务进程，不能假设同项目会话自动共享 MCP。

回收可以释放宿主资源，但频繁恢复会重新加载 SDK 资源及连接 MCP。会话历史不能恢复扩展所有仅存内存的状态；连接恢复也不保证外部服务会话连续。这些是自动回收方案的真实代价。

| 项目级请求仍可能以后台已变化的上下文收尾 | `src/renderer/src/stores/session.ts` 的列表补读没有项目令牌；`src/main/project-file-index.ts` 查询结束不复核项目；MCP 配置列举、MCP 探测与资源预读按前台项目 | 前台切换时旧结果可能进入新项目的视图 | 独立小项：列表与文件候选绑定项目及请求代际（摘要缓存已按项目隔离） |
| 桥接边界仍有失配 | `src/renderer/src/services/` 中部分调用仍丢失异常原文 | 排错信息缺失 | 独立小项：逐条核对服务层异常处理 |
| 共享配置写入竞争 | `src/main/pi-settings-manager.ts` 的文件标识检查与改名之间没有共享锁；本地 Pi SDK 的 `dist/extensions/mcp/config.js` 直接整文件读改写 | 多宿主及桌面设置修改可能互相覆盖 | 保持 Desktop 单写者，对受支持的共享 Pi 配置修改建立与 SDK 相容的互斥与合并边界 |
| 凭据初始化与交互竞争 | 本地 Pi SDK 的 `dist/core/auth-storage.js` 在取锁前初始化文件；`dist/core/models-store.js` 复用该存储；`dist/extensions/mcp/oauth.js` 已有刷新锁 | 首次初始化仍有竞争窗口，同一共享凭据可能收到冲突的登录或退出意图 | 复用官方锁，协调首次初始化及同凭据交互，不把已有保护误判为完全无锁 |
| 会话模型与全局默认耦合 | `src/renderer/src/components/RuntimeModelSelect.vue` 同时调用会话模型切换和全局默认保存；SDK 的会话模型切换本身默认不持久化全局默认 | 会话内操作影响未来其他会话的默认选择 | 推荐分开表达会话选择与全局默认设置，不联动其他已打开会话 |
| 自动回收不能复用无条件退出 | `src/sdk-host/session-runtime.ts` 的 `shutdown()` 会取消交互并中止工作（`release` 只释放当前会话）；`src/main/sdk-runtime-bridge.ts` 的 `releaseRun` 只解除占用 | 计时器与新任务竞争时可能误停工作；空闲判定尚未存在 | 阶段 3：增加宿主侧空闲复核与提交互斥；释放失败保留占用，确认退出后才允许恢复 |
| 同项目文件及外部资源不隔离 | `src/sdk-host/session-runtime.ts` 按项目目录建立会话 services；本地 Pi SDK 的 MCP 扩展按会话建立连接 | 并行写文件可能冲突；回收恢复会增加连接建立成本并丢失扩展内存状态 | 明示共享目录和资源生命周期边界，不引入未经确认的文件隔离或自动冲突解决 |
| 未确认退出的实例仍未收敛到界面 | `releaseRun` 保留占用并返回错误；侧栏已标记「上次退出未确认」（阶段 1c-1），但仍缺直接恢复入口 | 用户能看到阻塞态，却只能靠重启应用恢复 | 阶段 3：给出唯一恢复动作（重试释放或重启应用） |
| 未绑定会话的实例不在侧栏可见 | `stores/session-runs.ts` 只按「归属项目 + 会话 id」归集；`sessionId === null`（点「新建」但未发出第一条消息）的实例没有条目 | 该实例在侧栏不可见；重复点「新建」会复用同一个，因此不会累积宿主 | 阶段 3：随空闲回收一起处理，或在侧栏补一行未命名实例 |

## 8. 开发阶段与待定事项

### 8.1 阶段方向

1. **会话归属与生命周期基础**：明确注册表、运行身份、项目授权、重复接管及 SDK 内部会话变化的协调边界。（已落地）
2. **多会话请求和状态流**：贯通定向请求、事件、投影、审批及前端状态分片，分离前台选择和后台执行。（定向请求、事件来源、二维身份与侧栏运行状态（1c-1）已落地；投影/输入/交互分片待 1c-2、1c-3）
3. **空闲回收与按需恢复**：在前述身份及并发边界上实现空闲判断、回收交接、展示保留、恢复与提交，以及项目和应用范围关闭。
4. **侧栏与输入体验整合**：让运行、等待、无宿主和恢复状态可理解，保持草稿、附件、阅读位置和项目资源归属；同步直接受影响的描述。

阶段按依赖划分，不表示可以遗漏完整问题清单中的相邻问题。共享配置与凭据协调应在引入相应并发写入前完成设计。

### 8.2 实现阶段需要明确

- 空闲宽限期及其内部配置位置。
- 不建立完整执行环境时的历史读取与投影复用方式。
- 多运行实例下的登记交接与侧栏呈现：SDK 新建、分叉及扩展切换引起的身份变化，以及未确认退出的提示与恢复入口。
- 已回收会话执行模型切换、重载及 MCP 操作时的按需建立边界。
- 共享配置修改与凭据首次初始化的具体协调入口。
- 关闭失败后的可恢复状态及用户提示。

这些事项应依据目标文件及直接调用链收窄，不凭初步设计提前锁定文件修改范围或第三方内部实现。

## 9. 外部参考及适用边界

- [Zed Parallel Agents](https://zed.dev/docs/ai/parallel-agents)：可借鉴按项目分组、后台独立运行、点击切换前台，以及区分运行与历史管理的交互。该页面不能证明其 Agent 宿主常驻或回收策略。
- [Claude Code Desktop](https://code.claude.com/docs/en/desktop)：提供并行会话与归档管理。其归档和 worktree 行为不等于本项目需要引入归档或 worktree，也不能据此认定宿主的空闲回收机制。
- [Codex App Server](https://developers.openai.com/codex/app-server)：区分持久化线程和已加载运行实例，支持在无订阅、无活动后延迟卸载线程。可借鉴执行、加载与历史三个生命周期的分离；线程卸载不等于结束整个 app-server，不能直接套用为桌面切换行为。
- [OpenCode Server](https://dev.opencode.ai/docs/server/)：展示共享服务与按会话寻址的接口方向，仅作为架构对照，不将其内部进程回收实现作为本项目依据。
- [Electron utilityProcess](https://www.electronjs.org/docs/latest/api/utility-process)：提供宿主创建、消息及退出事件，不为应用规定会话池或空闲回收政策。
- 本地 Pi SDK 的 `docs/sdk.md` 与 `examples/sdk/13-session-runtime.ts`：说明会话、services 和 Runtime 替换边界，支持复用既有 SDK 生命周期；不构成“一会话一进程”的官方要求。

本项目的自动回收方向来自已确认的产品要求，独立宿主则是结合当前工程结构的推荐。不能把类似产品的界面行为推导为其私有进程策略，也不能把进程隔离解释为文件隔离或安全沙箱。
