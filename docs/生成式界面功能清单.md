# 生成式界面功能清单

本文说明 pi-desk 内置的「生成式界面」能力有哪些功能、各自解决什么问题、代码落在哪里，以及后续扩展时要同步改动的位置。字段细节与数量上限以 `src/shared/genui-api.ts` 为准，本文不重复抄写数值，只列关键约束。

> **4** 个工具 · **13** 种节点 · **6** 种图解 · **4** 种图表 · **7** 个字段主题

---

## 1. 能力总览

**模型不再只输出文字，而是输出一份声明式文档，由桌面端渲染成对话内的原生面板。**

面板与消息混排、留在历史里、可反复修改。对外是四个工具：

| 工具 | 动作 |
| --- | --- |
| `ui_render` | 交付整份界面文档 |
| `ui_patch` | 按 `documentId` 只发改动部分 |
| `ui_catalog` | 按主题读取字段说明 |
| `ui_inspect` | 列界面清单，或读结构大纲 |

什么时候用哪个：新建界面或结构大改（重排大部分节点）走 `ui_render`；改文案、换数据、增删一两个节点走 `ui_patch`；模型不确定字段形状时查 `ui_catalog`；修改前确认 `documentId` 与节点路径用 `ui_inspect`。

设计取向：

- 能力是产品内置的，不是用户自行安装的插件；注册失败只让生成式界面不可用，不影响会话建立。
- 字段说明不常驻在工具描述里，改成按主题按需查询，控制上下文占用。
- 模型写的是「内容与关系」，不是 HTML/CSS/脚本——这些字段根本不存在。

## 2. 何时出现、何时不出现

**内容本身值得用界面表达时出现；一句话能说清的内容留在正文。**

| 内容形态 | 呈现方式 |
| --- | --- |
| 方案或选项对比 | `row` 并排 `card`，每张一个方案 |
| 一组关键数字 | `row` 并排 `metric` |
| 多条同类记录 | `table`，可排序、可筛选 |
| 操作先后顺序 | `steps`；带具体时间点用 `timeline` |
| 需要用户亲自试算 | `params` + `controls`，可配 `diagram` |
| 机制与结构讲解 | `diagram`（6 种） |
| 趋势与占比 | `chart`（4 种） |

不会出现：

- 纯解释、闲聊、简短结论。
- 代码、命令、文件路径清单。
- 一句话能说清却包成一堆卡片的内容。

这条边界有实现层面的保障：交付时会做非阻断的交付检查，对以下情况给出提示，引导模型改写而不是继续堆界面——只有文本节点、首屏只剩一个收起的折叠容器、fallback 过短或与 title 相同、空表格、参数全被条件隐藏、同名参数分组不相邻。

## 3. 面板能放什么（节点类型）

**13 种节点分三类：内容节点、结构节点、图形节点。**

内容节点：

| 节点 | 用途 |
| --- | --- |
| `text` | 段落、结论、警告 |
| `list` | 要点列表 |
| `metric` | 单个指标 |
| `table` | 同类记录 |
| `steps` | 先后步骤 |
| `timeline` | 带时间点的过程 |

结构节点：

| 节点 | 用途 |
| --- | --- |
| `card` | 主题分组 |
| `row` | 并排比较 |
| `collapse` | 次要内容收纳 |
| `tabs` | 并列互斥内容 |
| `controls` | 参数控件组 |

图形节点：

| 节点 | 用途 |
| --- | --- |
| `diagram` | 机制图解 |
| `chart` | 图表 |

约束：

- `text`：`tone` 可取默认/次要/强调/成功/警告/危险，`size` 可取小/正文/大。
- `list`：可有序，条目数有上限。
- `metric`：标签 + 数值 + 单位；值可为字符串或有限数字。
- `table`：列 key 不重复，单元格只能是字符串或有限数字；排序与筛选由桌面端提供，文档里不声明。
- `steps`：只表达顺序，不带状态字段，不伪装成任务进度。
- `timeline`：时间是自由文本，桌面端不解析不排序，按数组顺序渲染。
- `card`：子节点至少一个；标题就是分区标题。
- `row`：可给期望列数上限，窄容器自动减列。
- `collapse`：默认收起，`open:true` 才默认展开；组内不允许 `controls`。
- `tabs`：一次看一页；页内不允许 `controls`。
- `controls`：只能引用已声明参数；每个声明的参数都必须被某个 `controls` 引用。
- `diagram`、`chart`：叶子节点，内部不再嵌套。

全局约束：节点总数与嵌套层数有上限，单段文本有字数上限，未知 `type` 整份拒绝（不做降级猜测），空字符串按缺失处理。

## 4. 机制图解（6 种）

**几何与推导结论都由桌面端算出，同时以文字给出结论，不依赖看图理解。**

| kind | 用途 | 输入 | 可调绑定 |
| --- | --- | --- | --- |
| `exploded` | 装配拆解，纵向展开零件 | 零件列表（名称 + 说明） | `spread`（0~1 拆解间距） |
| `gear` | 齿轮传动 | 各级齿数 | `angle`（主动轮驱动角） |
| `crank` | 曲柄连杆 | 曲柄长、连杆长 | `angle` |
| `vector` | 力矢量与合力 | 各力的模长与方向角 | `angle`（整体旋转） |
| `circuit` | 串联电路 | 电压 + 元件（电阻/灯泡/开关） | `voltage` |
| `section` | 层状剖面（同心圆环） | 各层厚度（由内到外） | 无 |

`crank` 的输入必须满足连杆长度大于曲柄长度。

推导结论举例：齿轮给出转速比与转向、曲柄给出活塞位移、力矢量给出合力（模长几乎相抵时写「受力平衡」）、电路给出总阻/电流/各元件压降/总功率（含断开开关时写「回路不通」）、剖面给出各层外径与环形面积占比。

绑定不是表达式：只有 `spread` / `angle` / `voltage` 三个键，值必须是已声明的 `number` 参数 id；绑定也不会让参数免于被 `controls` 引用。

## 5. 图表（4 种）

**四类图各对应一种读法：分类对比、趋势、占比、占比加总计。**

| kind | 用途 |
| --- | --- |
| `bar` | 分类对比，从零线起算，正负方向相反，多序列并排分组 |
| `line` | 趋势与变化 |
| `pie` | 占比，单序列 |
| `donut` | 占比 + 中间显示总计 |

结构规则：

- `labels` 是分类轴，`series` 最多 3 条且 `values` 长度必须与 `labels` 一致。
- 多序列时 `name` 必填且不重复。
- 柱状与折线允许负数，饼图与环形不允许。
- 饼图/环形只能一条序列，切片数有上限，百分比由桌面端计算。

选型规则：

- 占比与构成优先 `pie`/`donut`，不要用柱状图让人硬读比例。
- 超过切片上限或需要跨分类对比时改用 `table`。
- 图表不绑定参数——需要随参数变化用 `diagram`。

## 6. 参数交互

**调参数不请求模型，只有用户点提交才发出一条真实用户消息。**

四类控件：`number`（滑杆）、`select`（下拉）、`toggle`（开关）、`text`（单行输入）。数量有上限，`id` 需符合命名规则。

分组：`group` 按声明顺序把相邻同名参数归到同一区块；同名却不相邻会被拆成两块，交付检查会提示调整顺序。

条件显示：`visibleWhen {id, equals}`，目标只能是 `select` 或 `toggle`，不支持多级依赖，不能自引用，也不能是被图解绑定的目标。条件不满足的参数仍随提交带出，并标注「条件未满足，未生效」。

交互语义：

- 调参数只是本地取值变化，不请求模型。
- 只有用户点提交，才发出一条以 `[genui] 界面参数已提交` 开头的真实用户消息，逐行列出当前取值；模型据此认定是同一份界面的回填。
- 界面底部自带「重置为默认值」：首次点击只进入确认态，超时或改任一参数即撤销，再次点击才生效；无需在文档里声明。
- 被隐藏参数同样出现在提交文本里，避免模型误以为参数丢失。

取值存放：

- 内存是运行时真源，键为 `documentId`（每份界面只有一份可交互），条目数有上限并按创建序淘汰最旧。
- 文档改版时按参数 `id` 迁移已调取值，并按新区间/步长/选项重新收敛；迁移有有效期，超期回落默认值并提示；回退到旧版本不迁移，避免取值跨分支泄漏。
- 磁盘侧是本机旁路文件 `genui-params.json`，与 `desktop-config.json` 刻意分开（参数是高频变化、可再生的缓存）。节流回写、提交与卸载时立即落盘、原子替换、单条记录容错、超期丢弃、文件超字节上限整体重建。

## 7. 对话内行为

**界面身份与版本完全由当前分支的工具结果推导，视图状态不进文档。**

- **版本**：`ui_render` 不带 `documentId` 是新建（`revision` 从 0 开始），带则自动加一；`ui_patch` 必须带 `documentId` 且总是应用到当前分支最新版。每个版本都存完整文档（不是补丁链），任一版都能单独渲染。
- **旧版处理**：被取代的版本折叠成一行只读记录，可展开查看但控件与提交都禁用，可点击跳转到新版。
- **分支语义**：界面的身份与版本完全由当前分支的工具结果推导，不落外部文件；rewind 到修改之前时，那一版重新成为最新版并恢复可交互。
- **按需挂载**：界面进入视口附近才挂载真实组件，远离视口退化为占位，并自行补偿滚动高度（对话区关掉了浏览器的滚动锚定）。
- **复制 Markdown**：全量输出（表格全部行、折叠与标签页全部展开），图形节点复用几何层算出的结论，参数取屏幕上的当前值。
- **活动条**：对话区顶部的活动摘要条有「界面」分类，列出本次会话交付过的界面与版本。
- **视图状态不落文档**：表格排序筛选、折叠开合、标签页选中页都只是视图状态，文档改版后重置。

## 8. 开关与清理

### 整体开关

**设置 → 功能 → 生成式界面** 控制这项能力是否可用。

- 只改「是否注册内置扩展」，不改 Pi 配置。
- 生效时机是会话创建期，所以切换后显示「已保存，待重新加载」并提供重载入口，不自动重载、不打断正在运行的回答。
- 重载成功后状态变为「已重新加载，开关已生效」；重载未完成时在本区块就地给出原因（被中断确认或信任流程拦下时是提示，真正失败时是错误）。
- 关闭后历史会话里已交付的界面仍能正常渲染。

### 清除已保存参数

**只删本机旁路文件里的取值，不动会话与界面文档。**

- 按钮旁显示当前已保存的界面份数。
- 参数预加载结束前按钮禁用，避免清掉的记录被迟到的预加载补回内存。
- 已挂载的界面不会被强制重建，仍显示原取值，重新打开或文档改版后才回到默认值。

## 10. 扩展与开发注意点

### 新增一种节点类型

例如 `code`、`image`：

1. `src/shared/genui-api.ts`：加类型定义、上限常量、解析分支（含容器/叶子与嵌套层数判定）、修复分支（如果可机械修正）。
2. `src/sdk-host/genui/catalog.ts`：在 `NODES` 里补字段说明；需要时新增主题。
3. `src/sdk-host/genui/tools.ts`：更新 `ui_render` 的工具描述与 `promptGuidelines`。
4. `src/renderer/src/components/genui/GenuiNode.vue`：加分派分支；新增对应渲染组件。
5. `src/renderer/src/genui/markdown.ts`：补 Markdown 序列化分支，否则复制时会缺内容。
6. `src/sdk-host/genui/outline.ts`：如果是容器，补路径层级展示。
7. `src/sdk-host/genui/diagnostics.ts`：如果新类型会带来「负价值用法」，补交付检查。

### 新增图解种类

在 `GENUI_DIAGRAM_KINDS` 加种类 → `catalog.ts` 的 `DIAGRAM_KIND_DOCS` 补文档（`Record<GenuiDiagramKind, string>` 会强制补齐，缺键即编译报错）→ `genui-api.ts` 加字段定义与解析 → `diagram-geometry.ts` 加布局纯函数 → `GenuiDiagram.vue` 加标题映射与分派 → `markdown.ts` 补输出。

### 新增图表种类

`GENUI_CHART_KINDS` → `catalog.ts` 的 `CHART_KIND_DOCS`（同样是穷尽 `Record`）→ 解析 → `chart-geometry.ts` → `GenuiChart.vue` 的 `KIND_TEXT` → `markdown.ts`。

### 其它约定

- **上限与常量**：所有数量上限集中在 `src/shared/genui-api.ts`，`catalog.ts` 通过导入拼进说明文本，不重复声明数值。改上限只改一处。
- **诊断与修复**：严格解析是唯一准入，修复只处理引用与冗余这类机械错误；失败文案会进入模型上下文，因此要短、具体、不重复——前两次给完整排查路径，同一错误连续多次后直接指向 `ui_catalog({topic:"examples"})`。
- **版本与存储边界**：界面文档走工具结果 `details`（天然跟随分支），参数取值走本机旁路文件（不进 session，避免污染回放与 fork/rewind 语义）。改这部分时要保持这个分工。
- **测试现状**：`package.json` 的 `test` 脚本只覆盖 `src/main/*.test.ts` 与 `src/renderer/src/*.test.ts`；`src/sdk-host/genui/` 与 `src/renderer/src/genui/` 下目前没有测试文件，纯函数层（几何、markdown、参数收敛）是最容易补测的地方。

## 11. 已知边界与不支持项

**结构**

- 不写 HTML/CSS/脚本，也没有这些字段。
- 未知节点 `type` 或未知 `kind` 整份拒绝，不做降级猜测。
- `diagram` 与 `chart` 是叶子节点，内部不嵌套其他节点。
- `collapse` / `tabs` 内不允许 `controls`（收起或切页会让参数看不见却仍被提交）。

**交互**

- 图表不绑定参数；需要随参数变化的图形用 `diagram`。
- `visibleWhen` 不支持多级依赖，目标只能是 `select` / `toggle`。
- 参数不做派生计算（需要受限求值器，不在当前层）。
- 电路只支持串联；并联与分支需要节点图自动布局，目前用 `table` 表达。

**修改与视图**

- `ui_patch` 的粒度是节点：改表格里的一行也要 `replace` 整个 `table` 节点，没有行级、项级补丁。
- 折叠开合、标签页选中页、表格排序筛选都是视图状态，不写文档、不参与提交，文档改版即重置。
- 表格排序筛选与复制出的 Markdown 无关：复制始终是全量、文档顺序。
