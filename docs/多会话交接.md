# 同时多对话任务交接文档

## 0. 用途与阅读方式

本文档用于把「同一窗口多会话并行」任务交接给下一位开发者。它记录**当前事实、已完成工作、剩余工作与必须遵守的边界**，不构成任何实施授权。

必读配套：

- `docs/多会话设计.md`：需求与架构基线（§3 现状、§7 问题清单、§8 阶段方向已同步到阶段 1b）。
- `.agents/memory/INDEX.md` 及 `topics/conventions/`：桌面配置单写者、渲染端桥接调用、平台中立等硬约定。
- `package.json` 的 scripts：构建与类型检查入口。

接手后仍按仓库规则执行：先只读收窄 → 给出方案与推荐 → 提交**逐文件执行清单** → 用户明确审核同意后才修改；构建、类型检查、运行、测试均需**单独授权**。

---

## 1. 任务目标（已确认，不要重复讨论）

- 同一窗口支持多个会话同时执行，允许跨项目并行。
- 用侧栏会话列表管理和切换，不新增标签栏；一个前台会话，后台继续执行。
- 前台会话所属项目决定当前项目上下文，项目资源展示与文件索引随前台切换。
- 生命周期：**会话保留 → 宿主空闲延迟自动回收 → 再次发送自动恢复**（替代早前「全部打开即常驻」）。
- 回收语义：不删除历史、不归档、不移除侧栏条目、不切换前台；保留消息、草稿、图片与滚动位置；再次发送只提交本次新内容，不重放旧请求。
- 仅查看历史不应强制建立完整 Agent 执行环境。
- 不做：多窗口、分屏、批量操作（侧栏多选）、worktree、进程池、固定会话数上限、资源监控面板、自动恢复退出前的全部任务、草稿与图片的跨应用重启持久化。

## 2. 技术栈与不可违背的技术边界

- 技术栈：Electron + Vue 3 + TypeScript + Pinia + Pi SDK `@earendil-works/pi-coding-agent`（版本以 `package.json` 为准）。渲染端为 Vue 3 **JavaScript**（`vue-spec`），主进程/宿主为 TypeScript。
- `DesktopConfigStore` 保持主进程单写者；多个会话宿主不得各自写 Desktop 配置（项目列表、偏好、窗口）。
- 渲染端跨 `contextBridge` 载荷必须由 `src/renderer/src/services/` 显式重建为普通对象，不传 Vue 响应式对象。
- 桥接失败必须保留原始异常文本（新增 IPC 通道走 `src/main/index.ts` 的 `handle()` 包装）。
- 授权绑定会话归属项目，不依赖可变的前台项目。
- 同一个持久化会话在应用内只能由一个运行实例接管；占用覆盖打开中与退出未确认状态。
- SDK 内部编号不得当作跨运行实例的全局身份。
- 页面契约的二维身份已落地：`runId` 定位运行实例，`runtimeId` 是应用级唯一的绑定代际；动作在两者都与该实例当前状态一致时才发给宿主。
- 自动回收不能用 `src/sdk-host/session-runtime.ts` 的 `shutdown()` 作无条件入口：需要宿主侧复核空闲并与新提交互斥；未确认旧宿主退出前不建立替代宿主。
- 等待审批、扩展输入、排队、工具执行、生命周期操作**不属于**空闲；普通等待用户下一条消息属于空闲。
- 共享 Pi 配置写入与凭据首次初始化的协调，应在引入并发写入之前完成设计。
- 进程隔离不等于文件隔离或安全沙箱；不要编造内存、启动耗时或连接数量。

## 4. 阶段 1b 落地明细

### 4.1 主进程

`src/main/sdk-runtime-bridge.ts`（改动最大）：

- 状态映射 `mapStatus(host, session, runId)`、`IDLE_STATUS`、`EMPTY_PROJECTION`、`EMPTY_EXTENSION_UI` 都带 `runId`；`sameStatus` 比较加入 `runId`。
- 事件按实例订阅：`attachRun(runId, host)` 每实例挂接一次并保存 detach（`Map<number, () => void>`）；宿主 `failed` 时 `markUnconfirmed(runId)`。
- 只有**前台实例**的状态事件、投影批次与 Extension UI 快照进入页面（`forwardBatch`/`forwardUi` 过滤，并补 `runId`）；`publishStatus()` 只映射前台实例。全部实例的粗粒度运行状态另经运行状态列表广播，见 §4.5。
- 目标解析 `matchedRun(target)`：实例必须存在且不是 `unconfirmed`，`runtimeId` 非空时必须等于该实例当前绑定；读取能力/诊断/投影允许未绑定，提交、中止、资源、MCP 与交互要求已绑定。
- 实例选择与建立 `ensureRun`：已占用命名会话 → 转前台复用（未确认退出时抛 `SESSION_OPERATION_CONFLICT`，不重复接管）；否则复用「宿主可用且无绑定、且不承载其他项目会话」的实例；都不命中才 `allocateRunId → createHost → registerRun → attachRun`。
- `stop()` 被删除，替代为 `releaseRun(runId, allowInterrupt)`（宿主未建立或已失败时只解除占用；未确认时保留占用并返回错误）、`runHasPendingWork(runId)`、`foregroundRunId()`、`sessionStatusOfRun(runId)`、`focusRun(runId)`（转前台并补发该实例的交互快照，供编排层复用）。
- `switchSession(action, reference, allowInterrupt, owner)`：`action !== 'reload'` 且会话已被占用时幂等转前台；否则 `beginOpen`（冲突 → `SESSION_OPERATION_CONFLICT`）→ 必要时 `resetSessionHost()` → `runSessionAction` → `settleOpen`；失败 `failOpen`。

`src/main/session-manager.ts`：

- `applyOpen` 删除全局 `starting/stopping` 与「前台流式需中断确认」拦截：多实例下打开其他会话不中断任何会话；保留同会话幂等返回与 `SESSION_NOT_FOUND` 检查。

- `releaseRun` 只在**项目移除**时被调用，应用退出仍走 `shutdown()`；前台项目切换不再释放任何会话（设计 §5.5 的方向）。

### 4.7 阶段 1c-2 已落地：输入与阅读状态按会话保存

- 新增 `src/renderer/src/stores/session-view.ts`：按会话保存草稿、待发送附件、粘底与滚动位置；附件预览地址（objectUrl）由该模块统一创建与释放，视图卸载不释放（切到设置页时草稿与附件仍然保留），应用退出时统一释放。状态只在内存中，不写磁盘。
- 会话键由前台实例报告的会话身份派生：已绑定会话为 `session:<会话 id>`，未绑定实例为 `run:<运行身份>`，都没有时是 `idle`。同一实例暂时失去会话身份（宿主失败、关闭中）时沿用上一次的会话身份，否则一次宿主故障就会把用户输入判给别的会话。
- `PromptComposer.vue`：草稿与附件在会话切换时存回原会话、取走目标会话；空闲与未绑定实例没有独立历史，输入随会话建立原样带走（「首次发送只启动 Runtime」的路径因此不换内容）；提交固定来源会话，附件读取期间切走时不再把迟到结果落到新会话；视图卸载时按会话留底。
- `ChatMessageList.vue`：粘底与滚动位置按会话保存，切回时在投影同步过程中逐批应用保存的位置；同一会话重绑（Runtime 代际变化）没有可恢复的位置，仍按原来的方式贴底。
- `App.vue`：在 Runtime 之后初始化该 store（会话身份要先于运行状态就绪），页面卸载时释放。
- 已知边界：只登记已绑定会话的状态，空闲与未绑定状态不留底；同一会话被释放后由新实例接管（阶段 3 的回收恢复）时按会话键仍能取回，但当前还没有释放路径，因此该场景尚不存在。

## 6. 阶段 1b 的生效决策（D1–D7）

- **D1 页面二维身份**：`runId` + `runtimeId`；`RuntimeStatus` 必带 `runId`，投影快照/批次与 Extension UI 快照由桥接层补 `runId`（因此这两个类型用可选字段，宿主协议载荷不带）。
- **D2 事件路由**：桥接层按实例订阅，只有前台实例的状态事件、投影批次与交互快照进入页面；后台实例的这两类事件在 1b 直接丢弃（完整分片留给 1c）；全部实例的粗粒度运行状态见 §4.5。
- **D3 实例复用**：已占用命名会话 → 转前台复用不重绑；否则优先复用空绑定实例，最后才新建宿主；「新建会话」点击不重复驻留宿主。
- **D4 前台/项目切换不收敛宿主**：释放入口只剩项目移除、应用退出与后续的空闲回收。
- **D5 reload 目标**：前台实例的当前绑定会话；信任判定在 `session-manager` 内按绑定会话的归属项目复核。
- **D6 渲染端最小适配**：只做契约跟随与「只消费前台实例事件」，保持单前台展示。
- **D7 范围外**：信任 decide/status 的来源会话绑定、渲染端完整分片、草稿/阅读位置、侧栏运行状态展示、项目级请求令牌、扩展 UI 快照来源的完整分片、空闲回收、共享 Pi 配置与凭据协调设计。
