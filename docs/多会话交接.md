# 同时多对话任务交接文档

## 0. 用途与阅读方式

本文档用于把「同一窗口多会话并行」任务交接给下一位开发者。它记录**当前事实、已完成工作、剩余工作与必须遵守的边界**，不构成任何实施授权。

必读配套：

- `docs/多会话设计.md`：需求与架构基线（§3 现状、§7 问题清单、§8 阶段方向已同步到阶段 1b）。
- `.agents/memory/INDEX.md` 及 `topics/conventions/`：桌面配置单写者、渲染端桥接调用、平台中立等硬约定。
- `package.json` 的 scripts：构建与类型检查入口。

接手后仍按仓库规则执行：先只读收窄 → 给出方案与推荐 → 提交**逐文件执行清单** → 用户明确审核同意后才修改；构建、类型检查、运行、测试均需**单独授权**。

---

## 1. 任务目标（已确认，不要重复讨论）

- 同一窗口支持多个会话同时执行，允许跨项目并行。
- 用侧栏会话列表管理和切换，不新增标签栏；一个前台会话，后台继续执行。
- 前台会话所属项目决定当前项目上下文，项目资源展示与文件索引随前台切换。
- 生命周期：**会话保留 → 宿主空闲延迟自动回收 → 再次发送自动恢复**（替代早前「全部打开即常驻」）。
- 回收语义：不删除历史、不归档、不移除侧栏条目、不切换前台；保留消息、草稿、图片与滚动位置；再次发送只提交本次新内容，不重放旧请求。
- 仅查看历史不应强制建立完整 Agent 执行环境。
- 不做：多窗口、分屏、批量操作（侧栏多选）、worktree、进程池、固定会话数上限、资源监控面板、自动恢复退出前的全部任务、草稿与图片的跨应用重启持久化。

## 2. 技术栈与不可违背的技术边界

- 技术栈：Electron + Vue 3 + TypeScript + Pinia + Pi SDK `@earendil-works/pi-coding-agent`（版本以 `package.json` 为准）。渲染端为 Vue 3 **JavaScript**（`vue-spec`），主进程/宿主为 TypeScript。
- `DesktopConfigStore` 保持主进程单写者；多个会话宿主不得各自写 Desktop 配置（项目列表、偏好、窗口）。
- 渲染端跨 `contextBridge` 载荷必须由 `src/renderer/src/services/` 显式重建为普通对象，不传 Vue 响应式对象。
- 桥接失败必须保留原始异常文本（新增 IPC 通道走 `src/main/index.ts` 的 `handle()` 包装）。
- 授权绑定会话归属项目，不依赖可变的前台项目。
- 同一个持久化会话在应用内只能由一个运行实例接管；占用覆盖打开中与退出未确认状态。
- SDK 内部编号不得当作跨运行实例的全局身份。
- 页面契约的二维身份已落地：`runId` 定位运行实例，`runtimeId` 是应用级唯一的绑定代际；动作在两者都与该实例当前状态一致时才发给宿主。
- 自动回收不能用 `src/sdk-host/session-runtime.ts` 的 `shutdown()` 作无条件入口：需要宿主侧复核空闲并与新提交互斥；未确认旧宿主退出前不建立替代宿主。
- 等待审批、扩展输入、排队、工具执行、生命周期操作**不属于**空闲；普通等待用户下一条消息属于空闲。
- 共享 Pi 配置写入与凭据首次初始化的协调，应在引入并发写入之前完成设计。
- 进程隔离不等于文件隔离或安全沙箱；不要编造内存、启动耗时或连接数量。

## 4. 阶段 1b 落地明细

### 4.1 主进程

`src/main/sdk-runtime-bridge.ts`（改动最大）：

- 状态映射 `mapStatus(host, session, runId)`、`IDLE_STATUS`、`EMPTY_PROJECTION`、`EMPTY_EXTENSION_UI` 都带 `runId`；`sameStatus` 比较加入 `runId`。
- 事件按实例订阅：`attachRun(runId, host)` 每实例挂接一次并保存 detach（`Map<number, () => void>`）；宿主 `failed` 时 `markUnconfirmed(runId)`。
- 只有**前台实例**的状态事件、投影批次与 Extension UI 快照进入页面（`forwardBatch`/`forwardUi` 过滤，并补 `runId`）；`publishStatus()` 只映射前台实例。全部实例的粗粒度运行状态另经运行状态列表广播，见 §4.5。
- 目标解析 `matchedRun(target)`：实例必须存在且不是 `unconfirmed`，`runtimeId` 非空时必须等于该实例当前绑定；读取能力/诊断/投影允许未绑定，提交、中止、资源、MCP 与交互要求已绑定。
- 实例选择与建立 `ensureRun`：已占用命名会话 → 转前台复用（未确认退出时抛 `SESSION_OPERATION_CONFLICT`，不重复接管）；否则复用「宿主可用且无绑定、且不承载其他项目会话」的实例；都不命中才 `allocateRunId → createHost → registerRun → attachRun`。
- `stop()` 被删除，替代为 `releaseRun(runId, allowInterrupt)`（宿主未建立或已失败时只解除占用；未确认时保留占用并返回错误）、`runHasPendingWork(runId)`、`foregroundRunId()`、`sessionStatusOfRun(runId)`、`focusRun(runId)`（转前台并补发该实例的交互快照，供编排层复用）。

### 4.7 阶段 1c-2 已落地：输入与阅读状态按会话保存

- 新增 `src/renderer/src/stores/session-view.ts`：按会话保存草稿、待发送附件、粘底与滚动位置；附件预览地址（objectUrl）由该模块统一创建与释放，视图卸载不释放（切到设置页时草稿与附件仍然保留），应用退出时统一释放。状态只在内存中，不写磁盘。
- 会话键由前台实例报告的会话身份派生：已绑定会话为 `session:<会话 id>`，未绑定实例为 `run:<运行身份>`，都没有时是 `idle`。同一实例暂时失去会话身份（宿主失败、关闭中）时沿用上一次的会话身份，否则一次宿主故障就会把用户输入判给别的会话。
- `PromptComposer.vue`：草稿与附件在会话切换时存回原会话、取走目标会话；空闲与未绑定实例没有独立历史，输入随会话建立原样带走（「首次发送只启动 Runtime」的路径因此不换内容）；提交固定来源会话，附件读取期间切走时不再把迟到结果落到新会话；视图卸载时按会话留底。
- `ChatMessageList.vue`：粘底与滚动位置按会话保存，切回时在投影同步过程中逐批应用保存的位置；同一会话重绑（Runtime 代际变化）没有可恢复的位置，仍按原来的方式贴底。
- `App.vue`：在 Runtime 之后初始化该 store（会话身份要先于运行状态就绪），页面卸载时释放。
- 已知边界：只登记已绑定会话的状态，空闲与未绑定状态不留底；同一会话被释放后由新实例接管（阶段 3 的回收恢复）时按会话键仍能取回，但当前还没有释放路径，因此该场景尚不存在。

### 4.8 阶段 1c-3 已落地：投影与扩展交互按来源会话分片

- `src/main/sdk-runtime-bridge.ts`：`forwardBatch`/`forwardUi` 不再按前台过滤，改为带 `runId` 转发全部实例的事件；前台状态映射与运行状态列表不变。
- `src/renderer/src/stores/runtime.ts`：新增按运行实例的投影分片（`backgroundProjections`）。离开前台时留底（含 `appliedRuntimeId`/`appliedSeq`），后台批次只更新来源实例的分片；切回前台时取回，代际一致且已同步时不再重取。无基准或代际不符时只标记 `stale`，由切回时的重取收敛，不做无基准的增量。
- `src/renderer/src/stores/extension-ui.ts`：新增按运行实例的交互分片（`backgroundUi`）。后台快照只更新来源实例的分片（dialog、通知、状态条、widget、编辑器填充文本、收起态与回应状态）；切回时取回，分片代际与当前绑定一致才复用，否则重新查询（避免回应落到失效代际）。
- 分片寿命跟随运行实例：两个 store 各自监听运行状态列表，实例消失（释放、移除或退出）时丢弃对应分片；页面卸载时清空。
- 模型清单（`capabilitiesView`）按运行实例缓存：切回前台先用上次结果顶上，避免闪一次空列表；命中后仍会重新读取，不把缓存当权威。
- 顺带修正：中止请求与 dialog 回应的迟到结果不再写入已切换后的前台展示状态（前者缺守卫，后者原为共享状态）。
- 已知边界与代价：
  - 渲染端每个存活实例保留一份投影与交互分片，后台会话越多占用越高；释放路径落地（阶段 3）后随之回收。
  - 后台实例的批次仍要逐个应用与确认（`applyUpdates` + `ackRuntimeProjection`），多个会话并行流式时渲染端工作量随会话数线性增长。
  - 从未进入过前台的实例没有分片，它的后台事件只被忽略，首次切到前台时按现有路径取基准。
  - 投影以外的瞬态动作状态（提交、回退、模型切换）仍只有一份：这些动作只能由前台会话发起，且各自带 `runId` + `runtimeId` 守卫，迟到结果不会写入其他会话；切前台时重置并由状态收敛重新派生。

### 4.9 多会话线剩余边界已落地（`f6cc478`）

- **项目级请求携带项目令牌**：`SessionList` 与 `ProjectFileSearch` 新增 `projectPath`（主进程填实际读取/检索的项目）；`stores/session.ts` 的列表写入与 `stores/project-file.ts` 的检索结果都按它复核，前台项目已切换时旧结果不进入新项目的视图。
  - MCP 配置列举与 MCP 探测**未改**：`stores/resource.ts` 已按 `currentProjectId` 复核这两个结果，再叠一层 `projectPath` 只会是重复机制。
- **信任交互按来源会话绑定**：`TrustManager.decide` 的第三个参数由「当前项目」改为「允许本次决定的唯一项目」；`src/main/index.ts` 新增 `trustProjectOf(runId)`，`TRUST_STATUS_CHANNEL` 可接收 `{ runId }`、`TRUST_DECIDE_CHANNEL` 可接收 `runId`，两者都按该运行实例的归属项目解析；重载路径（`stores/session.ts`）传入前台实例身份，不再用前台项目代替被重载会话的授权范围。

- **未绑定实例在侧栏可见**：`stores/session-runs.ts` 新增 `unboundRuns`，侧栏为当前项目下 `sessionId === null` 的运行实例补一行「未命名会话」，点击转前台（复用空绑定实例，不会另建宿主）。
- **会话模型与全局默认解耦**：`RuntimeModelSelect.vue` 就绪时选中只切换当前会话模型（SDK 的会话切换本身不持久化全局默认），未启动时才写 Pi 默认模型；文案与 `title` 同步说明两种语义。
- **异常原文补齐**：`services/runtime.ts` 与 `services/extension-ui.ts` 的 `callFailed` 改为接收并保留 `error`，与其余服务层一致。
- 已知边界：
  - 释放只解除登记，不删除历史、不移除侧栏条目，也不重试退出前的任务；宿主仍存活时释放可能失败并保留占用（这是有意行为）。
  - 信任决定仍只能作用于「当前项目或已登记运行实例的归属项目」；已移除项目的记录不由页面改写。
  - 未绑定实例行只在当前项目下展示，其他项目的未命名实例仍不可见（属于跨项目视角，不在本批范围）。

### 4.10 阶段 3 已落地：空闲回收与按需恢复（`d7b1c60`）

- **回收入口**：`src/main/sdk-host-manager.ts` 新增 `suspend()`：关闭宿主进程但**保留管理器可重用**（不设 `shuttingDown`、保持 `wanted`），随后 `invalidateSession(true)` 清掉已失效的绑定代际；占用与会话身份保留在注册表里。不用 `shutdown()` 作为入口（它会永久阻止重启）。
- **空闲判定**：`isIdleForReclaim()` 只读宿主已推送的 `SdkSessionStatus` 与主进程在途标记（`sessionSubmission`/`uncertainOperationId`）。等待用户下一条消息算空闲；排队、独立 Bash、等待审批、生命周期操作、`needsHostRebuild` 都不算。不新增宿主协议请求。
- **宽限期**：`src/main/sdk-runtime-bridge.ts` 的 `RECLAIM_IDLE_MS = 5 分钟`（内部常量，不做成用户可见设置）。
- **计时重置**：显式需要宿主的动作（提交、中止、切换/重载、回退、切模型、MCP 命令、交互回应、能力/资源/诊断/MCP 状态读取、切前台）经 `keepAlive` 重置；状态查询与投影读取**不**重置，因此渲染不会延长宿主寿命。
- **互斥**：回收前复核空闲 → `beginClose` → `suspend()`；有在途提交时放弃并重新计时；关闭未确认时 `markUnconfirmed` 保留占用。`releaseRun` 与 `switchSession` 先 `awaitReclaim`，不与释放竞争。
- **挂起态契约**：`RuntimeStatus` 新增 `sessionId`（当前或最近绑定的会话）。宿主已释放但会话身份仍在时，映射层输出 `state: 'idle'` 且带 `sessionId`，页面按「上次 Runtime 已关闭」展示并**保留聊天区与模型清单**；会话视图键（`stores/runtime.ts` 的 `conversationKey`）在挂起与恢复之间保持稳定，消息组件不重建。
- **按需恢复**：`runNeedsRebind` 命中（宿主进程已释放或已失败、宿主侧要求重建）时，`switchSession` 不再只转前台，而是走原有重绑链路（`resetSessionHost` → 重建宿主 → 重新打开该会话）。渲染端在挂起态发送时先 `sessionStore.open(suspendedSessionId, false)`，再提交本次输入；提交目标与内容在发起时固定，不重放旧请求。
- **侧栏**：`SessionRunBadge` 新增 `suspended`，文案「已回收，发送时恢复」，与「已就绪」分开。
- 已知边界：
  - 宽限期 5 分钟是内部默认值，未经资源测量，需真机观察后再调。
  - 恢复会重新加载 SDK 资源并重连 MCP（设计文档 §6.4 已声明代价）；扩展仅存内存的状态不恢复。
  - 挂起态下能力/资源/MCP 读取会返回未绑定错误，页面按挂起态提示而不是报故障。
  - 关闭未确认时占用保留，用户需经侧栏「重试释放运行实例」收敛（§4.9）。

### 4.11 共享 Pi 配置写入与凭据协调已落地（`b7c2d56`）

- 新增 `src/main/file-lock.ts`：以原子创建 `<文件>.lock` 目录作为协作锁，锁路径与原子原语（`mkdir`）都与官方 SDK 使用的 `proper-lockfile` 一致，因此桌面写入与 SDK 自己加锁的配置（`auth.json`、`trust.json`、MCP OAuth 每服务器锁）互斥；陈旧锁按锁目录 mtime 清理，避免异常退出留下永久锁。
- `src/main/pi-settings-manager.ts` 与 `src/main/models-config-manager.ts`：读-改-写整体进入锁内，且**锁内重新读盘**，因此并发保存依次叠加而不是互相覆盖；`models.json` 的形状校验仍在取锁前完成（纯输入检查）。取锁超时归为内部错误并保留原文。
- `src/main/auth-manager.ts`：启动认证辅助进程前确保 `auth.json` 与父目录存在（只创建、不读取也不覆盖，文件已存在时直接返回），关闭 SDK 在取锁前初始化文件的竞争窗口；登录流程进行中拒绝退出登录，避免同一共享凭据收到冲突意图。
- 阶段 4 的状态可理解性收尾：挂起态在输入区状态行与空状态给出专门文案（「会话已回收以释放资源；发送会先恢复它」），不再复用「Runtime 正在关闭」。
- 已知边界：
  - SDK 写 `settings.json`、`models.json`、`mcp.json` 时不取锁，这三处仍只能靠文件标识比对发现外部改动，本锁不假装提供跨进程强互斥。

  - `auth.json` 的预创建只关闭「桌面自己触发」的初始化窗口；SDK 宿主进程与外部 Pi CLI 同时首次初始化仍可能竞争，要彻底消除需上游改动。

## 6. 阶段 1b 的生效决策（D1–D7）

- **D1 页面二维身份**：`runId` + `runtimeId`；`RuntimeStatus` 必带 `runId`，投影快照/批次与 Extension UI 快照由桥接层补 `runId`（因此这两个类型用可选字段，宿主协议载荷不带）。

- **D5 reload 目标**：前台实例的当前绑定会话；信任判定在 `session-manager` 内按绑定会话的归属项目复核。
- **D6 渲染端最小适配**：只做契约跟随与「只消费前台实例事件」，保持单前台展示。
- **D7 范围外**：信任 decide/status 的来源会话绑定、渲染端完整分片、草稿/阅读位置、侧栏运行状态展示、项目级请求令牌、扩展 UI 快照来源的完整分片、空闲回收、共享 Pi 配置与凭据协调设计。

## 9. 验证、构建与运行注意事项

- **构建产物**：`out/` 与 `release/` 已被 `.gitignore` 忽略，但目录存在，且可能是任意时刻的快照（当前这份已落后于工作区源码）。运行前必须重新构建：`npm run dev` 会先执行 `auth-helper:build` 与 `sdk-host:build`；单独构建 sdk-host 用 `npm run sdk-host:build`。宿主协议当前是**版本 3**（`src/sdk-host/protocol.ts` 与主进程校验一致）；现有 `out/` 快照是协议 v2，`out/` 下四个子目录都已过期，因此运行前必须整体重建。
- 类型检查：`npm run typecheck`（= `typecheck:node` + `typecheck:web`），当前 0 错误通过；构建：`npm run build`。**构建尚未执行**。执行前确认 Node 在 PATH 中。
- 仓库**没有自动化测试**（`package.json` 无 test script），验证依赖类型检查与真机手动验证。
- 真机手动验证方向（需单独授权）：同一项目两会话并行、跨项目并行、切换前台不中断后台、回到已运行会话直接复用、项目移除收敛、应用退出收敛；切到后台会话时消息与扩展对话是否直接取回分片；后台会话等待回应时侧栏提示是否准确。
- 开发态两个已知坑（见 `.agents/memory/topics/gotchas/`）：`dev-server-header-cache`、`dev-main-process-restart`。
- 开发在 Windows 与 macOS 主机之间交替进行（本次接手为 Windows x64）；命令与路径按实际终端适配，文档与命令示例保持平台中立。
- 真机 GUI 验证与进程清理见 `topics/gotchas/gui-verification.md`。
