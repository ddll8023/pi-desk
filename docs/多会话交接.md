# 同时多对话任务交接文档

## 0. 用途与阅读方式

本文档用于把「同一窗口多会话并行」任务交接给下一位开发者。它记录**当前事实、已完成工作、剩余工作与必须遵守的边界**，不构成任何实施授权。

必读配套：

- `docs/多会话设计.md`：需求与架构基线（持续维护，当前已同步到阶段 1a）。
- `.agents/memory/INDEX.md` 及 `topics/conventions/`：桌面配置单写者、渲染端桥接调用、平台中立等硬约定。
- `package.json` 的 scripts：构建与类型检查入口。

接手后仍按仓库规则执行：先只读收窄 → 给出方案与推荐 → 提交**逐文件执行清单** → 用户明确审核同意后才修改；构建、类型检查、运行、测试均需**单独授权**。

## 1. 任务目标（已确认，不要重复讨论）

- 同一窗口支持多个会话同时执行，允许跨项目并行。
- 用侧栏会话列表管理和切换，不新增标签栏；一个前台会话，后台继续执行。
- 前台会话所属项目决定当前项目上下文，项目资源展示与文件索引随前台切换。
- 生命周期：**会话保留 → 宿主空闲延迟自动回收 → 再次发送自动恢复**（替代早前「全部打开即常驻」）。
- 回收语义：不删除历史、不归档、不移除侧栏条目、不切换前台；保留消息、草稿、图片与滚动位置；再次发送只提交本次新内容，不重放旧请求。
- 仅查看历史不应强制建立完整 Agent 执行环境。
- 不做：多窗口、分屏、批量操作（侧栏多选）、worktree、进程池、固定会话数上限、资源监控面板、自动恢复退出前的全部任务、草稿与图片的跨应用重启持久化。

## 2. 技术栈与不可违背的技术边界

- 技术栈：Electron 44 + Vue 3 + TypeScript + Pinia + Pi SDK `@earendil-works/pi-coding-agent` 1.0.4（Version 以 `package.json` 为准）。渲染端为 Vue 3 **JavaScript**（`vue-spec`），主进程/宿主为 TypeScript。
- `DesktopConfigStore` 保持主进程单写者；多个会话宿主不得各自写 Desktop 配置（项目列表、偏好、窗口）。
- 渲染端跨 `contextBridge` 载荷必须由 `src/renderer/src/services/` 显式重建为普通对象，不传 Vue 响应式对象。
- 桥接失败必须保留原始异常文本（新增 IPC 通道走 `src/main/index.ts` 的 `handle()` 包装）。
- 授权绑定会话归属项目，不依赖可变的前台项目。
- 同一持久化会话在应用内只能由一个运行实例接管；占用覆盖打开中与退出未确认状态。
- SDK 内部编号不得当作跨运行实例的全局身份。
- 自动回收不能用 `src/sdk-host/session-runtime.ts` 的 `shutdown()` 作无条件入口：需要宿主侧复核空闲并与新提交互斥；未确认旧宿主退出前不建立替代宿主。
- 等待审批、扩展输入、排队、工具执行、生命周期操作**不属于**空闲；普通等待用户下一条消息属于空闲。
- 共享 Pi 配置写入与凭据首次初始化的协调，应在引入并发写入之前完成设计。
- 进程隔离不等于文件隔离或安全沙箱；不要编造内存、启动耗时或连接数量。

## 6. 阶段 1b（多运行实例）设计定案与剩余逐文件清单

### 6.1 设计决策（已评审确认）

- **D1 页面二维身份**：`runId`（运行实例）+ `runtimeId`（绑定代际）。`RuntimeStatus` 必须携带 `runId`；投影快照/批次与 Extension UI 快照由桥接层补 `runId`（因此这两个类型用可选字段，避免改动宿主协议校验）。
- **D2 事件路由**：桥接层按运行实例订阅（创建时挂接一次），**只有前台实例**的状态、投影批次与 Extension UI 快照进入页面；后台实例的事件在 1b 直接丢弃（完整分片留给 1c）。`sameStatus` 比较需加入 `runId`。
- **D3 每会话宿主 + 复用策略**：命名会话若已被某实例占用 → **转前台复用，不重绑**；未被占用 → 优先复用「空绑定实例」（前台运行实例且同项目且 `sessionId === null`；或已释放的 `idle` 实例），否则新建宿主。**「新建会话」点击不重复驻留宿主**。
- **D4 前台/项目切换不收敛宿主**：`project-manager.applySwitch` 删除 stop 收敛与流式拦截（后台会话随前台切换继续运行）。释放入口只保留：项目移除（按项目收敛全部实例）、应用退出，以及后续阶段的空闲回收。
- **D5 reload 目标**：前台运行实例的当前绑定会话；信任判定迁入 `session-manager` 并按**绑定会话的归属项目**复核（页面发起的打开仍按前台项目拦截，不变）。
- **D6 渲染端最小适配**：只让契约跟随与「只消费前台实例事件」，保持单前台展示；完整状态分片、侧栏与输入体验在 1c。
- **D7 范围外**：信任 decide/status 绑定来源会话、渲染端完整分片、草稿/阅读位置、侧栏运行状态展示、项目级请求令牌、扩展 UI 快照来源的完整分片、空闲回收、共享 Pi 配置与凭据协调设计。

## 9. 验证、构建与运行注意事项

- **必须重建 sdk-host 才能运行应用**：`out/sdk-host/index.mjs` 仍是协议 v2 旧产物，而 `src/sdk-host/protocol.ts` 已是 v3、主进程按 v3 校验；不重建会导致会话打开失败。命令：`npm run sdk-host:build`（需授权）。
- 类型检查：`npm run typecheck`（= `typecheck:node` + `typecheck:web`）；构建：`npm run build`；开发：`npm run dev`（会自动先构建 auth-helper 与 sdk-host）。**本轮与上一轮均未执行过其中任何一项**。
- 仓库**没有自动化测试**（`package.json` 无 test script），验证依赖类型检查与真机手动验证。
- 开发态两个已知坑（见 `.agents/memory/topics/gotchas/`）：
  - `dev-server-header-cache`：只改 dev server 响应头时 ETag 不变、Vite 回 304 导致旧头沿用。
  - `dev-main-process-restart`：判断主进程改动是否生效、重启 dev 进程的做法。
- 本机为 Windows；命令与路径按实际终端适配，文档与命令示例保持平台中立。
- 真机 GUI 验证与进程清理见 `topics/gotchas/gui-verification.md`。
