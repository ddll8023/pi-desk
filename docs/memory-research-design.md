# 记忆系统调研与方案设计

## 1. 文档定位

本文整理记忆系统的当前实现事实、外部借鉴线索与候选优化方向。

现有实现提供全局词法索引、统一检索与定向读取工具、默认主动读取统计、随包产品资源与受管运行环境及桌面工具语义展示。实现描述以 `resources/agent/` 下的扩展与配套 Skill、文件引擎为准，运行实例的能力取决于已加载的产品资源版本。**本文关于后续阶段（如请求前按任务自动召回）的内容仍属方案设计，不构成开发或执行授权。实施前须明确需求边界并取得逐文件执行清单批准。**

第三方能力和历史实现仅作为事实与参考，不自动成为必须保留或新增的需求。

## 2. 问题与目标方向

讨论围绕以下问题展开：

- 如何让相关记忆在运行过程中主动进入上下文，而不是完全依赖模型记得搜索？
- 是否需要新增工具、MCP 服务，或者引入 OpenViking 一类系统？
- DSH 接入网站和 QQ 后，记忆究竟由消息渠道、宿主程序还是模型调用？
- 如何在提高召回可用性的同时，控制无关内容、历史误用和写入权限？

候选目标是：在模型处理任务前提供必要背景和相关记忆，保留深入读取能力，并让来源、适用范围与失败状态可解释。不以“调用过工具”代表模型理解或遵守，也不承诺检索必然命中。

## 3. 当前实现事实

### 3.1 组件与所有权

当前记忆能力由以下组件协作：

| 组件 | 当前职责 |
| --- | --- |
| Memory Skill | 统一管理工作日记、月度总结与画像，规范查询、整理与两阶段保存流程 |
| 用户级 `pi-memory` 扩展 | 请求级背景注入、记忆工具注册、主动读取统计触发、会话控制与保存审批通道 |
| Python 文件引擎 | 用户级数据读写、两阶段保存计划与事务、全局派生索引及词法排序，独立访问统计的去重、持久化与查询 |
| `pi-skill-setup` | 独立 CLI 的成套部署与跨机配置对齐，保持 Skill、扩展与引擎版本一致 |
| pi-desk 桌面端 | SDK 宿主、截断前工具语义摘要提取、实时/历史投影与结果优先卡片展示 |

扩展与配套资源的唯一维护源位于仓库 `resources/agent/`，构建时原样暂存到 `out/sdk-host/agent-resources/` 并附内容指纹，由 pi-desk 宿主显式装配，不要求在每个业务项目中安装。用户 agentDir 下同名的旧部署副本只在入口与全部组成文件内容一致时于执行前排除；带本地配置的副本不自动排除，未知同名内容按冲突处理。

pi-desk 通过 `src/main/shared/pi-paths.ts` 解析 agentDir，并在 `src/sdk-host/session-runtime.ts` 创建 SDK 会话服务；桌面端提供工具摘要投影与卡片展示，扩展本身作为随包产品资源在宿主内部装配。

### 3.2 数据边界

| 数据 | 存储位置 | 用途 |
| --- | --- | --- |
| 工作日记 | `~/.agents/memory-store/daily/` | 按日期记录事件、进展、决定和约束，所有项目共用 |
| 个人画像 | `~/.agents/memory-store/profile/` | 按领域与作用域保存偏好 |
| 月度总结 | `~/.agents/memory-store/monthly/` | 关联日记来源的历史回顾 |
| 派生索引 | `~/.agents/memory-store/index/` | 记录定位、当前有效规则、月份及全局词法检索（`search.json`） |
| 项目本地知识 | `<项目根>/.agents/memory/` | 历史可选域，记录项目约定与棘手问题；不由本能力自动读取或维护 |
| 主动读取统计 | 文件引擎 `ACCESS_STORE` 指定的独立技术文件 | 保存计数、采集起点、最近读取时间及必要的哈希去重身份，不保存正文或查询词 |

用户库通过 Markdown 正文与派生索引组织数据，不要求项目表或项目登记。旧项目表仅作为已有索引的历史来源参与指纹核对，不是新库的组成或读取、保存的前置条件。项目本地知识不由本能力读取或维护，也不作为全局日记查询的前置。访问统计不是权威记忆或派生检索索引，不参与正文与保存计划的内容指纹，也不能从记忆正文或历史会话自动重建。

### 3.3 自动读取与工具

当前扩展在 `context` 钩子中为每次模型请求提供独立背景消息，内容主要是适用画像和项目索引：

- 不覆盖系统提示词，不改写用户输入。
- 自动召回正文不追加到持久会话历史；显式工具结果仍按宿主工具消息机制处理。
- 画像使用内存缓存，来源变化时刷新；项目索引按请求读取。
- **自动背景已接入按任务自动检索日记与规则**：请求前自动提炼任务查询并调用 `recall-background` 协议，提供相关有效规则与日记，优先复用完整条目；模型仍可在存在缺口时主动调用工具深入检索或读取原文。

当前工具能力包括：

- `memory_search`：默认按任务检索全局已保存日记，支持中文词法相关度排序、近期／月摘要模式与分页。
- `memory_rules`：查询全局当前有效决定与约束，支持词法匹配，不受近期窗口限制。
- `memory_read`：按记录 ID 从索引定向读取完整原文，核对来源并保留历史状态与适用条件，不要求目录绑定；成功准备完整结果后默认提交独立访问统计，不是纯只读。
- `memory_access_stats`：按真实记录 ID 只读查询主动定向读取次数、去重会话数和最近读取时间，查询本身不产生计数。
- `memory_status`：读取全局库状态，并报告独立访问统计状态，不创建统计文件或修复数据。
- `memory_control`：记录当前分支的停用、恢复或刷新，不保存记忆正文或用户批准。
- `memory_profiles`：按领域与作用域读取画像。
- `memory_save`、`memory_profile_save`：分别提交日记、画像候选，经完整计划展示与真实用户批准后保存。

### 3.4 当前检索与保存的边界

引擎检索基于 `index/search.json` 派生索引，采用中文双字词元与英文词元的 BM25 词法相关度，支持跨词匹配与词项命中解释。记录定位采用索引定向读取来源文件并核对指纹，单条读取不再遍历全历史日记。

检索默认面向全局全部日记，项目、模式与月份仅作显式过滤，未限定时不按目录强行绑定。索引覆盖日记与月摘要，来源清单或内容指纹不符时如实报错，不伪装为无命中，也不在查询中自动全历史扫描或隐式修复索引。

主动定向读取统计默认自动采集，无需用户配置。扩展在完整结果准备好并检查操作状态后提交统计，按宿主会话与调用身份持久去重；底层 CLI `read`、搜索、规则、自动背景及历史回放不计数。统计只覆盖采集后的事件，不代表全部访问、模型实际接收或使用、记忆有用性或事实正确，也不参与排序。

首次统计仅在已有可用库中创建独立技术文件，不初始化库或补建锁文件。统计非阻塞取锁，失败时保留成功原文并报告结果未确认，不自动重试、补计或修复；已启动的统计写入不因取消或状态变化而撤销。明确删除记录时预览并在同一事务中清理对应统计，规则替代不转移旧记录计数。

保存通道先生成短期计划，完整展示新旧正文、来源、历史来源标签和替代／撤回影响，再等待真实用户批准。提交前复核会话、分支、计划及来源状态。日记保存不顺带维护画像，画像维护也不借用日记写入授权。

`/memory off`、`on`、`refresh` 管理启停和旧操作状态；停用阻止新的主动读取与统计，刷新不清空计数、不重载配置与代码，停用也不能清除已经进入模型上下文的内容。缺库、读取失败和待恢复事务不自动触发初始化或修复。

## 4. 外部调研线索

本节只记录与本次问题直接相关的机制，不作产品总体排名，不据插件数量判断普及程度，也不把第三方说明中的效果描述当成本项目已取得的收益。

### 4.1 DSH：消息渠道与记忆触发分离

DSH 官方将 `agent/pre-step` 定义为模型请求推导前的钩子，插件可以替换进入本步的消息。

已读 `tencent-connect/dsh-qqbot` 的会话管理与入站源码：插件按私聊用户或群定位 Agent，再调用 `agent.followup(message)`。QQ 是消息入口，不负责决定是否搜索记忆。网站接入同样需要将消息送入承载记忆插件的宿主执行链；不能据此推断任意网站都天然支持记忆。

会话隔离不等于记忆隔离。即使每个用户或群拥有独立 Agent，用户级或项目级记忆是否共享，仍取决于记忆系统自己的作用域与访问控制。

### 4.2 Culeot/dsh-agent-memory：自动检索与模型工具并存

已读 `src/index.ts` 的实现：

- 在 `agent/pre-step` 中根据用户消息形成查询，直接调用内部召回逻辑。
- 对结果进行相关度筛选、数量控制和重复抑制，再加入本步输入。
- 自动召回采用不更新访问状态的读取方式。
- 同时注册主动检索、保存与目录浏览工具，并提供记忆使用提示。

可借鉴的是“程序主动提供相关摘要，模型按需深入读取”的分工。工具使用提示仍依赖模型选择，不能当成程序强制调用。无相关命中或检索失败时，该实现可以不注入记忆，也不是保证每步都有结果。

### 4.3 zhbcher/dsh-memory：自动召回之外还有自动沉淀

已读 `lib/index.js` 的实现：

- 在请求前组合用户级与项目级记忆，按相关性和预算选择内容，并抑制重复注入。
- 在空闲、会话释放和压缩摘要等生命周期事件上，满足条件后调用模型提炼记忆操作。
- 自动提炼受开关控制，并与存储更新、来源记录和去重协作。

自动沉淀是独立的写入策略，不是 QQ 接入自动附带的功能。它增加模型调用、错误知识沉淀和维护责任，与当前明确批准后写入的边界不同，不宜仅因外部插件支持就照搬。

### 4.4 OpenViking：检索能力、自动接入与 MCP 分层

本次将“Viking”按 OpenViking 理解。依据其官方 MCP 文档与 OpenCode 插件说明：

- 服务提供检索、读取和记忆相关能力，并通过 MCP 暴露工具。
- 官方集成同时使用生命周期钩子，自动召回相关记忆并提供上下文。
- 模型仍可通过 MCP 工具主动查找和读取详情。
- 部分集成还捕获会话并在生命周期边界提交记忆提炼；这是另外的数据收集与写入行为。

这支持“检索核心、自动召回入口、模型工具入口分离”的方向，而不是证明必须采用完整 OpenViking。

本轮对 OpenViking 的上述结论主要来自官方文档和集成说明，未完成其服务端检索实现、运行成本和权限边界的深入审查。若考虑实际引入，必须重新调研，不能据此直接决定替换当前存储或部署服务。

### 4.5 可采纳方向与不照搬部分

| 参考 | 可采纳方向 | 需适配的边界 |
| --- | --- | --- |
| DSH 请求前钩子 | 把自动召回放在宿主生命周期中 | Pi 使用自己的 `context` 钩子；每请求重新构建，不按结果 ID 跳过单次注入 |
| dsh-agent-memory | 自动摘要与模型工具共用检索能力 | 已作为统一检索核心采纳；保留请求级背景，被动读取不写回访问统计 |
| dsh-memory | 相关度、来源与预算协作 | 跨项目检索不等于规则跨项目生效；自动提炼和会话挖掘不纳入推荐范围 |
| OpenViking 集成 | 上下文装配与模型工具解耦 | 全局任务检索已采纳；不引入独立向量服务、会话捕获或跨工作区无界召回 |

这些是机制借鉴与适配边界。外部插件报告的效果数字不代表本项目已取得同等收益。

## 5. 候选方案：统一检索核心与请求前自动召回

### 5.1 推荐方向与当前分工

优先在现有架构内演进：文件引擎提供统一的词法检索、规则投影与定向读取；扩展工具与桌面展示已完成接入；下一阶段重点将统一检索核心引入请求级自动召回钩子。暂不以建设独立 MCP 服务或替换存储引擎为起点。

职责分工：

- **固定必要背景**：适用画像、项目索引中的通用硬约束（当前已在 `context` 注入）。
- **任务相关自动召回（已接入）**：每次请求根据当前任务问题，复用引擎检索核心召回相关有效决定与必要日记，结合会话内条件缓存与来源指纹校验，无命中时保持静默。
- **模型深入读取**：完整原文、特定主题、历史经过与摘要来源，使用同一套工具协议深入读取。
- **权威存储与保存流程**：继续提供权威 Markdown 正文、派生索引和两阶段审批保存，不因自动读取开放自动写入。

### 5.2 查询与作用域

自动召回应从真实用户问题提炼任务查询，排除自动背景、旧召回消息及工具输出，避免记忆反复检索自身。工具续步没有新用户问题时，可复用仍有效的任务查询；话题切换后更新。

作用域原则：

- 用户级记忆统一存储于全局库，默认面向全部日记检索相关候选。
- 项目、目录和分支是相关度与适用范围线索，不是存储位置或默认硬过滤边界。
- 用户显式限定项目或时间时按条件过滤；未绑定项目不阻断默认全局检索。
- 项目专属决定可以作为参考召回，但不自动提升为其他项目的通用规则。
- 项目本地知识保持为独立可选域，不与用户级库合并，也不作为全局查询前置。

当前没有足够依据将 QQ 或其他多用户入口纳入本轮开发范围。

### 5.3 相关度、有效性与无匹配静默

词法相关度基于中文双字片段与英文词元（BM25），已在引擎层统一实现；自动召回与模型工具共用该核心。

内容性质区分：

- 当前有效决定不受近期窗口限制，保留稳定规则键与适用条件。
- 历史日记保留发生日期与生命周期状态，被替代条目不冒充现行决定。
- 月度摘要是定位历史的线索，必要时回溯日记来源，不替代原文。
- 检索相关度与正文存在不等于事实已核实。
- **无匹配静默**：相关度未达到阈值时不硬凑无关记忆，宁可不注入也不带偏模型判断。

### 5.4 上下文预算、缓存与可观察性

自动召回与固定背景统一控制上下文占用，去除重复内容，优先保留适用条件、来源项目、日期和有效状态。无关内容不为凑数量进入上下文。

长内容提供明确标注的摘要或原文定位，不截断必要条件后冒充完整约束。必要背景因预算未能完整提供时明确说明缺口。

缓存保持为请求或会话级内存派生结果，问题、项目、分支或来源变化时失效。读取失败如实报告，不使用旧结果；缓存不落盘，被动自动背景不记录访问日志。主动定向读取的持久技术统计与缓存分离，遵循前述独立采集边界，不因缓存刷新而清空。

可观察性：桌面端已实现工具语义摘要与卡片展示，清楚表达操作身份、查询、实际范围、计数口径与来源；自动召回接入后同样需要最小可观察表达，区分无命中、读取失败和预算省略。

## 6. 工具与 MCP 的取舍

三者解决的问题不同：

| 层次 | 解决的问题 |
| --- | --- |
| 检索核心 | 哪些内容相关、有效、可访问，以及如何返回来源 |
| 自动钩子 | 何时在不等待模型选择工具的情况下提供记忆 |
| 原生工具或 MCP | 哪些客户端可以主动调用这项能力 |

当前 Pi CLI 与 pi-desk 已共享扩展，已有原生工具入口。候选默认方向是先改善共享检索能力，不额外启动 MCP 服务。

若以后确认 Claude Code、Codex 或其他独立客户端需要访问同一记忆系统，再考虑薄 MCP 适配层，复用同一检索核心和权威存储。跨客户端需求也不意味着 MCP 是唯一接入方式，仍需结合实际客户端能力重新选择。

MCP 不保证模型主动调用，也不自动提高搜索质量。若未来开放写入，必须独立解决真实用户审批与身份授权，不能把现有插件通道的确认能力当作所有客户端天然具备。

## 7. 已实现事实与下一阶段候选范围

### 7.1 已落实事实

- 统一词法检索核心：引擎实现全局 bigram + BM25 词法检索（`recall`）、有效规则查询与按 ID 定向读取。
- 全局检索派生索引：`index/search.json` 覆盖日记与月摘要，来源指纹核对，事务同步发布。
- 工具协议对齐：扩展工具支持默认全局日记检索、分页与状态保留。
- 默认主动读取统计：定向原文读取自动提交独立技术统计，提供只读查询、持久去重、故障隔离与删除联动，不改变检索排序或权威内容审批。
- 随包产品资源与受管运行环境：构建阶段暂存扩展、Skill 与引擎并生成内容指纹，同时暂存当前平台的 CPython 3.12 与 IANA 时区数据；归档来源与 SHA-256 在清单中固定。
- 桌面结果展示：截断前提取语义摘要，工具卡提供操作分类、查询、范围、计数口径与来源展示。
- 请求级任务自动召回：扩展在 `context` 钩子中按任务自动调用引擎只读 `recall-background` 协议；实现续接语境保留、条件内存缓存、来源指纹校验、预算控制与区分展示（有效决定 vs 历史参考），被替代规则不自动注入，无命中保持静默。自动背景不计入主动读取统计。
- 检索返回策略截断（P0）：`indexed_recall` 与 `active_rules` 默认将 `content` 截断为前 200 字摘要并附带 `content_truncated: true`，恢复 `memory_read` 二次定向读取漏斗与主动读取统计可观察性。
- 报错指纹与避坑经验联动（P1）：工具执行报错时自动提取稳定特征串，通过 `error-recall` 优先匹配项目本地 `topics/gotchas/` 或全局日记 `issue` 记录，阻断同类环境与命令错误反复踩坑。
- 自动召回静默判据优化（P2）：在通过初步词法筛选（`eligible > 0`）但未达到自动注入条件或预算省略时，提供明确弱提示与建议查询词，降低完全静默导致模型无法感知记忆的概率。
- 主题型场景卡片聚合（P3）：命中同一 `rule_key` 的规则替代链时，在扩展背景装配层通过 `AggregatedCard` 提供现行版本与历史演进摘要，降低阅读碎片日记的理解成本。

### 7.2 下一阶段候选范围

在已接通请求级自动召回、报错指纹联动与主题聚合卡片的基础上，结合外部成熟实践，整理后续两项候选方向：

1. **长任务超长工具过程日志外部卸载（Context Offloading & Symbolic Graph）**：
   - **机制**：对超大命令输出、构建或测试日志自动卸载落盘至会话临时目录（如 `refs/*.md`），上下文仅保留状态拓扑图、退出码与首尾错误摘要及文件指针，由模型按需通过节点 ID 精确定向查看。
   - **收益**：解决长上下文恶化与机械截断无法回溯的痛点，显著节约 Token 消耗。
   - **不做项**：临时文件生命周期与会话绑定，会话结束后清理，不进入长期记忆存储。

2. **静态代码拓扑与影响分析（CodeGraph Impact Analysis）**：
   - **机制**：基于轻量静态解析（AST/符号索引）提供符号级别的调用方（Callers）与被调用方（Callees）查询工具，在修改业务代码前静态提供受影响调用链。
   - **收益**：减少盲目全局正则 `ffgrep` 尝试与调用链遗漏。
   - **不做项**：不引入重型外部图数据库服务，保持本地轻量化。

暂不建议纳入：

- 替换权威存储或在 pi-desk 中建立第二套记忆库。
- 引入独立向量数据库服务或自建模型嵌入管线。
- 自动保存日记、提炼画像、捕获完整会话或自动生成月总结。
- 新增 QQ、网站或其他客户端入口。
- 强制模型调用工具的门禁。
- 自动初始化、自动修复索引或恢复事务。

## 8. 取舍与待定项

### 8.1 主要取舍

- 自动召回减少对模型主动检索的依赖，但增加每次请求的检索与上下文开销；需要严格的无匹配静默和预算控制。
- 轻量词法检索保持标准库零依赖和确定性，但在隐含语义或跨语言问题上弱于语义向量；现阶段优先保持部署简单与可解释。
- 保持人工审批写入限制错误知识自动沉淀，但也意味着没有用户明确触发就不会自动产生新的权威记忆。
- 统一全局存储便于跨项目借鉴，但需要显式保留项目归属与适用条件，避免其他项目的特定方案被误当全局硬约束。

### 8.2 优先级与后续讨论

记忆系统效用不足的 P0-P3 改进（检索截断、报错指纹、弱提示、主题聚合）现已全部落实。后续候选优化按代价与收益排定：

1. **优先级 1：长任务超长工具日志外部卸载**（中成本）：解决会话执行期 Token 膨胀与超长输出截断无法恢复问题，独立于长期记忆体系。
2. **优先级 2：静态代码拓扑与影响分析**（中高成本）：需设计仓库静态符号提取机制，独立于记忆系统本身，作为代码审查与分析辅助。

本文没有将这些事项作为已确定的实现细节。
