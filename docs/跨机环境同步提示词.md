# 跨机环境同步与验证指令

本项目（pi-desk）已完成门禁（skill-guard）与记忆系统（pi-memory）的项目级绑定与自包含改造。请协助完成本地环境的拉取、旧扩展清理与自适应寻址验证：

1. **拉取最新代码**：
   - 检查当前 Git 工作区状态，执行 `git pull` 拉取最新代码，确认根目录 `AGENTS.md`、`.pi/memory.json`、`.pi/extensions/` 及 `.pi/skills/memory/` 均已就位。

2. **清理全局旧扩展与同名技能（关键步骤，遗漏会导致会话无法建立）**：
   - 检查全局用户扩展目录：
     - Windows 路径：`%USERPROFILE%\.pi\agent\extensions\`
     - macOS/Linux 路径：`~/.pi/agent/extensions/`
   - 若存在 `pi-memory` 或 `skill-guard` 目录，必须删除或**移出该目录**（如移到 `~/.pi/agent/extensions-disabled/`）；仅在 `extensions/` 内改名或加后缀无效，仍会被自动加载。
   - 再检查全局技能目录 `~/.pi/agent/skills/`，若存在名为 `memory` 的旧技能（通常位于 `memory-skill/memory/`），一并删除或移出；它与项目内 `.pi/skills/memory` 同名，用户级优先会使项目内新版技能不生效。
   - 原因：SDK 会同时加载用户级与项目级扩展，两处同名扩展重复注册同名工具，冲突被记为扩展错误，pi-desk 直接拒绝建立会话，界面提示「SDK 会话或必要交互绑定失败」「SDK 上下文不可继续复用，需要显式恢复基础设施」；此时点击「重新打开」不会恢复，须先清理并重启应用。

3. **验证环境与引擎可用性**：
   - 检查系统 Python 3.10+ 是否可用（系统 PATH 或项目 `.venv`）；
   - 执行 `python3 .pi/skills/memory/scripts/memory_store.py status`（Windows 执行对应 python 命令），验证自包含记忆引擎状态正常。

4. **验证项目级扩展加载**：
   - 确保当前项目已设为信任（Trust Project）；
   - 执行 `/memory status` 检查：
     1. 引擎路径 `engine` 是否自动定位到本项目的 `.pi/skills/memory/scripts/memory_store.py`；
     2. 项目身份 `projectId` 是否自动识别为 `pi-desktop`。
   - 确认全局 `extensions/` 下已无 `pi-memory`、`skill-guard`，全局 `skills/` 下已无同名 `memory` 技能，再重启应用并新开会话，确认可正常连接。

5. **汇报结果**：
   - 简短汇报同步和清理的完成情况，确认是否可正常开展后续开发。
