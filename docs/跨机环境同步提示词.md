# 跨机环境同步说明

## 产品资源与用户级全局记忆

门禁、记忆扩展和配套 Memory Skill 的唯一维护源位于 `resources/agent/`，由 pi-desk 宿主装配，不要求在每个业务项目中安装。

- `resources/agent/bundle.json`：产品扩展、Skill、引擎入口及组成文件声明。
- `resources/agent/extensions/skill-guard/`：技能选择与加载证据门禁。
- `resources/agent/extensions/pi-memory/`：请求级记忆背景、记忆工具与保存审批通道。
- `resources/agent/skills/memory/`：配套规范、引用和文件引擎。

记忆不绑定当前项目，不读取 `.pi/memory.json`，不要求登记项目。所有工作目录共用当前用户的 `~/.agents/memory-store/`；项目名称只可作为内容或历史来源，不决定存储和过滤。

同步源码不会复制全局库中的日记或画像，也不会复制用户认证、模型和 MCP 配置。

## 构建与分发边界

`sdk-host:build` 先构建宿主，再依次暂存产品 Agent 资源与当前平台的受管记忆运行环境。受管 Python 与时区归档先由 `npm run memory-runtime:prepare` 显式准备并缓存到工作区 `runtime/`；构建只复制当前主机的一份，不自动下载。

发行包内运行环境与宿主同属 `out/sdk-host/`，随 `out/**` 一并进包，不另写到 `resources/`。macOS 签名排除其中的二进制时区数据。

扩展不合并转译，保留模块相对路径和门禁加载指纹语义。主进程根据实际宿主入口传入产品资源目录与记忆配置；会话创建时核对资源清单并装配能力，不依赖业务 cwd，不把源码目录作为缺失构建产物的回退。

本说明不授权拉取代码、构建、打包、测试、启动或重载；各项操作仍按用户明确批准的范围执行。文件同步和磁盘修改不表示当前运行会话已经加载新实现。

## 同步到新主机后的操作

新主机不需要手工安装或准备任何一项：直接运行入口脚本即可，缺少的前置资源由脚本自行补齐。

| 入口 | 命令 | 行为 |
| --- | --- | --- |
| 开发启动 | `scripts/start-dev.cmd`（Windows）、`scripts/start-dev.sh`（macOS） | 补齐前置资源后进入开发模式 |
| 出包 | `scripts/package-win.cmd`、`scripts/package-mac.sh` | 补齐前置资源后构建并产出便携包 |
| 等价命令 | `npm run dev` / `npm run build` / `npm run start` / `npm run package:*` | 同样先执行环境预检 |

预检由 `scripts/ensure-environment.mjs` 执行，只处理三类可自动获取的资源，全部就绪时只做存在性检查后立即返回：

1. npm 依赖：`node_modules` 缺失时执行 `npm install`。
2. Electron 二进制：包存在但 `dist` 缺失时调用其自带的安装脚本。
3. 受管记忆运行环境：按 `resources/memory-runtime/manifest.json` 的固定身份检查当前平台那一份，缺失时执行与 `npm run memory-runtime:prepare` 相同的一次性准备。归档缓存在工作区 `runtime/`，该目录不纳入版本控制；准备过程校验固定 SHA-256，不执行下载的解释器，也不使用 pip 或系统安装器。

首跑需要网络：Electron 约 120 MB，当前平台 Python 与时区数据约 25 MB；未显式设置镜像时使用与其他脚本一致的默认镜像。预检失败时明确报出缺口并非零退出，不继续启动或出包，也不回退系统 Python、源码目录或旧产物。

Node.js 与 npm 本身无法由脚本安装，只做检测并提示。受管运行环境只准备当前主机的平台；macOS 的 Python 归档含符号链接，必须在 macOS 主机上准备、出包与签名。

不随 Git 同步、也不需要迁移或重建的内容包括：用户级全局库 `~/.agents/memory-store/`、用户认证与模型／MCP 配置、`out/` 与 `release/`。用户环境与重复来源的规则见上一节，不在此重复。

这些入口是主机侧的前置条件与顺序，不构成在任何主机上执行的授权。

## 用户环境与重复来源

不以删除或移动用户全局扩展、技能作为使用桌面的前置条件，也不改写用户已有 Pi 配置。

桌面使用同一份信任设置解析候选来源，仅在入口与完整组成文件内容都匹配时，在扩展执行前排除同源部署副本。带本地配置的副本不自动排除。无法确认同源的同名扩展按冲突处理，拒绝建立会话，不静默覆盖，不以目录名称作为身份依据；内容不一致的同名 Memory Skill 不采用用户副本，改用产品版本并在宿主日志留一条诊断。

普通用户扩展、技能、模板和上下文仍沿用 SDK 的发现规则及项目信任边界。全局记忆不自动读取项目元数据和项目知识，也不把项目身份作为检索或保存条件。全局可检索不等于内容普遍适用，历史来源和适用条件必须保留。

独立 Pi CLI 继续使用其自身的部署与配置；桌面产品资源装配不等于 CLI 配套部署，也不要求为桌面清理 CLI 环境。

## 当前能力范围

产品资源装配、全局记忆协议与受管运行环境已具备；用户数据仍留在用户级全局库：

- 桌面使用随包 Python 3.12 与 IANA 时区数据，不使用系统 Python，也不依赖项目虚拟环境；资源缺失时明确报告。
- 全局记忆默认开启，可在设置页关闭；首次创建需用户确认，已有库不覆盖、不迁移。
- 不自动重建索引或恢复事务；读取错误与缺库分别报告。
- 新记录和月摘要不要求项目表；旧条目来源标签继续可读，不自动升级为通用约束或改写用户文件。
- 新保存计划使用全局协议版本 3；旧项目语义计划不能沿用批准提交，须重新生成和确认。
