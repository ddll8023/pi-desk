# Agent 指令分层与归属

修改任何 AGENTS 文件或产品内置提示前，必须先按本文判定归属；pi-desk 专有规则不得写入全局文件。

## 四层载体

| 层级 | 路径 | 加载条件 | 用途 |
| --- | --- | --- | --- |
| 全局用户级 | `~/.agents/AGENTS.md` | 所有宿主会话共用；pi-desk 会话以只读方式注入同一份文件 | 跨项目用户偏好：沟通风格、权限边界、判断原则、环境适配 |
| 工作区项目 | `<cwd>/AGENTS.md` | 当前工作目录是该项目时 | 该项目的技术栈、开发约定、验证命令 |
| pi-desk 开发仓库 | `<pi-desk>/AGENTS.md` | 当前工作目录是 pi-desk 仓库时 | pi-desk 开发期约定（如跨平台兼容、Python 环境选择） |
| 打包产物内置 | 代码分段 + `out/sdk-host/agent-resources/` | pi-desk 应用启动时注入 | 产品行为：执行模式、需求理解、延续判定、记忆/委派时机、Skill 裁剪 |

## 产品内置规则的真实载体

pi-desk 产品行为只能存在于以下位置，**禁止写入全局 AGENTS.md**：

| 内容 | 实现位置 |
| --- | --- |
| 执行模式定义 | `src/shared/preferences-api.ts` 契约、`src/main/config/desktop-config-store.ts` 持久化 |
| 标准/快速模式分段 | `src/sdk-host/session-runtime.ts` 常量 `STANDARD_MODE_SECTION`、`FAST_MODE_SECTION` |
| 需求理解与延续判定分段 | `src/sdk-host/session-runtime.ts` 常量 `INTENT_SUMMARY_SECTION`、`CONTINUATION_SECTION`，判定函数 `judgeContinuation` |
| 专家角色段 | `src/sdk-host/expert-role.ts` 常量 `EXPERT_SECTION_KEY`，定义来自 `resources/agent/experts/` 与 `<agentDir>/experts/`，只在会话选中专家时注入 |
| 快速模式豁免 Skill | `src/sdk-host/product-resources.ts` 常量 `FAST_MODE_BLOCKED_SKILLS` |
| 记忆与委派工具时机 | `src/sdk-host/product-tools-hint.ts` 函数 `productToolsSection`，由 `session-runtime.ts` 的 `MODE_HINT_EXTENSION_NAME` 扩展注入 |
| 回合头改动文件提示 | `src/sdk-host/turn-files-hint.ts` |
| 扩展与 Skill | `resources/agent/**` → 构建暂存为 `out/sdk-host/agent-resources/`（不携带 AGENTS 文件）；技能来源目录由 `src/shared-process/skill-sources.ts` 给出（全局：产品 agent 目录与共享目录；项目：受信项目的 `.pi/skills` 与逐级 `.agents/skills`） |

**设计原则**（来自 `src/sdk-host/product-tools-hint.ts` 文件头与 `session-runtime.ts` 的模式提示扩展注释）：
- 记忆与委派工具随应用提供，其他宿主没有。
- 使用时机写进分段，不写全局 AGENTS.md，避免在缺少工具的宿主里产生"有规范无工具"的偏置。

## 运行时注入源登记

回答「当前会话每轮到底注入了什么」以本表为唯一清单；新增或改动注入源时同步本表。三种形态的代价不同：系统提示分段按轮重写、影响请求前缀；请求级消息不落盘不进界面、不改前缀；随工具注册的提示只在工具被装配时进入。

**系统提示分段**（经 `systemPromptOptions.sections`，`before_agent_start` 钩子，仅用户消息轮）：

| 分段键 | 实现位置 | 写入条件 |
| --- | --- | --- |
| `execution-mode` | `src/sdk-host/session-runtime.ts`（内联扩展 `execution-mode-hint`） | 每轮，按当前模式取标准/快速两段之一 |
| `intent-summary` | 同上 | 非延续轮写入；延续判定为延续时不写 |
| `continuation-signal` | 同上 | 延续判定有结论时写入（延续/新任务两种文案） |
| `expert-role` | `src/sdk-host/expert-role.ts` | 会话选中专家时每轮重写（改定义文件下一轮生效） |
| `product-tools` | `src/sdk-host/product-tools-hint.ts` | 记忆或委派工具可用时；快速模式仅委派段，均不可用不写 |
| `previous-turn-files` | `src/sdk-host/turn-files-hint.ts` | 上一轮有文件写入时 |
| skill-guard 段 | `resources/agent/extensions/skill-guard/index.ts` | 每轮：门禁说明＋登记摘要＋实现版本行 |

**请求级消息**（`context` 钩子追加，`display: false` 且 `requestOnly`，不落盘不进界面）：

| 注入源 | 实现位置 | 触发 |
| --- | --- | --- |
| 记忆背景四段（适用偏好、用户本人的表达风格、常驻约定、当前项目近况） | `resources/agent/extensions/pi-memory/index.ts` | 每轮置于消息列表首位；风格段全量注入要点与原句（独立 20,000 字符预算），标题与段尾写明来源为用户本人发言；另追加注入审计条目（随分支保存） |
| 待办清单回述 | `src/sdk-host/todo-list.ts` | 本轮清单存在且每 3 个工具结果重述一次；首句声明不是用户消息 |

**随工具注册的提示**（SDK 汇入，工具被装配时生效）：`todo_write`、`delegate_subagent`、`present_card`、`skill_guard_select` 与 `memory_*` 的描述及 `promptGuidelines`，见各扩展注册处。`present_card` 的「能力候选」段由 `src/sdk-host/expert-capability.ts` 的 `readCapabilityCandidateSection` 在会话装配时生成（随包非子代理技能 + 全局技能目录 + 本会话 MCP 服务器 + 随包工具声明），不按专家许可集裁剪：模型自己可见的技能已被裁过，候选全集只能单独注入。「专家候选」段由同一文件的 `readExpertCandidateSection` 同源生成（标识、显示名、简介、内置或自定义标记），供团队草案按标识引用团长与成员、更新模式定位目标——标识是主进程分配的，模型无从得知。

**SDK 层注入**（非产品代码，产品不可配置）：全局与工作区 AGENTS.md、技能元数据清单、内建工具描述。

新增系统提示分段前，先核对与 skill-guard 门禁段和记忆背景的叠加效果，避免对同一行为重复提出要求。

## 归属判定规则

写入全局文件前自检：**该规则在非 pi-desk 宿主（Codex / Claude Code / 其他 Pi 项目）是否成立？**

| 内容特征 | 归属层级 |
| --- | --- |
| 提到 pi-desk、设置页路径、功能开关名称、随包资源路径 | 打包产物内置（代码分段） |
| 提到特定宿主的工具名（如 `memory_*`、`delegate_subagent`、`todo_write`） | 打包产物内置（分段） |
| 提到 pi-desk 的技术栈、构建命令、目录约定 | pi-desk 开发仓库 AGENTS |
| 跨项目通用的沟通、权限、判断原则 | 全局用户级 AGENTS |
| 项目专有的技术栈、数据库、API 约定 | 工作区项目 AGENTS |

以下内容不得写入全局 `~/.agents/AGENTS.md`：宿主产品名称、设置页路径或 UI 组件名、功能开关状态、随包资源路径（如 `resources/agent/**`、`out/sdk-host/**`）、产品特有工具的使用时机、执行模式定义与快速模式豁免 Skill 清单。

跨宿主同样成立的通用判断规则（如新任务／延续的信号判定、显式识别的触发条件）可以留在全局文件；但不得把产品注入分段的原文照抄进来，同一要求在 pi-desk 会话中只保留产品分段这一处来源。

## 检查流程

修改前按以下顺序检查：
1. 读本文，判定目标层级。
2. 若属打包产物内置，定位对应代码分段或 `resources/agent/**`，不动全局文件。
3. 若属全局用户级，核查是否依赖产品功能；若依赖则移至产品分段。
4. 改动后检查同义规则是否散落多层；若重复则保留单一来源。
5. 把产品规则从全局文件移出时，先确认产品分段已完整承载原约束（含例外与不豁免项），再删除全局表述，避免约束变弱。
