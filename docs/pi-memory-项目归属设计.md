# pi-memory 项目归属与存量修复设计（初稿）

任务分级：高风险（持久化格式变更 + 存量数据改写，不可逆）。本文只写需求、方向、风险与阶段，不含测试计划与通过标准；任何写库操作仍需单独授权。

## 1. 问题与已确认需求

0.3 起每日文件统一写「全局记忆」段，记录不再携带项目归属。后果是跨项目约定无差别进入每轮背景、挤占常驻预算，且无法按项目收敛或筛选。

已确认需求：

1. 写入记忆时保留项目归属。
2. 修复 0.3 之后写入记录的归属缺失。
3. 常驻约定收敛到当前项目；任务召回仍按关键词全库检索。

## 2. 目标与不做项

目标：记录级恢复项目归属且不牺牲跨项目方法约定；常驻背景按「当前项目优先 + 全局兜底」装配；存量在可核实范围内恢复归属。

不做：

- 不做项目隔离，`docs.`、`memory.`、`pi.` 这类跨项目写法约定仍全局生效。
- 不改查看器 `_global` 的显示语义，无归属记录仍显示「全局记忆」。
- 不重写旧格式的 151 条项目段记录。
- 不做猜测式批量回填，无唯一证据的一律留空。
- 本稿不写字段级结构与实现常数。

## 3. 项目事实

| 事实 | 来源 |

## 4. 关键前提审查

- 「常驻限定当前项目」的前提目前不成立：没有可靠项目字段，硬过滤会排除近七天约三分之二的约定，直接回到「约定不被遵守」的原点。设计必须分两步，先补字段再收敛；字段缺失期间按「项目优先 + 全局兜底」降级运行。
- 项目标识不能用目录名推导：`pi-desktop` 与 `pi-desk` 已不一致，`yymes` 与 `yymes-vdb-*` 也不一致，靠目录名会持续失配。应取项目注册表 id，拿不到时留空。
- 归属缺失属实现缺口而非数据天然缺失：保存时 `cwd` 可得却未传递，协议也未留位置。

## 5. 推荐方向

推荐：写入侧补项目归属 + 读取保持全库 + 常驻改「项目族优先、全局族兜底、其余按预算降为索引行」+ 存量只回填唯一可判定项。

收益：恢复可筛选性、降低跨项目噪声，且不破坏跨项目约定的生效路径。代价：格式版本升级需查看器与引擎同批；存量回填需人工核对。

替代：不动格式，仅把常驻排序改为与本轮任务的相关性优先。收益是零格式变更、当天可落地；代价是不解决归属缺失，存量永久不可筛选，未来任何按项目的能力都要重做。若目标只是减少噪声而非恢复归属，才采用此方向。

## 6. 架构与职责

- 数据：段标记继续用「全局记忆」，归属记在记录上而不是新开项目段，避免出现第三种段形态；`schema_version` 升级，引擎与查看器同批接受。
- 接口：保存候选计划增加项目归属，落盘前校验；不新增工具。
- 职责：扩展负责确定并传递项目标识；引擎负责校验、落盘与索引；查看器只读展示，`_global` 语义不变。
- 数据流：会话工作目录 → 项目注册表 id → 保存计划 → 记录与索引。

## 7. 关键取舍

| 取舍 | 选项 | 推荐与理由 |
| --- | --- | --- |
| 段结构 | 新开项目段 / 全局段加记录级归属 | 后者：段形态不增，查看器与月摘要改动最小 |
| 空值语义 | `null` 表示跨项目全局 / 表示未知 | 统一 `null`，不引入第三种状态，避免「无法判定」被误当「全局」 |
| 常驻收敛 | 硬过滤 / 项目优先加全局兜底 | 后者：字段缺失时不会丢约定 |
| 存量回填 | 唯一可判定 / 全量人工复核 | 前者：错误归属比留空更有害，会误导常驻 |

## 8. 风险与不可逆点

- 写库不可逆：回填前整库备份；只写高置信项；写后核对索引与每日文件一致。
- 格式版本升级：旧引擎或旧查看器会拒绝解析，须同批升级，不做静默降级。
- 错误归属比留空更有害：别的项目的约定被当成本项目约定注入，比不注入更难发现。
- 预算不变时项目族优先：部分全局族会降为索引行，属预期取舍。

## 10. 已确认决策

| # | 决策 | 结论 | 影响 |
| --- | --- | --- | --- |
| D1 | 项目标识来源 | 取项目注册表 id，拿不到时留空 | 写入链路不依赖目录名，不需要项目重命名映射；未登记项目记为全局 |
| D2 | 存量回填门槛 | 只回填唯一可判定项（约 71 条），其余约 39 条留空 | 写库范围限于高置信项，避免错误归属误导常驻 |
| D3 | 字段缺失时常驻行为 | 项目族优先加全局兜底 | 字段缺失时不会丢约定，预算内先装当前项目族，再装全局族 |

三项已定，本设计可收束。阶段一的字段命名、`allowed` 集合扩展方式与旧版本兼容口径另起讨论，不在本稿决定。
