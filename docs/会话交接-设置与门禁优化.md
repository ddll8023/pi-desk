## 三、 待办事项 1：门禁扩展（`skill-guard`）逻辑修复

### 1. 缺陷根因
- **文件路径**：
  - 部署副本：`~/.pi/agent/extensions/skill-guard/routing.ts`
  - 维护源：`~/.pi/agent/skills/pi-skill-setup/assets/extensions/skill-guard/routing.ts`
- **缺陷分析**：
  1. `addRequirement` 函数中将条件错写为 `if (!skill || !skill.disableModelInvocation || origin === 'explicit') result.push(...)`。导致**未安装的技能在自动推断时被强制推入 required**，进而在 `missing()` 检查中因缺失触发永久死锁阻断；
  2. 部署副本中残留了 `frontend-module-map`、`frontend-review` 等已废弃规则，当用户提到“审查”时错误触发了未安装技能的推导。

### 2. 待执行修复动作
将两处 `routing.ts` 的 `addRequirement` 函数同步调整为：
```typescript
/** 仅选择已发现的候选；禁用模型调用的技能只接受用户显式加载。 */
function addRequirement(result: Requirement[], skills: readonly Skill[], name: string, reason: string, origin: Requirement['origin']): void {
  const skill = skills.find(candidate => candidate.name === name)
  if (!skill) {
    if (origin === 'explicit') result.push({ name, reason, origin })
    return
  }
  if (!skill.disableModelInvocation || origin === 'explicit') result.push({ name, reason, origin })
}
```
并将部署副本同步更新为已移除过时路由的最新代码。
