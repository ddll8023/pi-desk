# 会话交接：Pi-Desk 设置与 Skill 门禁

## 范围与工作边界

Pi-Desk 使用 Electron、Vue 3、TypeScript 与 Tailwind CSS。项目界面代码与 Pi Agent 的全局 Skill、扩展资源分属不同位置，不能把同步其中一方当作同步全部内容。

- `pi-desk` 仓库保存应用源码与项目文档。
- 独立的 `skills` 仓库保存 Skill 及其随包资源；门禁维护源位于其中的 `pi-skill-setup/assets/extensions/skill-guard/`。
- 门禁部署副本位于目标 Pi 实际采用的 `<agentDir>/extensions/skill-guard/`，不属于 `pi-desk` 仓库。
- `<agentDir>` 表示目标 Pi 的实际全局资源目录，应根据宿主配置确认，不根据操作系统或目录是否存在猜测。

Git 状态以各仓库的实际差异为准。本文不授予文件修改、提交、推送、测试或运行权限，旧会话中的方案与执行清单也不自动成为新任务的执行授权。

## 界面实现入口

### 会话输入与模型选择

- `src/renderer/src/assets/styles/sessions.css`：会话输入坞的悬停、聚焦与文本区样式。
- `src/renderer/src/providers/components/RuntimeModelSelect.vue`：模型选择触发键的外观与展开状态。
- `src/renderer/src/ui/AppSelect.vue`：共享下拉选择组件，包括模型选项、供应商分组与选中标记。

具体尺寸、颜色、间距与状态规则以对应源码和主题令牌为准，不在交接文档中复制维护。

### 设置公共样式

- `src/renderer/src/assets/styles/shell.css`：设置页内容区、导航、卡片与分隔行样式；`.settings-section-stack` 供分节根容器复用页面级间距，避免只调整外层容器而遗漏分节内部。
- `src/renderer/src/assets/styles/ui.css`：共享分段控件的选中态，包括边框、底色与轻阴影；使用该控件的弹窗也受此规则影响。
- `src/renderer/src/resources/components/ResourceView.vue`：资源与 MCP 主卡片采用 `.settings-section`，卡片内部内容间距与页面级间距分别管理。

设置页保留左侧分节导航、右侧内容区及各自滚动的结构。模型页使用独立布局，不因公共设置卡片的样式调整而自动重新包裹内容。

### 第二阶段待讨论项

- `src/renderer/src/preferences/components/QuickSendSection.vue`、`src/renderer/src/preferences/components/QuickCommandsSection.vue`：协调输入框与行内按钮的高度及对齐，优先复用现有紧凑控件规范。
- `src/renderer/src/providers/components/ModelSettingsView.vue`：讨论供应商清单外层的卡片层级与圆角，保留凭据、模型可见性和编辑入口的交互边界。

这些内容是讨论范围，不是可直接执行的修改清单；进入该阶段时应按当前源码重新确认方案和逐文件操作。

## Skill 门禁职责

部署机制与前置条件以 `skills` 仓库中的 `pi-skill-setup/SKILL.md` 及其随包源码为准。

- 主模型依据当前任务、对话上下文、项目事实与宿主实际发现的 Skill 描述选择执行规范，通过 `skill_guard_select` 登记执行技能、仅审查对象及必读引用。
- 门禁不维护具体 Skill 名称、业务触发词、技术栈到技能的映射或引用文件名清单，也不调用额外分类模型。
- 登记不是加载证明。门禁核对已登记技能与引用的当前版本全文是否进入有效模型上下文，新读取或新登记不能作为同批其他调用的放行证据。
- 必读引用由主模型依据 Skill 正文判定并登记；扩展不扫描全部附件，也不保证模型没有漏选或漏登记。
- 门禁不替代人工确认，不证明模型遵守了正文，也不是命令或进程沙箱。文件同步与宿主加载是不同操作。

维护扩展时应修改随包维护源，再同步同名部署副本，不在两处独立维护逻辑。规则模板与门禁源码是不同资源，目标机器是否需要合并规则，应由 `pi-skill-setup` 核对实际差异后提交清单，不整份覆盖已有约定。

## 新电脑接续

1. 分别同步需要接续的 `pi-desk` 项目源码与 `skills` 仓库。同步 Skill 不会带上应用界面改动；仅运行另一台电脑上的旧版 Skill，也不会自动获取新资源。
2. 将完整的 `pi-skill-setup` 目录放到目标 Pi 可发现的技能位置，保留 `SKILL.md` 与 `assets/` 的相对结构，不只复制入口文档或单个扩展文件。
3. 调用 `/skill:pi-skill-setup`，先只读核对实际资源目录、规则差异和扩展所需 SDK 接口；依次确认方案与逐文件执行清单，再部署获批文件。
4. 需要让新扩展生效时，单独取得运行授权后重载目标 Pi。文件已部署不代表当前宿主已重新加载。
5. 继续界面第二阶段前，先讨论上述待定项与当前源码，不重复执行旧修复步骤或沿用旧授权。
