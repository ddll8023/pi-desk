# 作品库开发设计

状态：已实施（2026-11-16）。本文档保留方案与改动需求，不是逐行实现说明；各文件以当前代码为准。

## 1. 问题与目标

已开发的界面成品散落在各项目与已删除的 demo 里：做完一处界面后，下一次做同类界面仍要从零选型，配色、间距、组件形态与实现手法都没有沉淀。现有能力覆盖不到这一层——记忆库存「用户怎么表达」与工作结论，语气风格库存「用户怎么说话」，都不记录「做出来的东西是什么样、怎么实现」。

作品库要做的是：把界面成品作为资产保存下来（要点 + 截图 + 可运行快照），供后续界面开发按需取用，并在界面上可浏览、可维护。

## 2. 已确认范围

由产品负责人在 2026-11-16 确认的三项：

- **保存对象**：界面成品——页面、组件、demo 的最终视觉与交互。不保存实现产物（模块结构、接口）与外部参考项目。
- **素材形态**：要点 + 截图 + 可运行快照文件。
- **使用方式**：设置页可浏览维护 + agent 按需读取。

配套边界：

- 作品库是全局资产，跨项目共用，不绑定当前目录，不做项目级实例。
- 登记是显式动作：只有用户明确要求「存进作品库」时才写入，不做后台扫描会话或仓库。
- 读取按需发生，不常驻注入每轮背景。
- 快照取源文件副本，不做渲染后 DOM 导出。

## 3. 方案依据

### 3.1 为什么独立目录，不进 `memory.db`

| 备选 | 结论 |
| --- | --- |
| `memory.db` 扩表（复用受管引擎 `plan→commit`） | 不采用。加表要连带加引擎子命令、扩展侧 operation 白名单并升 `STORE_VERSION`，而作品只有少量字段；更要紧的是素材只能是文件，索引入库后一件作品被拆到库与目录两处，删除、备份、迁移都要两处保持一致，属双状态源。作品的词法检索、月摘要、预算、导出快照、有用性标注都用不上，放进记忆库后每处记忆逻辑都要先判断「这条是不是作品」 |
| 独立目录 + 每件作品一个 `meta.json` | 采用。索引与素材同目录：删一件作品就是删一个目录，迁走全部作品就是拷一个目录，没有第二处需要同步 |
| 独立 SQLite 库 | 不采用。作品数量是十几到几十件量级，全量扫描目录即可回答列表与详情，引入第二个库会带来第二套运行时、备份与完整性校验 |

改判条件：作品到需要按要点检索、按标签筛选，或需要跨设备同步索引时，再考虑把索引迁入数据库。

## 4. 数据模型

目录结构：

```
~/.agents/portfolio/
  w_<ULID>/
    meta.json              # 唯一真源
    cover.png              # 可选，封面截图
    snapshots/<原始文件名>    # 可选，源文件副本
```

`meta.json` 字段（版本 1）：

| 字段 | 说明 |
| --- | --- |
| `version` | 结构版本，当前为 1；读取到不认识的版本按不可读处理，不猜测 |
| `id` | `w_` + ULID，同时是目录名，创建后不可变 |
| `name` | 作品名称，用户视角的稳定标识 |
| `scene` | 适用场景，如「设置页分节」「数据表格页」 |
| `points` | 设计要点：布局、配色与令牌、字号阶梯、间距、动效与交互约定 |
| `sources` | 来源数组：项目名、项目路径、会话 ID、日期；仅作溯源，允许失效 |
| `assets` | 素材数组：类型（`cover`／`snapshot`）、库内相对路径、原始来源路径、字节数 |
| `createdAt` / `updatedAt` | ISO 时间 |

约束：

- 目录内相对路径是读取素材的唯一依据；原始来源路径只作溯源，原项目文件变更或删除不影响库内作品可用。
- ID 与目录名一一对应；改名只改 `name`，不移动目录。
- `meta.json` 用临时文件 + rename 写入；同一作品的写操作在主进程内串行，不引入跨进程锁。

## 5. 写入边界

唯一写入方是主进程。三条写路径汇聚到同一数据层，共用同一套校验：

| 来源 | 路径 | 允许的操作 |
| --- | --- | --- |
| 模型工具 `work_save` | sdk-host → 主进程（宿主请求） | 新增作品、复制快照 |
| 设置页作品分节 | 渲染层 → preload → 主进程 IPC | 删除、改名、存封面截图 |
| 其余 | —— | 无 |

校验口径：

- 渲染层只能传作品 ID 与素材相对名，不能传任意绝对路径。
- 快照复制时来源文件必须位于登记会话的工作区根内，超出即拒绝；复制后库内是独立副本。
- 封面截图由主进程按当前内置浏览器页面捕获，不接受渲染层传入的图片数据。
- 素材定位按作品根解析并校验未越界，越界即拒绝。

## 6. 工具契约

三个工具注册在宿主侧（`src/sdk-host/portfolio/`），经注入的 operator 调主进程：

| 工具 | 性质 | 参数要点 | 返回 |
| --- | --- | --- | --- |
| `work_list` | 只读 | 无 | 作品数组：ID、名称、场景、要点摘要、素材数、日期 |
| `work_read` | 只读 | `id` | 单件全量：要点、素材清单（相对路径与类型）、来源；不返回图片二进制 |
| `work_save` | 写入 | `name`、`scene`、`points`、可选 `sources`、可选 `files`（工作区内路径清单） | 作品 ID、素材数与写入结果 |

口径：

- 工具返回不携带图片内容；`work_read` 是否支持返回图片留到实施阶段按当时通道能力决定。
- `work_save` 只登记新增，不覆盖既有作品；更正要点的更新路径在实施阶段确定，本阶段不承诺。
- 三个工具都进工具声明清单与展示分类；两个只读工具进门禁放行集合，`work_save` 不放行。
- 快速模式不裁剪作品工具：作品库与记忆开关、执行模式无关。

## 7. 界面

设置页新增顶层分节「作品」，位于「Pi」组，与「专家」「记忆」并列。

- 列表：名称、场景、日期、素材数；空库给出登记说明，不伪造示例。
- 详情：要点全文、封面、素材清单、来源项目与会话、删除与改名。
- 封面：可「从内置浏览器截取」，复用既有截图通道后由主进程落 `cover.png`。
- 快照：第一版用系统浏览器打开（主进程按作品 ID 解析路径后 `shell.openPath`），不新增内嵌预览协议。

## 8. 宿主装配

- 主进程新增作品数据层单例，按 `memoryManager` 的既有方式作为 provider 传给 `SdkHostManager`。
- sdk-host 侧按 `browserOperator` 的既有做法新增 `portfolioOperator`：等待表、超时、关闭时整表收回；请求经协议事件发往主进程，主进程回对应 `-result`。
- 协议新增作品操作类型与结果类型，字段白名单，不携带路径以外的任意载荷。
- 会话装配时仅在 operator 存在的情况下注册作品扩展；注册失败不影响会话主链。

## 9. 提示与门禁

- `src/sdk-host/product-tools-hint.ts`：补使用时机——界面与前端类任务开工前先用 `work_list`／`work_read` 取已确认的作品要点与素材；用户明确要求「存进作品库」时才 `work_save`，不主动登记。
- `resources/agent/extensions/skill-guard/index.ts`：`RECOVERY_TOOLS` 增 `work_list`、`work_read`；`work_save` 不放行。
- `resources/agent/bundle.json`：`tools` 段补三个工具，`required` 为 false。

## 11. 明确不做

- 不做自动后台采集：不扫描会话、不扫描仓库、不推断「这一轮产出了一个作品」。
- 不做语义检索、向量召回、标签体系与作品评分。
- 不做渲染后 DOM 导出、内嵌预览协议与作品目录的可写协议面。
- 不做跨设备同步、分享、导出打包、版本对比与回滚。
- 不做实现产物与外部参考项目的收录。
- 不新增 `present_card` 卡片类型；登记不经会话内卡片。
- 不改记忆库与语气风格库的任何契约。

## 12. 待定与风险

待定（实施阶段按当次事实确定）：`points` 与 `scene` 的长度上限、快照单个与总量大小上限、`work_read` 是否返回图片、同名作品的处置、作品数量增长后的列表分页。

| 风险 | 说明 |
| --- | --- |
| 素材体积 | 截图与快照各留一份，无自动清理策略，库随登记次数单调增长 |
| 副本脱节 | 快照是登记时刻的副本，原项目后续改动不会反映到库内；这既是稳定性也是陈旧性 |
| 采集受限 | 模型没有截图能力，封面只能由用户在界面里触发；无封面的作品只有要点与快照 |
| 路径越界 | 快照来源与素材定位都涉及路径，校验放在主进程；渲染层与模型都不得传任意绝对路径 |
| 全局单库 | 作品库只有一份、位于用户目录，多账号与多设备不共享，备份需连同目录一起做 |
| 认知重叠 | `docs/开源项目参考/` 与本作品库都可能被当作「参考」：前者是外部产品对照，后者是本项目自己的成品，两处分工需在文档里说清，避免模型混用 |

## 13. 交接说明

实现方开列执行清单前需自行复核：`browserOperator` 链路对超时、关闭与绑定失效的处理能否原样照搬；作品分节可用的截图 `webContents` 来源与既有元素选取截图的差异；设置页分节枚举与图标组件的现有契约；`bundle.json` 构建期核对的覆盖范围；门禁放行集合改动后 `work_save` 的登记时机是否仍可被模型感知。本文档给方案与改动需求，具体实现按各文件当次事实确定。
