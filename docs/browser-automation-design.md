# pi-desk 内置浏览器 AI 自动操控初步设计

本文说明需求、范围、项目依据、推荐架构、权限边界及开发阶段方向，不是实现规格或开发授权。协议字段、工具命名、依赖选型、具体源码改动和实现常数留到对应开发阶段讨论。

## 1. 目标与需求来源

### 1.1 用户明确提出的需求

- 在 pi-desk 内置浏览器中提供 AI 自动操控能力。
- 参考 CoWork OS 的浏览器能力，并结合当前项目形成开发设计文档。
- 本次交付为设计文档，不直接实施业务功能。

### 1.2 已确认作为初稿依据的推荐方向

以下是本轮设计方向，不代表已经实现，也不把第三方的全部能力转为本项目需求：

- 默认复用 Electron 内置 Chromium，通过原生 CDP 驱动应用内页面。
- 复用当前会话的模型和 Agent 执行循环，不另建浏览器专用 Agent Loop。
- 使用结构化页面快照与元素引用，截图作为按需补充，不依赖每步视觉识别。
- 浏览器执行由主进程统一管理，经受限通道接入独立 SDK 宿主。
- 提供可观察、可暂停、可人工接管的操作过程。
- 将浏览器控制授权与 Project Trust 分开，推荐项目级登录态隔离。
- 首版沿用工作区浏览器标签，不先重做聊天与浏览器分栏布局。

### 1.3 目标

让 Agent 能在用户授权的内置页面上理解内容、导航和完成有限交互；用户能够确定操作归属、查看当前页面、停止后续动作并接管。会话切换、页面重建或执行异常不得导致操作转投其他标签，也不能把工具受理或输入派发等同于业务已经完成。

## 2. 范围与不做项

### 2.1 首版范围

- 面向当前桌面应用中的受管浏览器实例，支持页面导航、正文读取、结构化快照、截图及基础点击、输入、按键和滚动。
- 支持会话与浏览器实例的显式绑定、浏览器控制授权、单实例独占控制和动作串行。
- 支持状态展示、定位浏览器、人工接管和明确恢复。
- 处理导航、页面销毁、宿主失效、绑定换代、调试连接中断及操作结果未知。
- 保留既有人工浏览、截图、元素选择和批注交付；采集与自动化冲突时通过控制权协调，不直接覆盖未交付批注。

导航并非纯读取：访问地址本身也可能产生服务端副作用。基础交互同样不意味着可以无条件提交表单或修改远端数据。

### 2.2 首版不做

- 独立浏览器内核、Python 自动化运行时、云端浏览器及系统 Chrome／Edge 接管。
- 任意 JavaScript 执行、任意 CDP 命令透传、Cookie／存储导出及凭据管理。
- 自动上传下载、自动处理支付或账号删除、验证码绕过及系统级桌面控制。
- 后台无人值守运行、手机端浏览器控制、跨应用重启恢复执行及自动重放历史操作。
- 保证覆盖所有跨域 iframe、封闭 Shadow DOM、Canvas、复杂编辑器或原生弹窗。
- 通用浏览器扩展平台、完整开发者诊断工作台及全项目网络沙箱。

## 3. 当前项目事实

本节描述已读取的实现，不将现状直接当成必须保留的需求。

- 项目使用 Electron、Vue、TypeScript 和 Pinia。浏览器视图位于 `src/renderer/src/browser/components/BrowserView.vue`，网页由 `<webview>` 承载，导航状态由 renderer Store 保存。
- `src/main/browser/ipc.ts` 仅提供受限截图、人工元素选择与取消。目标校验包含可信主窗口、webview 类型及宿主归属；当前没有浏览器自动操控契约。
- `src/main/window.ts` 在挂载时强制关闭 Node 集成、开启上下文隔离与沙箱、移除网页 preload；普通浏览器统一使用 `persist:desktop-browser`。现有登录态不是按项目隔离。
- 同文件拒绝浏览器敏感权限请求并阻止下载。首版不因引入自动化而自动放开这些限制。
- SDK 会话在独立 utilityProcess 中执行。`src/sdk-host/session-runtime.ts` 装配内置扩展；`src/sdk-host/index.ts` 与 `src/main/sessions/sdk-host-manager.ts` 已有受限反向目标准备通道，但它不是现成的浏览器操作通道。
- `src/sdk-host/protocol.ts` 使用宿主身份和绑定代际约束请求；运行归属与代际分配由主进程注册表维护，不能由模型或宿主自行声明授权。
- 浏览器标签按项目分组。`WorkspaceView.vue` 以活动标签控制面板展示，浏览器与对话并非始终并排；切换项目也不能假定原浏览器实例仍可操作。
- `src/main/trust/trust-manager.ts` 明确只处理项目资源信任，不提供 OS 沙箱或工具权限限制。
- 现有浏览器工具栏可以打开 DevTools；自动化必须处理其与 CDP 调试连接的竞争。

## 4. 调研结论与技术取舍

### 4.1 参考 CoWork OS，但不照搬整个工作台

CoWork OS 的 Browser V2 文档将可见浏览器、主进程会话管理、工作台桥接和 Agent 工具分开；其浏览器会话管理源码中可以定位到无障碍树读取、DOM 几何信息、点击前命中检查与 CDP 输入派发。

本项目调整后采用：

- 人工与 Agent 操作同一页面实例，避免后台浏览器与可见页面状态分叉。
- 主进程管理目标、控制权和生命周期，工具层不直接依赖 renderer 页面脚本。
- 使用短生命周期元素引用，动作前重新解析目标，不保存坐标作为长期操作依据。

不照搬其全部云端后端、凭据服务、诊断抽屉和外部浏览器能力。相关资料说明机制存在，不证明本项目兼容性、操作成功率、token 消耗或延迟已经得到量化结论。

### 4.2 默认路线：原生 CDP，加受限宿主桥接

Electron 的 `webContents.debugger` 可向所属页面发送 CDP 命令，适合复用应用已有 Chromium。无需默认额外捆绑独立浏览器内核，但仍有页面适配、上下文裁剪、异常处理及维护成本。

浏览器工具通过当前 SDK 会话调用主进程服务，不在独立宿主中导入 Electron 窗口对象，也不假设两者可以直接函数调用。

MCP 是工具协议，不是浏览器引擎，与 CDP 不是互斥路线。首版优先复用受管进程通道；未来若需要服务外部 Agent，再单独讨论 MCP 适配及其授权边界，不提前开放本地 HTTP 或调试端口。

独立浏览器方案更适合无头或无人值守任务，但会增加页面、登录态、生命周期和分发管理；这些目标不在本次首版范围，因此不作为默认方案，也不作为静默后备。

### 4.3 容器复用与替换边界

Electron 官方提醒 `<webview>` 存在架构变化带来的稳定性问题，并建议考虑 `WebContentsView` 等替代方式。本项目已有网页批注与 Vue 工作区集成，首版暂复用现有容器，避免将自动化与整个浏览器界面重写绑定。

自动化核心只依赖经过登记的受管 `webContents` 和能力适配，不依赖 Vue 元素引用。后续替换容器时，保留控制权、授权与工具职责边界，但不承诺底层事件和界面编排无需调整。

## 5. 架构与职责

### 5.1 SDK 宿主工具层

- 在当前会话中注册浏览器能力，提供简洁、受限的操作语义。
- 传递动作意图、接收有界结果与取消状态，不掌握全应用浏览器清单或原始 Electron ID。
- 继续由当前 Agent Loop 决定下一步，不建立第二套模型配置、任务规划器或循环。
- 能力关闭或运行环境不支持时明确不可用；不因浏览器能力失败而悄悄改用外部工具。

### 5.2 主进程浏览器会话服务

- 维护浏览器实例、项目归属、绑定会话、授权、控制权和动作队列的权威状态。
- 复核每次请求的宿主身份、会话代际、实例归属、授权范围与页面状态。
- 管理 CDP 连接、导航策略、元素引用和取消；向宿主与界面投递受限结果。
- 浏览器内容的读取和截图同样需要授权，不仅校验写操作。

主进程只登记明确属于普通浏览器能力的实例，不因目标是主窗口下的 webview 就允许控制文件预览、HTML 预览或认证页面。

### 5.3 页面能力适配层

- 负责页面语义、必要正文、DOM 关联、几何信息和浏览器输入。
- 只暴露固定能力；模型不能提交任意脚本或选择原始 CDP 方法。
- 主动报告页面无法支持的能力，不把空结果包装成完整页面，也不默认跨越未支持的框架边界。

### 5.4 工作区展示层

- 将已就绪的浏览器实例经受限桥接登记，卸载和销毁时撤销登记。
- 展示归属会话、运行状态、最近动作、暂停原因及人工接管入口。
- 为对话提供浏览器活动入口和定位能力，不要求浏览器一直占据前台，也不反复抢夺用户焦点。
- renderer 保存展示副本，不自行批准控制权或认定动作已经完成。

### 5.5 数据流方向

Agent 工具意图经 SDK 宿主通道到主进程；主进程确定授权目标后交给页面适配层；实际结果和状态分别返回原工具调用与工作区展示。

创建或展示浏览器需要 renderer 配合时，必须等实例完成登记后才允许执行。没有目标时明确失败或请求建立受管页面，不按当前焦点猜测目标。

## 6. 身份、控制权与生命周期

### 6.1 固定目标，不跟随当前标签

项目、会话运行身份、绑定代际和浏览器实例共同确定操作归属；页面文档与快照版本再约束具体元素引用。持久会话 ID、工作区标签 key 和 Electron ID 各有职责，不能互相替代。

首版每个浏览器实例只允许一个会话控制，同一实例的动作串行执行；其他会话不能因同属一个项目就复用其授权。用户可以显式选择已有页面交给会话，或为会话建立新页面，不默认接管正在人工使用的任意标签。

### 6.2 观察与交互授权分开

控制授权绑定当前会话、浏览器实例和可访问站点范围。读取、截图和交互的范围都应向用户可见；导航也必须符合范围。

人工临时登录或跳转不自动扩大 Agent 授权。Project Trust、模型提示词以及网页提供的文字均不能代替控制授权。

### 6.3 接管、暂停与恢复

- 用户接管立即撤销后续自动动作资格，取消尚未派发的排队动作，再将页面交给人工操作。
- 已派发的输入或已发生的远端提交不可承诺撤回；界面区分停止派发与结果已经收敛。
- 恢复由用户明确触发，重新读取页面并确认授权仍有效，不续用人工接管前的旧引用或排队动作。
- 截图批注和人工元素选择期间暂停 Agent 交互，避免固定画面与实时页面分叉。
- 同项目切换标签不改变绑定目标；浏览器处于不可呈现或不可可靠操作状态时暂停需要该状态的动作，不把隐藏页视为前台页。
- 切换项目或窗口隐藏时暂停后续交互；返回后不自动重放排队动作。

### 6.4 失效与清理

关闭浏览器、移除项目、会话换代、宿主退出、主窗口失效或应用退出时撤销控制权、丢弃旧引用并结束等待。迟到响应只归属原调用，不重新授权新实例。

浏览器状态可在页面内保持，不代表自动化运行跨重启恢复。历史工具记录仅供回看，不携带可恢复的控制权。

## 7. 页面理解与动作语义

### 7.1 快照不是完整 HTML

以无障碍语义为基础，结合必要正文和 DOM 信息形成紧凑上下文。保留标题、说明、表单标签、控件状态与当前页面内容，不能只返回可点击按钮。

无障碍节点不天然等于可见或可点击节点，也不天然带有可用几何坐标。需要结合 DOM、视口和页面状态补足。长页面采用有界、按需读取，截断或局部覆盖必须明确报告，不承诺固定 token 数。

截图用于语义树不足、视觉定位或人工讨论；模型无图片能力时不强行依赖截图完成交互。

### 7.2 元素引用与动作前检查

元素引用绑定当前实例、文档及快照，不是长期选择器。导航、页面重建、接管或新的快照使旧引用失效；动态变化导致目标身份或语义不再匹配时，返回重新观察的指引。

执行前重新解析节点，检查是否仍属于原文档、是否启用、可见及未被遮挡，并以当前几何信息确定输入位置。不能仅因引用未过期就使用旧坐标，也不能把按钮名称相同当成同一元素。

### 7.3 输入派发与结果表达

CDP 输入向浏览器页面派发事件，不是操作系统级输入，也不能保证所有站点、复杂控件和浏览器手势限制都能处理。

工具结果分别表达请求是否被允许、输入是否已派发以及能观察到的页面变化。只有获得相应页面证据才能描述业务结果；点击已经派发不等于登录、保存或交易成功。

## 8. 数据与安全边界

### 8.1 项目级登录态

推荐按项目隔离浏览器存储分区，不复用主应用会话和系统浏览器 Cookie。同项目多个页面可以共享该项目登录态，但控制授权仍逐会话、逐实例建立；项目隔离不等于同项目账号隔离。

现有共享分区的 Cookie 不自动复制、迁移或清理。切换后的页面需要用户重新登录；现有页面如何退出和新分区如何启用，留到对应开发阶段讨论，不隐式删除用户数据。

### 8.2 不可信网页与模型可见内容

网页文本、无障碍名称、截图和错误信息都是外部数据，不构成操作指令或扩权依据。页面要求执行命令、读取本地文件或上传资料时仍受原任务与工具授权约束。

不向模型开放密码、认证存储、Cookie 或原始存储快照。人工处理密码、验证码和敏感页面时暂停自动化观察与截图，恢复后重新读取允许公开的内容；不能仅靠字段脱敏承诺整张截图没有隐私。

工具参数、错误、活动摘要和会话历史都属于信息出口，应减少采集与持久化，不主动保存完整页面或连续截图。必要内容进入模型意味着发送给当前供应商，界面必须让用户理解该边界。

### 8.3 导航与交互策略

首版 Agent 导航限于授权的 HTTP(S) 页面；本地开发服务可在明确授权范围内访问，不把内网所有地址视为自动允许。人工浏览已有能力不等于 Agent 可以使用本地文件或特殊协议。

导航、重定向、弹窗及新页面统一受策略处理；不能只检查工具传入的 URL。未受支持的弹窗或认证交接应暂停并提示，不在不知情时换成系统浏览器。

首版不承诺完整网络隔离。网页子资源、脚本请求与服务工作线程不因顶层导航限制就自动受到全面约束；不能把浏览器控制策略宣传为全项目网络沙箱。

交互必须落在用户授权范围内。提交性或无法可靠判定影响的动作保守请求确认；不能只依靠按钮文字、模型自报意图或关键词识别危险行为。首版不开放无法执行该边界的交互路径。

### 8.4 故障降级

调试连接断开、DevTools 竞争或能力不支持时停止相关动作并给出可恢复状态，不自动改走任意脚本、独立浏览器或更高权限路径。普通人工浏览与已有对话能力应独立可用。

停止自动化不回滚已经发生的远端修改；恢复方向是人工检查当前页面后重新授权观察与交互，而不是重放旧队列。

## 9. 异常与结果未知

导航或交互超时不等于没有执行。若请求已经派发但完成结果丢失，保留结果未知状态，不自动重复点击、输入或提交。

可通过重新观察原页面收集事实，但不能将一次观察无变化解释成动作未执行。需要人工判断时停在原目标，不转投其他标签继续。

宿主等待浏览器结果期间，取消、授权回应和控制权撤销不能依赖被该动作占用的串行链，避免相互等待。解除等待与底层动作真正停止是不同事实，状态必须分别收敛。

## 10. 开发阶段方向

### 阶段一：目标登记、权限与控制权

明确浏览器实例归属、项目分区方向、显式绑定、观察／交互授权及接管语义。建立主进程权威状态与关闭失效边界，先解决“谁可以控制哪个页面”。

本阶段详细讨论实例创建与登记、旧共享分区页面的处理范围、站点授权粒度及无法判断副作用时的确认交互。

### 阶段二：页面观察与有限动作

在阶段一的目标和权限边界内形成页面适配层，提供有界快照、正文、截图与基础交互，处理元素引用、命中检查和调试连接失效。

本阶段详细讨论快照裁剪、页面变化判定、可支持的控件与框架范围，以及输入后的状态表达，不把未支持页面包装成通用能力。

### 阶段三：SDK 宿主工具接入

接入当前会话执行循环，补齐受限的宿主到主进程请求、回应和取消语义，保持原运行身份与绑定代际规则，不另建通用远程调用入口。

本阶段详细讨论工具契约、能力启停、SDK 运行时适配及结果未知的投影方式；具体实现基于当时实际加载的 SDK，而不是只依据编译期依赖声明。

### 阶段四：工作区状态与人工交接

将主进程控制状态接入浏览器标签和对话活动入口，提供定位、暂停、接管、恢复和明确的失败展示，与现有截图批注协调。

展示层设计可提前梳理，但真实执行和状态接线依赖前述身份、权限与工具通道。首版不因此重排整个工作区。

## 11. 开发阶段待定项

以下内容不阻塞初稿交付，但必须在进入相应阶段时明确，不视为已经解决：

- 项目分区启用方式、用户重新登录的提示及已有共享分区页面的收尾方式。
- 站点范围、读取与交互授权的持续时间，以及疑似提交动作的保守确认方式。
- 动态 DOM 的引用失效规则、无障碍树与 DOM 的补充策略、框架目标路由边界。
- 工具命名、请求与取消契约、运行时能力探测、图片结果和活动投影的表达方式。
- 后台标签的可操作条件、视口与页面节流处理、DevTools 冲突后的恢复交互。
- 截图与正文的信息裁剪、敏感页面保护范围及工具结果的持久化边界。

上述细节若无法满足本稿安全边界，应缩小相应能力范围或回到受影响的设计决策，而不是以默认放行维持功能完整。
