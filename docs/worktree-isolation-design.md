# 多 Worktree 隔离与会话分支管理初步设计

本文档用于明确多 Worktree 隔离、会话分支树（Branching Session）与 Rewind 代码联动回退的需求、范围、架构职责、核心机制与开发阶段规划。本文档为初步设计，不作为最终实现规格或代码开发授权。具体文件改动、协议字段与实现细节在对应开发阶段结合事实讨论。

---

## 1. 目标与需求边界

### 1.1 需求来源与要解决的问题
1. **多会话并发修改冲突**：当前多个会话并发执行时共享同一主工作区，Agent 并发写入同一文件会导致代码覆盖，同时运行测试或构建会造成相互踩踏；
2. **Git 工作区分支抢占**：单工作区下某会话切换 Git 分支会直接强行改变所有会话的文件基线，暂存区提交可能连带提交其他会话的未完工代码；
3. **会话单一直线历史**：当前回退（revert）机制仅能将消息指针前移覆盖，无法在多方案探索间保留分叉历史；
4. **回退缺乏代码联动**：现有 Rewind 仅回退会话文本，无法将磁盘文件重置到对应轮次的状态，导致“会话已回退但代码仍包含错误”的不一致。

### 1.2 预期目标
- **物理工作区隔离**：统一 Agent、文件、Git 与终端的执行上下文，为选定任务创建独立的 Git Worktree 与临时分支；新对话默认继承当前工作区环境，不强迫用户预先选择模式；
- **任务完成闭环**：任务交付后提供「审阅合入 → 一键清理（移除工作树与临时分支）」流程，并在合入与清理前阻断在途操作，弹窗确认关闭受影响的运行终端；
- **独立 Turn 检查点与代码时光倒流**：基于独立 bare Git 仓库记录交互轮次增量检查点，不向任务分支追加快照提交；用户在历史会话点击回退时，联动将代码精确回滚到该轮次完成时的状态；
- **会话历史分支树**：会话支持从任意历史回合派生新分支探索，并可在多分支间自由切换。

### 1.3 明确不做项
- **不做跨主机/远程 SSH Worktree**：所有工作树均在本地文件系统执行；
- **不做内置复杂三方冲突解决器**：合并遇到严重代码冲突时保留标准 Git 冲突标记，交由本地代码编辑器或终端解决；
- **不强制每会话必建 Worktree**：普通代码浏览、文档问答或低风险轻量修改仍默认运行在主工作区，避免无谓的磁盘与资源开销。

## 2. 项目事实与调研结论

### 2.1 项目底层事实
- **Git 架构具备基础**：`src/main/git/git-repository.ts` 中已有 `--absolute-git-dir` 与链接工作树识别能力，能正确获取工作树独立的 `gitDir`；
- **进程 CWD 统一管理**：`src/main/sessions/session-run-registry.ts` 和 `sdk-host-manager.ts` 集中分配会话运行环境，主进程具备向 SDK 宿主、终端注入自定义工作目录（CWD）的能力；
- **会话回退已有机制**：当前已具备基于官方 SDK 条目 ID 的会话回退指令，但未持久化代码快照映射。

### 2.2 外部成熟实践参考
- **Orca（Worktree 任务隔离标杆）**：以任务工作树为调度中心，工作树独立隔离分支，依赖目录通过共享/软链接复用；提供完成后的审阅合入与归档清理闭环；
- **Lancer（会话分支与 Turn 快照标杆）**：在每个交互回合（Turn）自动为工作区记录轻量增量快照，支持任意历史 Turn 维度的差异审阅与回退，并通过拓扑图直观展现分支派生。

## 3. 总体架构与职责划分

```text
[主工作区 (Main Repo)] ─── 共享 .git ───┬─── [Worktree 1 (Task/Feature A)]
         │                              └─── [Worktree 2 (Refactor B)]
         ▼
[会话 1 (默认主目录)]                  [会话 2 (绑定 Worktree 1)]
   ├── SDK 宿主 (cwd: Main)              ├── SDK 宿主 (cwd: Worktree 1)
   ├── 文件树 (root: Main)               ├── 文件树 (root: Worktree 1)
   └── 终端 (cwd: Main)                  └── 终端 (cwd: Worktree 1)
```

### 3.1 核心服务职责
1. **工作树生命周期服务 (`src/main/git/worktree-service.ts`)**：
   - 负责调用系统 Git 执行工作树创建（`git worktree add <path> -b <branch>`）、查询、检测与移除（`git worktree remove`）；
   - 管理工作树专属目录路径，负责主工作区依赖（如 `node_modules`、`.venv`）的符号链接（symlink）映射；
   - 监听与同步工作树健康状态（是否被外部手动删除或损坏）。
2. **上下文与路径动态路由 (`src/main/sessions/` / `src/main/terminal/`)**：
   - 会话元数据增加 `worktree` 绑定关系；
   - `SessionManager` 在拉起 `sdk-host` 实例时，将实际 cwd 替换为工作树根路径；
   - 终端模块与文件模块感知当前标签绑定的会话属性，动态切换工作目录与文件树观察根。
3. **Turn 快照与 Rewind 联动协调器 (`src/main/git/turn-snapshot-service.ts`)**：
   - 在已绑定 Worktree 的会话中，当一轮工具调用产出实质修改（`agent_settled`）后，自动在 Worktree 分支打内部轻量提交；
   - 记录 `messageId <-> commitHash` 索引；
   - 承接用户 Rewind 请求，执行 Git 重置（`git reset --hard <commitHash>`）并协同 SDK 宿主回退消息。
4. **主进程工作区管理器与合并清理闭环 (`src/main/workspaces/workspace-manager.ts` / `src/main/git/worktree-service.ts`)**：
   - 负责工作区持久身份分配、会话绑定管理、操作在途占用计数与文件未保存编辑保护；
   - 负责调用系统 Git 执行工作树创建、合入（Merge / Squash Merge）与临时分支清理，合入与清理前提供运行终端统计与关闭许可确认。

## 4. 关键交互与数据流

### 4.1 新建并行任务工作区
1. 用户在对话标签右键菜单中点击「新建并行任务」（普通「+」新建对话则直接继承当前工作区环境）；
2. 主进程在 `.pi/worktrees/<uuid>` 目录创建新工作树，并固定所属项目分支与起始提交，分配临时分支 `pi/task-<uuid>`；
3. 主进程建立依赖软链接（如 `node_modules`）；
4. 会话启动，其绑定的 SDK 宿主、右侧文件树、Git 面板、新开终端均以此工作树根为执行上下文。

### 4.2 轮次快照与 Rewind 回退
1. **快照生成**：Agent 完成一轮工具写操作并交还控制权时，主进程在当前 Worktree 执行静默快照提交，记录 `messageId` 与对应 Commit；
2. **触发回退**：用户在历史消息点击 Rewind；
3. **确认弹窗**：提示用户选择：
   - **同时重置代码至该轮状态（默认推荐）**：Worktree 执行硬重置到对应 Commit，对话回退到该轮；
   - **仅回退对话**：仅回退会话消息，保留当前磁盘文件现状。

### 4.3 任务完成与审阅清理
1. **交付提示**：会话底部呈现任务工作区状态条，提示检测到的当前未提交文件状态；
2. **审阅并合并**：用户点击「审阅并合并」，展示当前未提交文件清单，并明确说明这不是任务分支的累计差异；
3. **合入与清理**：用户确认合并，可选择 Squash 模式、合入后自动清理工作树，并在存在运行终端时勾选允许关闭受影响终端；
4. **安全保护**：合入与清理前先锁定在途文件、Git 与终端操作，检查未保存编辑；若用户选择放弃该任务，可点击「放弃」，检测未提交改动并二次确认后安全删除。

## 5. 存储边界与安全约束

1. **工作树目录位置**：
   - 统一存放于主仓库内的 `.pi/worktrees/<uuid>`；
   - 创建工作树时，自动检查并在主仓库的 `info/exclude` 中追加 `/.pi/worktrees/` 忽略项，防止工作树文件被意外暂存，且不污染版本化 `.gitignore`。
2. **依赖共享与符号链接安全**：
   - 仅对受忽略的可再生依赖目录（如 `node_modules`、`.venv`）建立系统级符号链接；
   - 若遇到平台限制（如未开启开发者模式的 Windows），则降级为不自动创建依赖软链接，提示用户在终端按需安装。
3. **文件监听与资源释放**：
   - 避免无休止为所有历史工作树常驻文件监听；
   - 仅对当前界面激活的工作区挂载 `project-directory-watcher`，切走或闲置时解挂；
   - 工作区清理时主动释放关联的文件索引缓存与 HTML 沙箱预览。

## 6. 开发阶段规划

### 阶段一：任务工作区持久身份与物理工作树生命周期（已完成）
- **目标**：主进程建立稳定工作区身份与持久会话绑定，支持工作树创建、合入与受保护清理；
- **关注点**：多工作树 porcelain 解析、依赖符号链接映射、`info/exclude` 维护、写队列解除自等待与非托管工作树安全阻断。

### 阶段二：统一执行上下文路由与生命周期保护（当前完成）
- **目标**：实现会话、文件树、编辑器、资源预览、Git 和终端全链路绑定任务工作区，贯通清理保护；
- **关注点**：新对话环境继承与标签菜单并行任务交互、跨进程显式 `WorkspaceTarget` 路由、在途操作阻断、未保存文件编辑保护与运行终端关闭许可确认。

### 阶段三：基于独立 Bare 仓库的 Turn 检查点与审查工作台（下一阶段）
- **目标**：替换现有提交式快照，在应用数据目录建立独立 bare Git 仓库管理交互轮次增量检查点，端到端贯通代码时光倒流与审查工作台；
- **关注点**：独立快照捕获性能与保留策略、Rewind 联动代码重置、审查工作台与全任务累计差异展示。
