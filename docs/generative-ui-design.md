# pi-desk 内置生成式 UI 特性设计

> 目标：让模型在对话内交付可交互界面（参数调节、对比、流程、指标、图表、机制图解），而不是只给 Markdown。
> 本文是初步设计，只确定需求、边界、大致架构与阶段目标；具体实现留到各开发阶段按当时事实讨论。
> 参考对象：`Scorp1o117/dsh-motion-ui`（DSH 宿主插件，2026-10-17 版本 0.8.4）、`Michaelliv/pi-generative-ui`（pi 生态原生窗口方案）。

---

## 0. 结论先行

1. **做成 pi-desk 的内置特性，不做可安装包**。这是本项目与 dsh-motion-ui 的根本差异：dsh 是第三方插件，只能寄生在宿主已有的通用扩展点上；pi-desk 自己是宿主，可以直接改主进程与渲染进程，把能力做成产品的一部分。
2. **内置之后，上一轮卡住的两件事都不再是障碍**：渲染端没有通用扩展点（`ChatMessageItem.vue` 硬编码 `<ToolCard>`）可以直改；CSP 封死第三方 JS 也不影响，因为渲染的是我们自己的 Vue 组件，不是第三方代码。
3. **性质随之变化，这是要认的代价**：从"可卸载的第三方扩展"变成"永久内部契约"。文档 schema 从 v1 起就是兼容基线，体积与兼容负担全部归 pi-desk。
4. **一期做声明式原生组件 + 机制图解 + 交付可靠性，不做自由画布**。原生组件与机制图解都是零沙箱依赖，能最快形成 pi-desk 独有的能力；自由画布需要独立源与 CSP 改造，放二期。
5. **最值得借鉴的不是渲染，而是交付可靠性**。dsh-motion-ui 的绝大部分工程量花在"让模型可靠产出"上——短文本与富载荷分离、revision 与局部修改、具体字段诊断、部分交付标记、按需指南、提示词压缩。没有这层，生成式 UI 会变成负资产。
6. **有一整套机制不应照搬**：正文围栏标记定位、独立文件存储、六套视觉风格注入、视频语音流水线。前三者是宿主限制的产物或与本项目设计体系冲突，后者引入不可控的外部依赖。

### 1.2 pi 侧（官方文档事实）

- 扩展能力面：`pi.registerTool()`、`pi.on()`、`pi.registerCommand()`、`pi.appendEntry()`、`pi.sendMessage()`。
- `ToolExecutionEndEvent.result` 为完整工具结果，`details` 用于"渲染或状态重建"，不进入模型上下文。
- `renderCall` / `renderResult` 只作用于交互式终端 transcript 与 HTML 导出，**不作用于 RPC 客户端**（pi-desk 正是 RPC 客户端）。因此富 UI 必须由 pi-desk 渲染端实现。
- 内置扩展可通过 `resourceLoaderOptions.extensionFactories` 的 `InlineExtension` 注入，与用户安装的包走同一套 `ExtensionAPI`。
- 状态存放约定：跟随会话分支的工具状态放 `details`；不进模型上下文的持久数据放 `pi.appendEntry()`；要发给模型的内容放 `pi.sendMessage()`。

## 2. 需求、目标、范围

### 2.1 已确认需求

- 模型能在回答中交付结构化、可交互的界面，位置跟随该次工具调用。
- 界面内的参数调整不逐次请求模型；只有用户显式提交才产生新一轮对话。
- 界面可被模型在后续轮次定位、局部修改，而不是每次重画一份。
- 渲染失败、校验失败必须明确告知，不得把不完整结果当成成功展示。
- 作为产品特性，视觉风格与 pi-desk 现有设计体系一致，不引入第二套规范。

### 2.2 目标

- 打通"模型生成 → 投影放行 → 流内渲染 → 参数交互 → 显式提交"的最小可信链路。
- 交付机制图解（装配拆解、齿轮传动、曲柄连杆）这类无需沙箱、辨识度高的图解能力。
- 让模型可靠产出：校验、诊断、局部修改、部分交付标记、按需指南。

### 2.3 明确不做（本期）

- 自由 HTML / SVG / JS 画布与沙箱（列入后续期）。
- 视频成片、语音合成、FFmpeg / Playwright 相关能力。
- 多套视觉风格注入与风格预览系统。
- 模型侧自动触发的新一轮请求（参数变化不得静默发消息）。
- 正文围栏标记定位、独立文档文件存储。
- 向第三方开放渲染端扩展点（不引入外部 JS 进入渲染进程的能力）。
- 测试与验收由项目维护者自行负责，不在本设计范围内。

## 3. 性质变化：内置之后要认的代价

| 维度 | 作为第三方插件 | 作为内置特性 |
| --- | --- | --- |
| 分发 | 可 `pi install` / `pi remove`，独立 semver | 随 pi-desk 发版，用户不可单独卸载 |
| 协议归属 | 需要通用载荷协议 + 版本协商，供任意扩展使用 | 内部契约，只需服务自己，但仍需版本号以兼容历史会话 |
| 渲染端改动 | 需要通用扩展点（当前不存在） | 直接改，无需为第三方设计抽象 |
| 安全面 | 第三方代码不能进渲染进程（97 处 IPC 桥） | 自有可信代码，原生组件无此问题 |
| 体积与兼容负担 | 归扩展作者 | 归 pi-desk |
| 演进自由度 | 受宿主接口限制 | 可以自由调整，但受历史会话兼容约束 |

结论：内置路线在实现上更省、能力上更强，代价是把 schema 变成永久兼容基线，并把维护责任完全内化。

## 4. 已采纳的取舍

| # | 决策 | 结论 | 理由 |
| --- | --- | --- | --- |
| 1 | 内置范围 | 声明式组件 + 机制图解 + 交付可靠性；画布二期，视频不做 | 前两项零沙箱依赖，能最快形成差异化；画布需要独立源与 CSP 改造 |
| 2 | 代码归属 | 独立目录 `src/extensions/genui/`，通过 builtin factory 注册 | 模块边界清晰；若将来要拆成可安装包，只需搬目录 |
| 3 | 沙箱改造 | 二期新增独立源（如 `app://genui`），**不放宽** `app://desktop` | `app://desktop` 是静态资源专用且有 realpath 边界检查，放宽会削弱现有防线 |
| 4 | 图表能力 | 自研轻量柱/线图，不引入图表库；只支持单序列，多序列用 table | 刻度取整与坐标映射只有百余行，比任何图表库的接入成本都低，也不占主包体积；重型图表库不并入主包 |
| 5 | 视频 / 语音 | 本期不做 | 唯一的重外部依赖；Electron 只能解决 Chromium 部分，FFmpeg 仍需外部安装 |
| 6 | 渲染位置 | 对话流内，跟随工具调用位置 | pi 的工具结果天然挂在 `toolCallId` 上，位置语义确定 |
| 7 | 参数持久化 | 一期只存渲染端内存，界面明示"参数未随历史恢复" | 持久化需要跨重启契约；先诚实降级，二期再定 |
| 8 | 局部修改 | 放二期，一期只支持重新渲染 | 依赖 1 与 7 定型 |
| 9 | 用户侧开关 | 开关只停用生成；历史界面照常渲染与调参；改动在会话创建期生效，界面提示后由用户手动重载 | 生成是唯一会让模型主动尝试的行为；把已交付界面转纯文本会让历史看起来像丢了内容，也要在渲染链路再加一层门禁 |
| 10 | 图解派生方式 | 不引入通用表达式求值器：几何在组件内按固定公式算，节点只用 `binds` 把 `angle` / `spread` 指向 `number` 参数 | 图解只需要少数几个几何量随参数变，写求值器会把 §7 第 5 条风险重新引进来；固定公式也让几何能逐项审查 |
| 11 | 版本共存方式 | 会话数据 append-only 不删除；运行时按 `documentId` 只让最高 `revision` 可交互，旧版折叠为只读 | 删除旧载荷需要改会话文件，会破坏 fork / rewind 的分支语义；折叠既消除多版本干扰，又让 rewind 自动恢复旧版可交互 |

## 5. 架构与职责边界

### 5.1 分层

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 扩展层 | SDK 宿主子进程内，以 builtin factory 注册 | 工具注册、提示注入、文档校验与归一化、诊断与交付检查 |
| 投影层 | 主进程 | 识别 UI 载荷、形状校验、版本与体积检查、不符时降级 |
| 渲染层 | 渲染进程 | 组件注册表与文档渲染、参数内存状态、显式提交 |
| 沙箱层 | 二期 | 独立源 iframe 承载自由 HTML / SVG / JS 与动画 |

注册方式与既有内置扩展对齐，新工厂与 codemode / tool-search / mcp 并列，同样声明 `builtin: true`、`replaceable: true`。
区别在于它是条件注册：`SdkSessionTarget.genui` 为真时才把这个工厂放进 `extensionFactories`。开关由主进程在会话创建期从本地配置读出并随目标下发，关闭即不注册——模型看不到这些工具，也就不会尝试调用；而不是注册后再拒绝。偏好读取失败按开启处理，不让配置故障阻断会话。

### 5.2 数据流

```
模型调用 ui_render(document)
  → 扩展层校验并归一化，产出 details.ui { 版本、documentId、revision、document }
  → content 只给短文本摘要（供模型、TUI、纯文本模式与导出场景阅读）
  → SDK tool_execution_end 携带完整 result
  → 投影层：白名单识别 + 形状校验 + 版本与体积检查 → 工具块附带 ui 载荷
  → 渲染层：有载荷走 UiDocument，无载荷走现有 ToolCard
  → 用户调整参数（不请求模型，参数只在渲染端内存）
  → 用户显式提交 → 组装一条用户消息 → 既有 sendPrompt
```

修改既有界面走同一条通道，只多一步读取：

```
模型要改已交付的界面
  → ui_inspect：列出分支上的界面，或取某份的结构大纲（节点路径、类型、短预览、参数声明）
  → ui_render 带同一个 documentId 重新交付整份文档 → revision 递增
  → 旧版本折叠为只读记录，只有最新版可交互
```

回退到修改之前时，那条修改记录不在当前分支上，旧版本重新成为最新版并恢复可交互——折叠状态由分支内容推出，不是持久标记。

`revision` 不落任何外部文件：它每次从当前会话分支上已写入的工具结果重建，因此 rewind / fork 之后版本语义跟着分支走。

### 5.3 状态归属

- **document 放 `details`**：随工具结果进入会话，天然跟随 fork / rewind / 树导航，无需额外重建逻辑。
- **参数值只存渲染进程内存**，键为 `documentId`：参数不是对话内容，塞进 session 会污染分支语义，也会让历史回放显示过期值。每份界面只有一份可交互（旧版本折叠为只读），因此键里不带版本。文档改版（`revision` 变大）时按参数 `id` 迁移已调取值，并对新声明重跑一次收敛：区间、步长、选项变了会被夹取或回落默认值，新版删掉的参数直接丢弃，新增参数取默认值；回退到旧版本不迁移，否则取值会跨分支泄漏。旧取值的保留期限与条目淘汰上限见 `param-state.ts` 的 `PARAM_INHERIT_TTL_MS` 与 `MAX_PARAM_ENTRIES`；超期或条目被淘汰时界面会明示“参数已过期”，不静默归零；被淘汰的条目若又被旧组件写入，会挂回 Map，不丢这次调节；`evicted` 集合同样受条目上限约束。
- 该状态是模块级内存，不写 session、不落盘：页面重载或重启后回到文档默认值，界面上明示这一口径。同一版本被多处引用时共享同一组取值——文档内容相同，共享是正确语义。
- 这是与 dsh-motion-ui 的实质差异：dsh 的宿主没有分支结构，因此可以用扁平的按文档 + 会话哈希的文件存储；pi-desk 有 rewind / fork / navigateTree，必须尊重分支语义。

### 5.4 渲染接入点

- 投影块的 `toolcall` 类型**不新增 block 种类**，而是让工具块可选携带 UI 载荷；渲染层在一个分支内决定渲染 `UiDocument` 还是 `ToolCard`。这样改动局限在单点，不扩散到轮折叠、活动统计与复制逻辑。
- 未知组件类型、未知协议版本、载荷超限：一律降级为 fallback 文本 + 明确提示，不白屏、不部分渲染。

### 5.5 文档协议方向

- 声明式节点树 + 控件绑定 + 派生值；派生计算使用受限求值器，禁止 `eval` / `new Function`。
- 机制图解不做通用派生：几何由渲染端固定公式算出，节点只用 `binds` 把 `angle` / `spread` 指到数值参数，协议里既无表达式也无脚本。
- 图表只画单序列静态数据，不绑定参数、不做交互；需要随参数变化的图形走机制图解。
- 文档带版本号与 revision；未知版本按不支持处理并明确提示。
- 富载荷与模型可见文本分离：模型只看到短摘要与 documentId，避免大文档挤占上下文。

### 5.6 依赖边界

**复用宿主已有**：Electron 自带 Chromium（离屏渲染与截图，替代外部 Playwright）、KaTeX（公式）、marked + DOMPurify（Markdown 与净化）、motion-v（动效）、Pinia（状态）、既有 `AppButton` / `AppSelect` 与 Tailwind 设计令牌。

**可能新增**：图表已按自研轻量柱/线图实现，当前不引入任何图表库；将来若需求超出单序列，再按体积预算重新评估。机制图解为纯 SVG 与几何数学，不依赖任何绘图库。

**明确不引入**：FFmpeg、Playwright、付费语音服务、第二套样式框架或组件库。

具体版本与选型在进入对应阶段时按当时事实确定，不在本设计中锁定。

## 6. 借鉴与不借鉴

| 参考做法 | 结论 | 说明 |
| --- | --- | --- |
| 原生声明式组件（卡片、指标、表格、步骤、表单、滑杆、state / derived） | **移植**，Vue 重写 | 高频场景、零沙箱依赖，复用现有 Tailwind 与设计体系 |
| 机制图解（装配拆解、齿轮传动、曲柄连杆） | **移植** | 纯 SVG 与几何投影数学，零外部依赖，是差异化最快的部分 |
| 交付可靠性（inspect / patch / update、具体字段诊断、部分交付标记、自动修复） | **必做** | dsh 的真正价值所在；缺失会让生成质量不可控 |
| 短文本 + 富载荷分离 | 直接采用 | pi 的 `details` 本就不进模型上下文，天然适配 |
| `documentId + revision + patch` 连续修改 | 调整后采用 | revision 从会话分支重建，不自建文件存储 |
| 固定注入精简 + 按需目录取完整字段 | 直接采用 | 可借 pi 原生 skills 机制承载长指南 |
| 自由画布（HTML / SVG / JS + 动画） | **二期** | 需要独立源与 CSP 改造，安全面最大 |
| 扩展组件中的重型图表库、3D、Mermaid | 按体积挑选，懒加载 | 避免主包体积膨胀 |
| 不透明源 iframe + CSP + nonce + 通道令牌 + 消息限流 | 二期采用 | srcdoc iframe 会继承父文档 CSP，必须走独立协议与逐响应头 |
| 视频成片、语音合成 | 不采用 | 需要 FFmpeg、付费语音服务，超出对话内 UI 目标 |
| 六套视觉风格与风格预览 | 不采用 | 与 pi-desk 自有设计体系冲突 |
| React 组件协议与组件实现 | 不采用 | 技术栈为 Vue，只借协议思想，不搬实现 |
| 正文围栏标记定位 | 不采用 | pi 工具结果位置天然确定，该机制是宿主限制的产物 |
| 独立文件存储与 sessionId 哈希分片 | 不采用 | 见 5.3，本项目需要尊重分支语义 |

## 7. 风险与约束

1. **扩展加载零容忍不因内置而消失**：`errors.length > 0` → `SESSION_BIND_FAILED` 对内置扩展同样生效。工厂必须全程兜底、加载期绝不抛异常；注册失败降级为"工具不可用"，否则用户会打不开任何会话。
2. **schema v1 起即为永久契约**：历史会话会留着旧版本文档，渲染端必须做版本协商，未知版本降级为 fallback 文本而不是白屏。
3. **交付可靠性工作量占比高**：dsh-motion-ui 的工程量绝大部分在让模型可靠产出上（自动修复、空交付检测、诊断文案、提示词从约 16k 参考 token 压到约 3.7k），不在渲染本身。低估这部分会让功能落地后体验反而下降。
4. **会话文件体积**：`details` 会随工具结果写入会话文件。文档必须有硬上限，超限拒绝而不是截断后假装完整。
5. **表达式求值**：派生计算必须用受限求值器；`eval` / `new Function` 在任何路径都不可接受。
6. **投影层契约扩大**：新增载荷会扩大主进程与渲染端契约面，必须与既有 `details.diff` 处理保持同等严格度，避免成为绕过校验的入口。
7. **SDK 版本漂移**：项目依赖与运行时目录的 SDK 版本可能不一致，工具与事件类型以实际安装版本为准，设计期不做锁定。
8. **流内渲染性能**：消息区已有轮折叠与缓存复用，UI 组件需按可见性挂载，避免长会话下同时挂载大量交互组件。
9. **降级路径必须可用**：TUI、纯文本模式、其他 RPC 客户端、导出场景下，界面必须退化为可读文本，不能空白。
10. **与用户自装扩展的语义重叠**：用户若另装 `pi-generative-ui` 一类扩展，两套工具会争抢同一意图；提示词需写清分工，且不假设自己是唯一渲染方。
11. **版本判定与缓存耦合**：取代状态由 `chat-view.ts` 的 `toMessages` 一次算出并纳入缓存有效性；判定写错会让消息每批重建，长会话流式期间明显变卡。
12. **自由文本参数进入模型上下文**：文本参数把用户输入原样带入上下文，提交前缀只做识别与区分，不构成防注入边界；协议只限单行与长度，内容仍按用户原意生效。

### 8.1 已完成阶段的落地形态

- **P1**：协议、上限与严格解析在 `src/shared/genui-api.ts`；工具与按需目录在 `src/extensions/genui/`；渲染组件在 `src/renderer/src/components/genui/`；投影层只放行 `details.ui` 并重新完整校验，不符即降级为文本结果。
- **P2**：文档级 `params` 加 `controls` 节点承载 number / select / toggle / text 四类参数；文本参数只做单行自由输入（单行与长度上限见 `genui-api.ts` 的 `GENUI_MAX_PARAM_TEXT_CHARS`，`default` 可省略即空串），组合期间只写本地草稿、`compositionend` 才落状态，提交时空值写成「（未填写）」而不拦截提交；取值只在渲染端内存；提交按钮是唯一的模型请求入口，复用既有 `sendPrompt`；界面内常驻说明参数不随历史恢复。
- **P3**：`revision` 从会话分支重建；`ui_inspect` 提供界面列表与结构大纲；`explainGenuiDocument` 给出带 JSON 路径的失败诊断，并对重复错误收敛提示；交付检查以非阻断提示形式写进工具摘要。
- **P4**：新增 `diagram` 节点（`kind` 为 `exploded` / `gear` / `crank`），几何由 `src/renderer/src/genui/diagram-geometry.ts` 的纯函数算出，组件只负责拼图元；`binds` 只允许把 `angle` / `spread` 指向已声明的 `number` 参数，不做表达式求值；图解无动效，参数变化直接重算几何。
- **图表**：新增 `chart` 节点（`kind` 为 `bar` / `line`，单序列）；刻度取整与坐标映射在 `src/renderer/src/genui/chart-geometry.ts`，输出与机制图解同一套图元；图元渲染抽到 `GenuiSvgShapes.vue` 由两类图形共用；图表不绑定参数、无动效。
- **版本收敛**：同一 `documentId` 只有最高 `revision` 可交互，判定集中在 `chat-view.ts` 的 `toMessages`（缓存有效性一并比对）；其余版本折叠为只读记录，控件与提交禁用。参数状态按 `documentId` 而非版本存，改版（新工具调用带来的新界面实例）挂载时按参数 id 迁移取值并重新收敛，迁移有效期与条目淘汰上限见 `param-state.ts` 的同名常量，过期时提示“参数已过期”。界面以 `documentId` 作 key：同一实例的 `payload` 不会换版本，但 `supersededBy` 会在新版本交付后变，所以只读判定必须用取值器（`provideGenuiParams` 的 `readOnly` 传函数）而不是 setup 时快照，否则旧版界面会“文案只读、控件可拖”；被取代的旧版以较低 `revision` 重挂载时不回写参数条目，避免折叠再展开把当前版本的取值换成旧版默认值。

### 8.2 用户侧开关

- **归属**：开关存在本地配置（`desktop-config.json`）里，不进 session、不进 Pi 配置；设置页位于「设置 → 功能」。
- **路径**：主进程在会话创建期读一次，随 `SdkSessionTarget.genui` 下发；宿主据此决定是否注册工厂。因此改完必须重载资源才生效，界面明示这一点并提供重载入口。
- **范围**：只停用生成。历史会话里已交付的界面仍按原样渲染、参数仍可调；不做按开关降级历史界面，也不做会话级开关。
- **与版本的关系**：同一份界面只有最高版本可交互，旧版本折叠为只读记录；这一口径不随开关改变。
