# 项目结构

本文是 pi-desk 当前实现的导航入口：先按运行边界理解代码在哪里执行，再按业务模块定位一项功能的完整调用链。目录说明不代表目录整改方案；模块划分是逻辑归属，不改变现有源码位置。

## 项目概览与常用入口

Pi Desktop 是基于 Electron 的桌面客户端，使用 Vue 3 与 TypeScript 构建界面；会话由独立 SDK 宿主执行，终端由独立守护进程持有 PTY。源码、跨进程协议和业务模块的导航见下文，构建输入与发行资源见 [公共记录 F-build](modules/shared.md#f-build构建与发行上下文)。

| 命令 | 用途 |
| --- | --- |
| `npm run dev` | 准备 PTY 权限并构建受管辅助入口与手机页面，启动 Electron 开发环境 |
| `npm run build` | 构建受管辅助入口、手机页面及 Electron 应用产物 |
| `npm run start` | 准备终端守护入口与手机页面并预览已有 Electron 构建产物；不执行完整构建 |

脚本定义以 [`package.json`](../package.json) 为准；各入口与产物映射见 F-build。

## 阅读方式与范围

- 源码路径均以仓库根为基准，使用 `/` 分隔；文档之间使用相对链接。
- 处理一个功能时，先读对应模块，再读它引用的公共记录与跨模块接口，不必通读所有模块。
- 文件表区分模块专属、共享、混合和全局上下文。同一文件只有一个归属位置，被其他模块调用不改变归属。
- 映射覆盖当前 `src/` 源文件、根目录构建配置、`scripts/`、图标和许可资源。入口、核心编排与存储边界来自源码读取，辅助组件和编辑扩展的归属结合静态引用定位；这不是逐函数代码审查或运行行为认证。
- 外部 SDK、依赖包内部实现、用户安装的扩展和运行时动态发现的资源，止于本地调用边界，不作为仓库源码登记。

## 技术栈

项目是 Electron 桌面应用，界面使用 Vue 3、TypeScript、Pinia 和 Tailwind CSS v4，构建由 electron-vite 与独立 Vite 入口组成。源码采用 ESM 语法，主进程、preload 和终端守护进程输出 CJS，SDK 宿主与其他受管辅助入口输出 ESM；源文件语法不等于最终产物格式。

编辑器使用 CodeMirror 与 Tiptap/ProseMirror，终端使用 node-pty 与 xterm，聊天及文件排版使用 Marked、DOMPurify、KaTeX，图解使用 Mermaid。具体依赖声明与锁定结果以 `package.json`、`package-lock.json` 为准，本文不重复维护版本号。

## 运行边界

```text
Vue 页面：组件 → Pinia / services
                  ↓ 固定业务方法
沙箱 preload：contextBridge → ipcRenderer
                  ↓ Electron IPC
主进程：调用者校验、请求校验、业务编排、事件投递
  ├─ SDK 宿主：utilityProcess + MessagePort → 官方 SDK 会话
  ├─ 认证辅助进程：stdin/stdout JSONL → Provider 认证
  ├─ 一次性入口：CLI 预读 / MCP 探测 / 版本检查 / 扩展更新 / 运行时安装
  ├─ 本地流式套接字 → 终端守护进程 → PTY、画面、历史
  └─ 回环 HTTP（默认关闭）← 外部 HTTPS 代理 ← 手机网页
```

| 运行单元 | 启动与职责 | 通信与生命周期 |
| --- | --- | --- |
| Electron 主进程 | `src/main/index.ts` 只按固定顺序转交 `app-lifecycle.ts`：`services.ts` 建实例、`window.ts` 建窗口、`window-channel.ts` 负责投递；`app-lifecycle.ts` 管生命周期并在窗口就绪后调用各能力目录的 `ipc.ts` 注册通道 | 应用级配置、IPC、安全边界和退出编排的所有者 |
| preload | `src/preload/index.ts` 随窗口装载，域实现按业务拆在同目录 | 只暴露固定业务接口，验证结果与事件；不向页面开放任意 channel |
| Vue 页面 | `src/renderer/src/main.ts` 挂载应用 | 保存展示副本、局部编辑与阅读状态；不直接持有系统进程 |
| SDK 宿主 | `src/main/sessions/sdk-host-manager.ts` 拉起 `src/sdk-host/index.ts` 对应产物 | 主进程分配运行身份与绑定代际；宿主执行会话，应用退出时走关闭链 |
| 认证辅助进程 | `src/main/providers/auth-helper-process.ts` 拉起 `src/auth-helper/index.ts` 对应产物 | JSONL 请求、响应与认证提示；退出应用时由认证管理收敛 |
| 一次性辅助入口 | `src/main/shared/pi-cli-process.ts` 定位并启动固定产物 | 参数由主进程给出，完成后退出；超时与错误由各自编排层处理 |
| 终端守护进程 | `src/main/terminal/terminal-daemon-client.ts` 在显式创建终端时允许拉起 | token 与版本化端点通信；退出应用只断开，关闭终端才结束对应 PTY |
| 手机网页入口 | 主进程显式开启回环 HTTP 服务，提供页面与受限会话接口；手机经用户配置的可信 HTTPS 代理访问，应用不管理证书或部署隧道 | 设备配对后以 Cookie 认证，各连接独立同步；应用退出或关闭本地入口即断连 |

独立进程隔离故障与运行身份，不隔离同项目的文件和 Git 工作区，也不自动构成安全沙箱。

## 当前源码目录

| 目录 | 用途 | 业务归属 |
| --- | --- | --- |
| `src/main/` | Electron 集成、IPC、各业务管理器与受管进程监督 | 组合根 `index.ts` 只做装配；业务按能力分目录（`projects/`、`sessions/`、`git/`、`terminal/`、`providers/`、`resources/`、`updates/`、`preferences/`、`genui/`、`trust/`、`lan-remote/`、`config/`、`shell/`、`ipc/` 与叶子设施 `shared/`） |
| `src/preload/` | 沙箱桥接 | 公共通信边界 |
| `src/renderer/` | Vue 页面、组件、状态、前端服务与样式 | 页面按能力垂直切片（`shell/`、`projects/`、`sessions/`、`workspace/`、`editor/`、`git/`、`providers/`、`preferences/`、`resources/`、`updates/`、`genui/`、`lan-remote/`），共享展示在 `ui/`，样式在 `assets/` |
| `src/lan-mobile/` | 手机网页入口、远程会话客户端与窄屏样式 | 独立于桌面组合根，只经同源 HTTPS 接口工作；不加载 Electron 桥接 |
| `src/shared/` | 跨进程请求、响应、事件、常量及运行时校验 | 契约按业务归属；通用错误和综合 Runtime 契约登记在公共记录 |
| `src/shared-process/` | 跨进程基础设施：运行时发布目录布局、当前版本指针、SDK 入口解析与动态加载，以及跨平台进程树终止 | 被主进程与多个受管单元共用，不感知 Electron |
| `src/sdk-host/` | SDK 宿主、会话运行实现、会话日志读取与投影检查点，以及宿主内部的消息／工具／历史／活动投影与内置生成式 UI 扩展 | 会话与聊天、生成式界面 |
| `src/terminal-daemon/` | PTY、画面、历史及本地服务端 | 终端与快捷命令 |
| `src/auth-helper/` | Provider 认证辅助入口与协议 | 供应商与认证 |
| `src/entries/` | 一次性受管入口：`pi-cli/`、`update-check/`、`package-update/`、`runtime-install/` | 参数与生命周期由主进程给出，完成后退出 |

`src/main/` 已按业务能力分目录，主进程不再平铺。`src/` 一级目录按运行单元划分：常驻单元是 `main`、`preload`、`renderer`、`sdk-host`、`terminal-daemon`、`auth-helper`，一次性入口统一在 `entries/`，跨单元设施在 `shared/`（契约）与 `shared-process/`（基础设施）。目录数不等于业务模块数；前端已完成能力切片：`shell/`、`projects/`、`sessions/`、`workspace/`、`editor/`、`git/`、`providers/`、`preferences/`、`resources/`、`updates/`、`genui/`、`lan-remote/` 十二个能力目录各自内含 `components/`、`stores/`、`services/` 子目录与就近的纯函数，共享展示在 `ui/`，样式在 `assets/`，组合根 `main.ts`、`App.vue` 与 `env.d.ts` 留在目录根，下面的模块索引用于跨这些目录找齐一项能力。

## 关键数据流

### 发送消息

`PromptComposer.vue` 准备输入与附件，经会话打开链固定目标；Runtime 服务通过桥接把运行实例与绑定代际交给主进程。主进程定位 SDK 宿主，宿主调用 SDK 并将事件转换为有界投影。投影经主进程和 preload 到达 Runtime Store，由聊天组件渲染。历史文件由 SDK 管理，页面投影不是历史存储的替代品。

### 保存项目文件

`FileEditorView.vue` / 编辑组件将修改交给 `project-editor` Store，经文件服务、桥接及文件 IPC 到 `ProjectFileContent`。主进程复核已登记项目、相对路径与文件类型，按磁盘基线判冲突，再原子替换文件。文件标签本身由工作区模块持有，编辑正文与草稿由编辑模块持有。

### 终端接回

终端 Store 订阅事件并读取清单，标签模块派生标签；单个 `TerminalView.vue` 请求带投递代际的快照。主进程适配器经守护进程客户端分块读取画面，页面解析后确认恢复，再按连续序号接收与确认实时输出。应用退出不结束 PTY，守护进程重启只恢复历史记录而不复活旧 shell。

### 手机继续对话

用户配置可信 HTTPS 代理后，在桌面「设置 → 手机访问」填写外部来源与本地转发端口，显式开启回环 HTTP 入口，再选择授权项目并生成配对二维码；手机通过外部 HTTPS 地址扫码确认，取得设备凭证。手机选择项目与会话由主进程按设备授权复核；接入已有会话只取得或恢复运行实例，不改变桌面前台。消息、停止与问题回应经同源 HTTPS 请求提交，投影与交互快照由独立事件流送达，每条连接各自维护同步水位。手机断开不中断电脑上的任务，重新连接后按权威快照重建。手机页面不渲染生成式界面，也不提供文件、终端与设置入口。

## 状态与存储边界

| 数据 | 权威维护者 | 位置与边界 |
| --- | --- | --- |
| 项目、信任、界面与窗口配置、模型隐藏项、快捷输入及命令、功能开关 | `DesktopConfigStore` | Electron `userData` 下的 `desktop-config.json`；唯一写入队列 |
| 会话历史 | 官方 SDK 与受限会话文件访问 | Pi agent 目录下的项目会话文件；应用内占用由主进程注册表维护 |
| 认证凭据 | 认证辅助进程调用的官方 SDK | Pi agent 目录下的 `auth.json`；不将密钥快照回传页面 |
| 自定义供应商与默认模型 | `ModelsConfigManager` / `PiSettingsManager` | Pi agent 目录下的 `models.json` / `settings.json`；与 Desktop 配置不同 |
| 项目文件与导入图片 | 文件模块 | 已登记项目范围，实际写入需要显式业务动作 |
| 终端历史与画面 | 终端守护进程 | `userData` 下版本化终端数据区，不属于编译输出 |
| 生成式界面参数 | 页面内存与 `GenuiParamStore` | 本机旁路文件 `genui-params.json`，不写回会话正文 |
| 手机设备授权 | `DesktopConfigStore` | `desktop-config.json` 中只保存高熵凭证摘要与项目授权，不保存 Cookie 原文 |
| 手机访问入口配置 | 设置页表单与 `LanRemoteManager` | 外部 HTTPS 来源与本地转发端口只保留在内存中，不落盘、不自动恢复监听；契约见 `LanStartOptions` |
| 受管 SDK 发布与指针 | 运行时安装入口 | `userData` 下的 `pi-runtime`，不是项目依赖缓存 |
| 标签顺序、聊天草稿、阅读状态和编辑草稿 | 渲染端相应 Store / 组件 | 页面内状态，不承诺跨应用重启恢复 |

开发态 `userData` 使用系统应用数据位置；打包态优先使用程序旁的 `data/`，macOS 取 `.app` 同级目录。目录不可写时主进程会回退系统位置。Pi agent 目录由 `src/main/shared/pi-paths.ts` 固定解析，与 Desktop 数据目录分开。

## 构建、资源和资料边界

- `electron.vite.config.ts` 构建主进程、preload、页面；其他 Vite 配置对应独立进程入口与手机网页。详细入口与产物见 [公共记录](modules/shared.md#f-build构建与发行上下文)。
- `build/` 保存发行所需图标源与预生成资源，不是可整体删除的编译目录；`licenses/` 保存第三方许可声明。
- `out/` 是可再生编译输出；`node_modules/` 是依赖；`release/` 同时可能含发行包、展开应用和便携运行数据，不能整体按缓存处理。
- [生成式界面功能清单](生成式界面功能清单.md) 维护产品功能与用法；结构文档只链接，不复制其完整内容。
- [子代理初步设计](subagents-design.md) 保留设计依据；初步设计不自动代表已实现能力。当前源码地图不把子代理方案登记为已实现模块。
- `.agents/memory/` 记录项目约定与棘手问题，`后续开发任务.md` 记录待办；二者不替代当前结构地图，也不自动纳入源码改动。

## 维护边界

新增或移动源文件时同步其唯一归属；新增入口、变更进程职责或数据所有者时更新总览及对应模块。只改局部实现且职责不变，不必改写整份地图。共享调用与混合职责以真实符号记录，不以目录名称或 import 数量推断完整影响面。`src/preload/` 的域文件（`desktop`、`projects`、`sessions`、`runtime`、`terminal`、`git`、`preferences`、`providers`、`updates`、`trust`、`genui`、`lan-remote`）与各能力目录的 `ipc.ts` 按域约定登记，不在模块文件表逐条列举。
