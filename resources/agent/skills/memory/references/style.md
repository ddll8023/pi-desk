# 语气风格库

风格库回答「我通常怎么表达」：从本产品会话里取用户本人发的消息，蒸馏成可复用、可浏览、可覆盖的风格资产，写作或表达类任务按需取用。它与日记、画像并列存放（`styles`、`style_samples` 两张表），但不是第三类记忆：不参与词项检索、月摘要与导出快照；要点与全部原句会随每轮背景注入（独立 20,000 字符预算，超出整条跳过）。

## 能力边界

| 能可靠支持 | 不能可靠支持 |
| --- | --- |
| 像用户一样提要求、写需求说明 | 像用户一样写对外邮件、营销文案 |
| 像用户一样写评审意见、表达取舍与理由 | 像用户一样写私人消息、社交内容 |
| 像用户一样写决策记录、收尾与确认 | 需要特定体裁模板的成文材料 |

原因：本产品会话是「人指挥 AI」的语料，短句、祈使、夹杂代码与日志，其中没有对外文案体裁。不得把风格库描述成「代写邮件」这类语料不支持的用途。

## 语料边界（`SKILL.md` 第 6 条的例外）

第 6 条要求「不扫描其他 Agent 会话补造工作史」。风格取样读的是**用户本人发言**，不是工作史，因此属于明确例外，范围为：

- 只读本产品会话根（由宿主注入绝对路径），不读其他 Agent 客户端的会话目录，不读项目文件；
- 只取 `type:"message"` 且 `role:"user"` 的文本块，不取助手输出、工具结果、附件与图片；
- 只读不落盘，不把会话正文复制到库、日志或会话之外；
- 模型不能指定路径；宿主未提供会话目录时直接报错，不回退其他目录或其他推断。

技术手段才不受限，仍受这一节范围限制：越过上述范围取样属于越权，不是「风格更准确」。

## 取样：`style_sample`

参数（全部可选，缺省取默认值）：

| 参数 | 默认 | 范围 | 说明 |
| --- | --- | --- | --- |
| `scope` | `current-project` | `current-project`／`all` | 按会话头的 `cwd` 判定归属；当前目录未登记为项目时报错，可改用 `all` |
| `days` | 30 | 1..365 | 按会话文件日期的 UTC 自然日窗口 |
| `session_limit` | 20 | 1..100 | 本批处理的会话数上限 |
| `max_chars` | 12000 | 2000..40000 | 原句字符总预算 |
| `min_chars` | 24 | 1..1000 | 短于该长度的发言视为短指令，不入样本 |
| `offset` | 0 | ≥0 | 按会话维度分页，配合 `next_offset` |
| `include_used` | false | 布尔 | 已收录样本默认不返回；置 `true` 时保留，用于核对或重建 |

硬过滤先于统计，只覆盖可判定形态，不做主观筛选：整条只是确认句；夹入系统、技能与记忆背景的注入段；代码围栏与 diff；以图片标记为主；多行且 60% 以上是路径、或 40% 以上是日志与栈行；符号密度过高；短于 `min_chars`。样本带 `session_id`、`date`、`kind`（≥200 字符为 `long`）；每会话最多 12 条；单条长于整份预算时跳过而不是截断。

已收录样本在硬过滤之后、预算之前剔除并计入 `stats.filtered.used`：判据是库里 `style_samples` 的「会话 ID + 逐字原句」组合。因此重跑蒸馏不会把上次用过的原句再取一遍；覆盖某条风格后其样本被删除，对应原句会自然重新出现——那正是该重新蒸馏的信号，不需要额外维护进制表。读库不可用时不阻断取样，结果里的 `used_source` 会写明来源不可用，此时候选未去重。

返回体的 `stats.filtered` 与 `sessions_matched`／`sessions_scanned`／`chars_used` 是判断语料规模的依据；`stopped_by` 与 `has_more`／`next_offset` 说明是预算触顶还是已取完。

## 蒸馏

1. 先看 `stats`：样本条数明显偏少（个位数）或几乎只有短指令时，如实说明语料不足，不硬凑风格条目。
2. 按任务类型归类场景：提要求与需求说明、评审意见与取舍、决策记录、收尾与确认。同一场景只建一条风格。
3. 原句逐字来自样本，不改写、不拼接、不混入助手文本；每条 1..12 条，优先挑能体现句式与信息顺序的句子。
4. `points` 写「怎么做」：句式长短、语气、信息顺序、爱用的结构与表达习惯。不写人物评价、心理推测与隐私内容。
5. `scene` 写适用任务类型，如「需求说明与任务交办」；避免写成「日常聊天」这类不承载工作的场景。
6. `name` 是用户视角的稳定标识，如「需求说明-短句直给」。同场景复用同一名称：同名保存即自动合并（保留 ID 与创建日期，场景与要点覆盖，样本去重追加，合计不超 12 条，超限需先裁剪）；改名或换成另一条目才用 `replace_style_ids`。

## 保存：`style_save`

输入为 1..10 条风格，每条 `name`、`scene`、`points`、`samples`（1..12 条，`quote`／`source_session`／`source_date`）与可选 `replace_style_ids`。引擎校验字段白名单、文本非空、样本条数与单条长度（≤1000 字符）、来源日期合法、替换目标存在且本次不重复替换。

只有用户明确要求提炼或更新表达风格时才保存；保存不授予读取更多会话的权限。名称在库内唯一（数据库层有唯一索引，重名会直接被拒）；同名合并保留原条目与创建日期，样本去重追加后仍不得超过 12 条；`replace_style_ids` 是删除重建（连同样本删除），回执给出 `replaced_style_ids` 与 `merged_style_ids`。不保存密码、令牌、私钥与无必要的个人敏感信息。

## 读取：`style_list`／`style_read`

写作或表达类任务需要像用户本人提要求、写评审意见或决策记录时，风格要点与全部原句已在每轮背景的「语气风格」段里，直接模仿即可；背景里被预算挡下的条目用 `style_list`／`style_read` 按需取。描述用于理解表达习惯，原句用于模仿句式；两者都不代表当前适用的决定，也不复用原句中的事实与结论。产物仍是当前任务的正文，不是对用户原话的复读。

## 不做

- 不做外部写作样本导入、模型微调、后台定时蒸馏；取样只由用户显式触发、一次性、可重跑。
- 不进词法检索与月度摘要、不进入 `export` 快照、不参与记录的去重与替代；要点与原句只经背景注入（20,000 字符预算，超出整条跳过）。
- 不新增会话卡片、渲染层或 IPC 通道；风格库没有独立界面。
- 不因风格库把功能描述成对外文案代写。

## 失败边界

缺库、库版本不符（需 `migrate`）、库忙、宿主未提供会话目录、当前目录未登记为项目、风格 ID 不存在或数量越界，都如实报告并停止，不自动初始化、迁移、扩大范围或改用其他目录。
