# 全局工作日记保存与状态生命周期

## 触发与候选

只有用户明确要求记录今天、保存指定会话或维护对应记忆内容时生成候选。开发完成、自动召回和同意技术方案不触发保存。

保存目标分三层：

- **稳定知识**：后续仍会使用的结论、约束、写法和外部事实。
- **未决状态**：仍在推进的阻塞、依赖和下一步。
- **历史经历**：只回答“当时发生过什么”，不再影响后续决策。

活跃知识必须同时满足四个条件，缺一条就不应作为 `active` 保存：

1. **未来有用**：能改变后续实现、判断或协作方式。
2. **不易重新推导**：不能直接、低成本地从代码、Git 或现有文档得到。
3. **来源可靠**：是用户确认、实际观察或明确材料；AI 提案未经采纳不能写成决定。
4. **边界明确**：有项目归属、适用条件、日期和生命周期。

只有历史价值的“记录今天／保存会话”仍可保存，但应直接写入 `archived` 状态，不参与默认召回。

## 保存前整理

1. 按实际事项拆成记录，用 `progress`、`issue`、`fact`、`decision`、`constraint` 或 `preference_evidence` 表达，不混淆事实与推测。
2. 决定和约束提供稳定 `rule_key`；其他类型不带规则键或替代目标。不同适用条件使用不同语义键，不以同一键覆盖互不相干的规则。
3. 先按主题查询全局规则与历史，核对重复、来源和适用条件。相同事实没有变化就不重复保存。
4. 同一会话可以多次保存：去重看内容而不是会话，每批候选逐条按 `type`、`rule_key`、`topic` 与空白归一化后的正文比对已有记录，内容相同的条目直接跳过、不进入计划；全部命中时保存失败并列出重复主题。不更换 ID、不靠改写措辞绕过重复内容。历史材料仍须语义查重，不能只依赖指纹。
5. 日记引用使用已有真实 `source_record_ids`。不编造 ID，不用文件路径代替 ID；解释性文档链接可放正文。
6. 保存日期由库时区决定。补记过去工作在正文说明实际时间，不伪造保存日期。

## 统一文风

- 标题写当前结论，不写“完成××改造”。
- 正文顺序为：**结论 → 理由或证据 → 适用条件 → 日期／下一步**。
- 一条只表达一个可复用结论；强相关碎片先合并。
- 不使用脱离上下文就无法理解的“这个、上面、刚刚、本次”。
- 文件路径只在说明稳定职责时保留，不列改动清单。
- 不添加未经校准的重要性分数；由 `type + status + project` 决定召回层级。

## 状态生命周期

| 类型 | 允许状态 | 含义 |
| --- | --- | --- |
| `decision` / `constraint` | `active` / `superseded` | 规则类沿用替代链，不使用 `resolved` / `archived` |
| `progress` | `active` / `archived` | `active` 表示未决状态；完成后转 `archived` |
| `issue` | `active` / `resolved` / `archived` | `resolved` 表示问题已关闭；`archived` 表示不再相关 |
| `fact` | `active` / `archived` | 失效或不再当前的事实用 `archived` |
| `preference_evidence` | `active` / `archived` | 偏好证据失效后转 `archived` |

- `resolved` / `archived` 不进入“当前项目近况”，仍可通过 `memory_search` 与 `memory_read` 查历史。
- 关闭已有活跃记录时，在保存计划中提供 `status_updates`，每项包含 `id`、`status`（`resolved` 或 `archived`）和 `reason`；只允许把 `active` 的非规则记录关闭。
- 规则记录仍用 `supersede_record_ids` / `supersession_reason` 替代，不用 `status_updates` 伪装关闭。
- 新保存的非规则记录可直接带 `status`；规则记录只能以 `active` 进入，由替代机制退出。

## 提交与回执

通过 `memory_save` 提交具体记录与状态更新：扩展生成库内计划后直接提交，不再逐次等待界面确认；独立 CLI 使用 `plan save --input -` 与 `commit` 两步。不传项目参数，不在业务目录散落候选 JSON。

提交前由写入闸门判断宿主可写（无交互界面或未知 RPC 客户端拒绝，不生成计划）。回执给出操作、保存日期或月份、`new_record_ids`、被替代 ID、状态更新 ID 与 `withdrawn_months`；计划本身仍写入待确认表 24 小时，不称为完全只读。

`withdrawn_months` 列出新增记录进入已有当月摘要时需撤回的月份，不宣称自动重建。仅替代旧月份规则不抹去旧月份历史摘要。

候选、源内容、引擎、计划有效期或所属会话／分支变化时重新生成。多用途计划按当前库状态依次处理，不提前生成多份计划后盲目连续提交。

用户明确要求纠错或忘记时，按 [数据边界](integrity.md) 提交独立删除计划。日记保存不授权画像更新、月度整理、初始化、迁移、词项重建或库维护。
