# 用户级个人画像

## 触发

画像表示稳定偏好或长期背景，不是每日工作记录。只有用户明确要求提炼、维护、纠正或删除偏好时才准备候选。一次选择、临时要求、日记保存和月度总结不授权画像写入。

从指定日记提炼时，区分明确陈述与推测，展示依据并取得用户对具体内容和适用范围的确认。不从不可见会话补造长期特征，不在收尾反复询问是否更新。

## 读取与作用域

按任务选择 `communication`、`coding`、`learning`、`workflow` 领域。已在有效上下文中的完整偏好复用，不因切换项目而重读全部画像，也不依赖项目身份。

新画像作用域只接受 `global` 或当前所选 `domain:<id>`，不能建立项目绑定画像。具体技术、平台或环境的适用条件写入正文，不因存于全局库就宣称普遍成立。

旧 `project:<id>` 条目保留原文和来源，但不自动作为全局偏好注入，不自动改写作用域。需要调整旧画像时，展示旧、新正文并由用户明确确认。

用户当前明确要求优先于历史偏好；实质冲突先核实，不静默修改。读取不构成画像维护授权，也不授权回溯所有日记。

## 候选与提交

1. 查询相关领域，核对重复、冲突和适用条件。已正确表达时不新增。
2. `basis:explicit` 用于用户明确表达；`inferred_confirmed` 用于已展示依据且用户确认的推测。
3. 来源用真实 `source_record_ids`；没有日记来源时不编造，历史记录也可作为依据。
4. 更新时用同领域 `replace_profile_ids` 指定旧条目，展示全部新旧正文、来源和作用范围。
5. 桌面调用 `memory_profile_save` 由扩展审批；CLI 走 `plan profile` → 确认 → `commit`。

画像替换不删除日记或旧偏好证据，不自动撤回历史月摘要。用户另行要求删除来源时按 [数据边界](integrity.md) 处理；已确认的画像正文不因来源删除自动消失。

不保存口令、令牌、无必要的个人敏感信息，不把短期情绪、一次错误或泛化标签写成永久身份。
