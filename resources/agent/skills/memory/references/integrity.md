# 全局记忆的数据与操作边界

## 单一权威库

日记、画像和月摘要位于当前用户的 `~/.agents/memory-store/`。权威内容写入只能通过文件引擎的具体 `plan` / `commit`，不能用文本替换修补用户库。

工作目录不选择数据根，不要求项目表或登记。旧目录表可作为已有索引的历史来源参与指纹核对，但不是新库组成或读取、保存的前置条件。不自动迁移、复制或双写用户内容。

## 生命周期与历史

- 新全局记录没有必需项目字段。旧日记、旧摘要及来源标签可读，读取不重写文件。
- 当前全局同 `rule_key` 仅允许一个有效版本。历史来源的同名规则保留各自命名空间，不自动合并或提升适用范围。
- 新全局规则的同键更新仅自动替代当前全局旧规则；替代历史来源或不同键目标必须显式指定有效记录 ID 和理由，并展示完整影响。
- 替代保留旧 ID、日期和正文，关联真实后继，不允许循环或悬空引用。当前规则查询排除历史版本，历史和月度来源仍可读取。
- 普通日记来源使用真实 ID；非规则记录不能参与有效版本替代。画像替换不删除日记来源。
- 新画像只用全局或所选领域作用域；旧项目画像不自动变为全局偏好。

## 技术统计

`.system/access.json` 独立于权威正文、索引和计划指纹。它保存主动定向读取次数、会话数、最近时间和必要的哈希去重身份，不保存正文、查询词或原始会话／调用 ID；哈希不等于匿名化。

首次事件可在已有可用库创建统计文件，不初始化库或补锁。统计不参与排名，不代表理解、采用或正确性；未采集和零次不证明历史未使用。

统计写入非阻塞取既有独占锁，忙时报告，不重试。原文成功而统计失败时保留原文及未确认状态。已启动写入不因停用或取消而撤销。

## 明确删除

仅在用户明确要求忘记、删除或纠错时准备 `plan delete`。展示完整目标正文、真实 ID、日期、历史来源及受影响日记关联、画像来源、访问统计和月摘要。

获批提交在同一事务中删除目标、清理悬空引用及对应统计；删除后继不会使旧决定复活。画像已确认正文不因来源删除自动消失。摘要撤回不等于语义重建。

删除计划绑定完整目标统计范围，提交时新增的对应计数也包括在内；缺少范围的旧计划拒绝执行。不能跳过统计故障宣称已忘记。

删除不覆盖外部 Git、备份、云同步或其他设备，也不授权操作项目内文件。

## 计划、并发与恢复

计划协议版本为 3，24 小时失效。旧项目语义计划拒绝提交，须重新生成并提交，不批量改写旧缓存。

`plan` 写短期候选缓存，`commit` 才修改权威文件。候选、引擎、源内容或所属会话／分支变化后旧计划失效；`--approved` 只是引擎内部标记，不能替代用户明确要求保存。

多用途计划按当前状态依次生成。提交在既有锁内核对全局源指纹，更新正文及派生索引；外部绕过协议的写入不受其保护。取消已启动提交不等于撤销，结果未确认时不自动重试。

查询不创建缺锁、不修索引、不恢复事务；缺库、权限错误、索引错误和无命中分别报告。遇 `RECOVERY_REQUIRED` 停止，只有独立获批才能恢复。

`index/search.json` 是日记与月摘要的词法派生索引，不是第二份正文。来源集合、指纹或身份不一致时停止，不回退全历史扫描。文件属性仅用于判脏，原文还须核对内容哈希。

`validate`、`reindex`、初始化和恢复都不是默认收尾。重建只更新派生索引，实际运行须单独批准；本 Skill 不自动执行这些操作，也不建立迁移链或后台捕获服务。
