# 全局月度工作回顾

## 触发与范围

只在用户明确要求月度整理或重建摘要时执行，不后台定时生成，不因查询缺少摘要顺带写入。

正式摘要要求月份已结束；最后一天只有用户明确确认当日记录结束才允许，读取使用 `--closed-today-confirmed`，计划使用 `closed_today_confirmed:true`。

默认读取指定月份的全部日记，不要求项目登记、分类或绑定。不扫描业务目录或其他会话补造工作史。

## 收集与归纳

1. 调用 `month-source YYYY-MM --offset 0 --limit 50`，按 `has_more`、`next_offset` 读取完整月份。
2. 保留旧决定及其后续替代状态，区分当时发生的事与今天仍有效的要求。
3. 按工作主题归纳工作、结果、决定、反复出现的问题和未决事项，不强制项目分组。
4. 每个主题引用指定月份内真实的 `source_record_ids`；不同历史来源可属于同一主题，但保留原适用条件，不能制造统一结论。
5. 讨论、尝试和完成分开，不捏造工时、提交数或通过的检查。月度回顾不是只提炼通用原则。

## 计划与确认

候选使用 `month`、`topics`、`closed_today_confirmed`、`rebuild_existing`。每个 topic 包含标题、正文和真实来源 ID，不传项目字段。

展示全文、月份、材料覆盖和不确定性；`source_total`、`source_used`、`source_uncovered_ids` 按整月记录计算，不能隐藏重大遗漏。无来源不生成虚构摘要。

已有摘要仅在明确设置 `rebuild_existing:true` 且展示覆盖内容后才能重建。用户确认该份计划后提交，来源变化或计划过期则重新预览，不盲目重试。

摘要不替代或清理日记。后来规则被替代不自动抹去旧月份历史；显式删除来源或向已整理月份新增日记时，计划列明撤回影响，不自动重建。

月度整理不授权画像维护、项目文件写入、全局经验另存或删除，不能借一次确认写入其他数据域。
