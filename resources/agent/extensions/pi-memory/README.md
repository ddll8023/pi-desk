# pi-memory 用法

## 用户级全局能力

pi-memory 为 Pi CLI 与 pi-desk 提供请求级记忆背景、按需检索、有用性标注和经写入闸门直接提交的保存通道。Memory Skill 判断如何核实材料与整理候选；pi-desk 内检索与委派时机由宿主系统提示分段给出，独立 CLI 由 Skill 正文承担；扩展不自行总结、更新画像或保存会话。

所有业务项目共用当前系统用户的 `~/.agents/memory-store/memory.db`（SQLite，WAL）。不读取 `.pi/memory.json` 或项目目录中的知识文件，不要求项目登记，不通过 cwd 选择数据根，也不把 `general` 作为绕过项目依赖的默认桶。

记录可带项目归属，由宿主按项目注册表解析后随保存写入；无项目归属即通用记忆，承载跨项目的方法与写法约定。检索默认覆盖全库，可按当前项目或注册表内指定项目收窄，收窄时总含无归属的通用记录；常驻只覆盖当前项目与通用两类。历史项目字段和局部适用条件继续保留，不因为全局可查询就自动提升为通用要求。项目内已有知识文件不由本扩展修改。

## 产品资源与装配

唯一维护源位于 `resources/agent/extensions/pi-memory/`，配套规范和引擎位于 `resources/agent/skills/memory/`。构建将资源原样生成到 `out/sdk-host/agent-resources/` 并附内容指纹，桌面宿主显式装配，不依赖业务项目安装。

宿主只在入口和组成文件均匹配时，在扩展执行前排除同源副本；带本地配置的副本不自动排除，未知同名内容明确报告冲突，不删除用户全局文件或静默覆盖。独立 CLI 的成套部署与桌面装配分开，不维护第二套核心逻辑。

运行参数来源分两种：桌面由宿主固定注入受管配置（解释器、引擎、全局库、时区目录与开关），扩展不自行探测；独立 CLI 读取入口旁的可选 config.json，并可回退自身探测。两种模式都只从 config.json 取 profileDomains，缺失时默认取四个领域；不读取项目绑定配置，产品资源不携带用户配置或记忆数据。

运行环境由宿主显式提供：桌面固定使用随包 Python 3.12 与 IANA 时区数据，不回退系统 Python 或项目虚拟环境；独立 CLI 继续按自身环境探测。宿主可选 config.json 只提供 profileDomains 等偏好，不读取项目绑定配置。

桌面全局记忆默认开启，可在设置页关闭；首次使用需用户确认后才创建空库。会话内 `/memory on` 不能绕过全局关闭，关闭只停用能力，不删除既有记录。

宿主还会按执行模式派生一层：pi-desk 的快速模式在当前会话关闭记忆注入与召回，用户开关本身不变。这种停用会在 `/memory status json` 的 `disabled_by` 里标成 `execution-mode`，与用户自己关闭（`user`）区分开，恢复入口也不同。

## 自动背景

每次模型请求通过 context 钩子提供独立背景，只含两段：适用全局／领域画像，以及常驻约定与当前项目近况合并结算后的一段。后两段共用一份 10,000 字符预算：约定为近七天、`rule_key` 非空、只收当前项目与通用（无项目归属的跨项目约定）两类归属，每族取最新有效版本，其他项目的记录不进常驻也不占预算；近况为当前项目近七天 `status=active` 的 `progress`／`issue`／`fact`／`preference_evidence`，按段内名额先裁到最多 3 条。两段候选合并后按日期降序统一结算（同日约束先于决定、规则先于近况），装不下即停，并报出本次覆盖的截止日期与未注入条数。

- 缓存与失败：成功结算后本会话复用；失败整份不缓存，下一次请求整份重算一次，仍失败才停止；保存或停用后重新取得。常驻或近况停止重试后仍在所属段下报未注入原因，画像段失败或超时按段降级并写明原因、不重试。
- 预算只约束正文块：约定单条 2,000 字符、近况单条 1,200 字符；超预算的约定降为索引行，最多 20 行，并附按 `rule_key`／`memory_read` 取用的指引；索引行与段尾提示不占额度。
- `resolved`／`archived` 记录不进入近况，仍可按需检索。不按相同 rule_key 合并不同历史来源，记录有效不表示适用于当前任务。旧 project 画像不自动成为全局偏好。
- 注入块头带完整记录 ID：约定块、近况块与索引行都以 `■ <记录ID> <日期> <类型> …` 或 `· <记录ID> …` 开头，模型可在记忆实际影响任务时按 ID 标注；被截断时出口行不再重复 ID。画像没有记录身份，不参与标注。
- 背景正文只用于本请求，不追加会话正文、不覆盖系统提示词或改写用户输入。每次装配另追加一条审计条目（`pi-memory.injection.v1`，记段状态、条目身份与 240 字摘要），它不进模型上下文：pi-desk 的 `/memory status` 卡片就是它的展示端，记录条目全文按记录 ID 另取，画像条目全文按领域另取。
- 读后提醒：本会话已读原文但未标注的记忆在背景尾部提示一行（最多列 8 个 ID），不占常驻共享预算；标注提交或会话更换后清除。
- 明确停用记忆的请求连背景也跳过；读取故障、缺库和停用分开处理，不自动修复。

背景之外的历史只能靠主动工具查：`memory_search`／`memory_rules`／`memory_read`／`memory_profiles`。实现见 [context.ts](context.ts)；公共安全文件读取位于 [files.ts](files.ts)。

## 控制与生命周期

| 命令 | 行为 |
| --- | --- |
| `/memory status` | 查看控制状态和全局配置，不启动库查询；输出为中文摘要 |
| `/memory status json` | 同一份状态的完整字段；排障用，不随摘要字段变化 |
| `/memory off` | 停止新增背景、读取、保存和统计；控制入口仍可用 |
| `/memory on` | 恢复记忆能力 |
| `/memory refresh` | 丢弃缓存及待确认操作，保留启停状态，不重载代码或清空统计 |

启停选项写入当前会话分支的非上下文条目，不写记忆正文或保存授权。会话、分支、压缩、刷新和关闭使旧租约失效；保存期间目录仅是宿主来源和会话有效性线索，不绑定项目或改变目标库。

停用和刷新不能清除已进入模型上下文的内容；已启动提交不强杀，取消不等于撤销，也不自动重试。

## 工具

以 [tools.ts](tools.ts) 的注册定义为参数契约，没有项目知识工具；`scope`／`project` 只收窄检索来源，不绑定项目。

| 工具 | 职责 |
| --- | --- |
| memory_status | 查询全局库、标注汇总及状态，不初始化或修复 |
| memory_control | 停用、恢复或刷新 |
| memory_profiles | 按领域分页取得适用全局／领域画像 |
| memory_rules | 查询全局库当前有效规则摘要 |
| memory_search | 全局主题检索，默认按时间分层（近期日记 + 更早月份摘要），支持明确时间模式和分页 |
| memory_read | 按真实 ID 读取完整日记（纯读取） |
| memory_reinforce | 模型判定记忆实际影响任务时标注记录，提升检索排名 |
| memory_save | 具体全局日记候选与状态更新的保存（生成计划后直接提交） |
| memory_profile_save | 用户明确要求的画像维护（生成计划后直接提交） |

search 默认 auto：近窗口日记与更早月份的月摘要代表同池排序，缺摘要的月份回退该月最多两条；records 覆盖全部已保存日记；recent 限近期，historical／month 仅查已有月摘要。查询、规则和原文通过 memory_scope:global 明确实际范围。主题分数仅是词法相关性（命中记录带标注乘子），不证明事实正确或通用。

搜索和规则返回摘要，全文需 memory_read；分页按 has_more／next_offset，跨页核对 store_version。旧来源标签可随结果展示，但不作为当前项目过滤。库版本不符或库忙时停止，不回退全历史扫描，也不自动重建词项。

## 保存与写入闸门

只有用户明确要求保存对应内容时准备候选。日记、画像、月摘要、初始化和删除不互借授权。

1. 写入门禁先判断宿主是否可写：无交互界面或未知 RPC 客户端直接拒绝，不生成计划；闸门只判断能不能写，不代表用户已要求保存。
2. 通过后生成库内计划并直接提交；计划仍写入待确认表 24 小时，提交时核对会话分支、计划内容与库变更序号。
3. 提交返回回执（操作、日期或月份、`new_record_ids`、被替代 ID、状态更新 ID、撤回月份），不再逐次等待界面确认。

保存语义分三层：

- **稳定知识**：`decision`／`constraint` 及仍有效的 `fact`，进入常驻约定或按需检索。
- **未决状态**：`active` 的 `progress`／`issue`／`fact`／`preference_evidence`，进入当前项目近况。
- **历史经历**：`archived`／`resolved` 的非规则记录，不进入近况，仍可按需检索。

非规则记录可在保存时直接带 `status`；关闭已有活跃记录用 `status_updates`（`id`＋`status`＋`reason`），只接受 `resolved`／`archived`，且只作用于 `active` 的非规则记录。规则记录仍用 `supersede_record_ids`／`supersession_reason` 替代，不用状态更新伪装关闭。

模型不能提供 approved 或外部计划 ID。计划变化、过期或来源变化后重新生成，旧项目语义计划不能沿用。新全局会话身份不包含项目 ID，不更换 ID 绕过重复保存；历史材料仍需语义查重。

新同键规则只自动替代全局旧版本；替代历史来源须显式指定真实有效 ID，回执会列出影响。替代保留旧正文、日期和 ID；画像替换不删除日记来源。新画像 scope 仅为 global 或所选 domain。

写入门禁只判断宿主能不能写，不展示正文，也不代表用户已要求保存；能力声明不是保存授权。详见 [write-gate.ts](write-gate.ts)。

## 有用性标注与故障

memory_reinforce 在模型判定某条记忆实际影响当前任务的判断或产出时写入标注事件；每记录每会话只计一次，重复标注仅刷新时间。检索排序按会话数与最近标注时间计算有界乘子（衰减与封顶），常驻注入资格不受影响。读取、检索命中或用户提及本身不是标注理由。

标注事件只存记录 ID、会话哈希与时间，不存正文、理由或原始调用身份；清空事件表即整体回滚。标注走引擎单命令写入，与保存通道同一租约边界：停用、取消或会话变化时不写，提交开始后不撤销，库忙或版本变化如实报告，不自动重试。

明确删除记录时由引擎在计划中展示并事务清理对应标注事件，不自动补计或扫描历史。缺库、权限、版本不符与库忙如实报告，不自动初始化、迁移或重建词项。写入闸门仅覆盖本扩展保存通道，不是文件沙箱；桌面工具展示还依赖匹配的宿主投影实现，复制扩展不等于整体功能一致。
