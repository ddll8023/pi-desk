# pi-memory 用法

## 用户级全局能力

pi-memory 为 Pi CLI 与 pi-desk 提供请求级记忆背景、按需检索、主动读取统计和受宿主闸门约束的保存通道。Memory Skill 判断如何核实材料与整理候选；pi-desk 内检索与委派时机由宿主系统提示分段给出，独立 CLI 由 Skill 正文承担；扩展不自行总结、更新画像或保存会话。

所有业务项目共用当前系统用户的 `~/.agents/memory-store/`。不读取 `.pi/memory.json` 或项目目录中的知识文件，不要求项目登记，不通过 cwd 选择数据根，也不把 `general` 作为绕过项目依赖的默认桶。

记录可带项目归属，由宿主按项目注册表解析后随保存写入；无项目归属即通用记忆，承载跨项目的方法与写法约定。归属只标明来源，检索与召回仍覆盖全库；常驻只覆盖当前项目与通用两类。历史项目字段和局部适用条件继续保留，不因为全局可查询就自动提升为通用要求。项目内已有知识文件不由本扩展修改。

## 产品资源与装配

唯一维护源位于 `resources/agent/extensions/pi-memory/`，配套规范和引擎位于 `resources/agent/skills/memory/`。构建将资源原样生成到 `out/sdk-host/agent-resources/` 并附内容指纹，桌面宿主显式装配，不依赖业务项目安装。

宿主只在入口和组成文件均匹配时，在扩展执行前排除同源副本；带本地配置的副本不自动排除，未知同名内容明确报告冲突，不删除用户全局文件或静默覆盖。独立 CLI 的成套部署与桌面装配分开，不维护第二套核心逻辑。

运行参数来源分两种：桌面由宿主固定注入受管配置（解释器、引擎、全局库、时区目录与开关），扩展不自行探测；独立 CLI 读取入口旁的可选 config.json，并可回退自身探测。两种模式都只从 config.json 取 profileDomains，不读取项目绑定配置，产品资源不携带用户配置或记忆数据。

运行环境由宿主显式提供：桌面固定使用随包 Python 3.12 与 IANA 时区数据，不回退系统 Python 或项目虚拟环境；独立 CLI 继续按自身环境探测。宿主可选 config.json 只提供 profileDomains 等偏好，不读取项目绑定配置。

桌面全局记忆默认开启，可在设置页关闭；首次使用需用户确认后才创建空库。会话内 `/memory on` 不能绕过全局关闭，关闭只停用能力，不删除既有记录。

宿主还会按执行模式派生一层：pi-desk 的快速模式在当前会话关闭记忆注入与召回，用户开关本身不变。这种停用会在 `/memory status` 的 `disabled_by` 里标成 `execution-mode`，与用户自己关闭（`user`）区分开，恢复入口也不同。

## 自动背景

每次模型请求通过 context 钩子提供独立背景，包括适用全局／领域画像、跨任务方法与写法约定的常驻约定，以及按任务检索的全局日记。仅从仍可见的用户任务提取关键词和明确时间条件，不从当前项目身份、工具输出或摘要猜测范围；任务原文超长时降级为首段片段，不以长度放弃召回。

- 只读内部协议 recall-background 复用词法核心及来源核对；缓存命中仍核对原文，不注入被替代规则。
- 常驻约定不依赖词法命中：近七天每个 `rule_key` 族按项目归属分别取最新一条，只注入当前项目与通用（无项目归属的跨项目约定）两类族，其他项目的族不进常驻也不占索引行，并在背景末尾报出被排除的族数；候选族按同类内约束优先与日期倒序依次注入全文，预算用尽后才降为索引行并附未展开族数与按 `rule_key`／`memory_read` 取用的指引；未识别当前项目时不做过滤；成功装配后本会话复用，失败不缓存正文并在下一次请求重试一次，仍失败才停止；保存或停用后重新取得。
- 任务召回无命中时在背景中标明原因（无词项／无重叠／低于门槛），不保留空小节。
- 工具报错可通过 error-recall 查询全局 issue 记录，不读取项目本地避坑知识。
- 正文受预算限制，超限提供真实记录 ID，不截断适用条件。完整同版本工具原文可作为请求内去重证据，摘要不算全文。
- 不按相同 rule_key 合并不同历史来源，记录有效不表示适用于当前任务。旧 project 画像不自动成为全局偏好。
- 背景只用于本请求，不追加会话、覆盖系统提示词或改写用户输入；自动背景不计主动读取统计。
- 明确停用记忆的请求连背景也跳过。读取故障、缺库和无命中分开处理，不自动修复。

实现见 [context.ts](context.ts)、[recall.ts](recall.ts)；公共安全文件读取位于 [files.ts](files.ts)。

## 控制与生命周期

| 命令 | 行为 |
| --- | --- |
| `/memory status` | 查看控制状态和全局配置，不启动库查询 |
| `/memory off` | 停止新增背景、读取、保存和统计；控制入口仍可用 |
| `/memory on` | 恢复记忆能力 |
| `/memory refresh` | 丢弃缓存及待确认操作，保留启停状态，不重载代码或清空统计 |

启停选项写入当前会话分支的非上下文条目，不写记忆正文或保存授权。会话、分支、压缩、刷新和关闭使旧租约失效；保存期间目录仅是宿主来源和会话有效性线索，不绑定项目或改变目标库。

停用和刷新不能清除已进入模型上下文的内容；已启动提交不强杀，取消不等于撤销，也不自动重试。

## 工具

以 [tools.ts](tools.ts) 的注册定义为参数契约，没有 project_id 参数或项目知识工具。

| 工具 | 职责 |
| --- | --- |
| memory_status | 查询全局库及统计状态，不初始化或修复 |
| memory_control | 停用、恢复或刷新 |
| memory_profiles | 按领域分页取得适用全局／领域画像 |
| memory_rules | 查询全局库当前有效规则摘要 |
| memory_search | 全局主题检索，支持明确时间模式和分页 |
| memory_read | 按真实 ID 读取完整日记，并自动记录独立统计 |
| memory_access_stats | 只读查询真实 ID 的访问统计 |
| memory_save | 具体全局日记候选的保存与回执 |
| memory_profile_save | 用户明确要求的画像维护与回执 |

search 默认 records，覆盖全部已保存日记；recent 限近期，historical／month 仅查已有月摘要。查询、规则和原文通过 memory_scope:global 明确实际范围。主题分数仅是词法相关性，不证明事实正确或通用。

搜索和规则返回摘要，全文需 memory_read；分页按 has_more／next_offset，跨页核对 index_version。旧来源标签可随结果展示，但不作为当前项目过滤。索引缺失或过期时停止，不回退全历史扫描，也不自动重建。

## 保存与回执

只有用户明确要求保存对应内容时准备候选。日记、画像、月摘要、初始化和删除不互借授权。

1. 先通过宿主写入闸门（非交互宿主直接拒绝），再调用引擎生成版本 3 的全局计划。
2. 计划写入 .system/plans/ 短期缓存，尚未改变权威内容，但不是完全不落盘。
3. 计划生成后直接提交，提交前复核会话、分支、有效期、引擎及库指纹，仅提交这一份计划。
4. 回执包含计划 ID、保存日期、条目类型与主题、替代与摘要撤回影响及变更文件；具体记录 ID 需用 memory_search 定位。

模型不能提供 approved 或外部计划 ID。计划变化、过期或来源变化后重新生成，旧项目语义计划不能沿用。新全局会话身份不包含项目 ID，不更换 ID 绕过重复保存；历史材料仍需语义查重。

新同键规则只自动替代全局旧版本；替代历史来源须显式指定真实有效 ID，回执会列出影响。替代保留旧正文、日期和 ID；画像替换不删除日记来源。新画像 scope 仅为 global 或所选 domain。

独立 CLI 仍按完整计划逐份核对后提交；桌面在 `piDeskConfirmCapabilities` 声明可用时才视为可写宿主，能力声明不是保存授权。详见 [write-gate.ts](write-gate.ts)。

## 主动读取统计与故障

memory_read 在身份、完整输出及操作状态核对后，通过 access-record 记录独立统计；底层 read 为纯读取。搜索、规则摘要、画像、自动背景和历史回放不计数。

统计保存次数、去重会话数、最近时间和必要哈希身份，不存正文或原始调用 ID，不参与排名或计划指纹，也不证明理解和采用。首次事件只在既有库创建统计文件，不初始化库或补锁；统计查询不产生计数。

同一调用持久去重，统计锁忙不等待或重试。原文成功、统计失败时保留原文和未确认状态；已启动写入不因取消而撤销。明确删除记录时由引擎在计划中展示并事务清理对应统计，不自动补计或扫描历史。

缺库、权限、坏索引和待决事务如实报告，不自动初始化、恢复或修索引。写入闸门只约束本扩展保存通道，不是文件沙箱；桌面工具展示还依赖匹配的宿主投影实现，复制扩展不等于整体功能一致。
